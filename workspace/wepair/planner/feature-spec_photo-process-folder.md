### 현재 행동 흐름 (문제 시나리오)

**관리자(박정훈) 시나리오 — 보험 청구 사진 준비**

```
보험사에서 공정별 증빙 사진 요청
    ↓
구글 드라이브에서 차량 폴더 열기
    ↓
폴더 내 사진 수백 장 — 시간순 혼재
    ↓
한 장씩 열어 육안으로 공정 식별
    ↓
판금 사진, 도장 사진 각각 임시 폴더에 수동 분류
    ↓
AOS에 해당 사진 삽입
    ↓
전체 소요: 1건당 평균 1~2시간 (매일 반복)
```

**작업자(최성호) 시나리오 — 공정 전환 시 사진 혼재**

```
판금 작업 중 차량 사진 연속 촬영 (15장)
    ↓
도장 부스로 이동 후 동일 차량 사진 촬영 (10장)
    ↓
앱에 차량 폴더 단일 저장 → 25장 시간순 혼재
    ↓
관리자가 "판금 사진 10장만 보내줘" 요청 시
    ↓
작업자는 갤러리에서 찾아 전달해야 하나 어떤 게 판금인지 파악 어려움
    ↓
결국 관리자가 직접 분류 작업 수행
```

### 문제 원인

현재 위페어 파트너스는 차량 폴더에 모든 사진을 시간순으로 누적 저장하는 단일 구조를 사용한다. 공정 맥락 정보가 사진과 연결되지 않아, 보험 청구·품질 검수·고객 공유 시 관리자가 수작업으로 분류해야 하는 행정 비효율이 발생한다. 동시에 출고 전 공정 누락 사진을 발견하더라도 어느 공정인지 알 수 없어 보험 청구 자체가 불가능해지는 재무 리스크로 이어진다.

### 페르소나 영향도

| 페르소나 | 영향도 | 구체적 피해 |
|---------|--------|-----------|
| 박정훈 (관리자, 50세) | **매우 높음** | 매일 1~2시간 사진 폴더링 야근. 보험 청구 시 사진 분류·재편집 필요. 공정 누락 사진 발견 시 보험 청구 불가 리스크 |
| 최성호 (작업자, 55세) | **중간** | 관리자의 재분류 요청으로 인한 추가 확인 부담. 현재 구조에서는 촬영만 하면 되지만 결과적 비효율이 관리자에게 전가됨 |

### A안 — Sticky 모드 ★ 권장

**개요**: 카메라/갤러리 진입 시 화면 상단에 현재 공정 칩을 항상 노출. 한 번 선택한 공정은 작업자가 직접 변경하기 전까지 유지(Sticky). 공정 변경이 필요할 때만 칩을 탭하여 바텀 시트에서 공정 선택.

**화면 레이아웃**

```

┌─────────────────────────────────────────┐

```

**공정 칩 상태 정의**

| 상태 | 표시 내용 | 시각 처리 | 설명 |
|------|----------|----------|------|
| Default (최초 진입) | `현재 공정 ▾ 초기` | 회색 칩, 기본 공정 자동 선택 | 관리자가 설정한 공정 목록의 첫 번째 항목 자동 선택 |
| Selected | `현재 공정 ▾ 판금` | 브랜드 컬러 칩, 공정명 강조 | 작업자가 선택한 공정 표시 |
| 공정 변경 시트 | 공정 목록 바텀 시트 노출 | 배경 딤 처리 | 칩 탭 시 바텀 시트 슬라이드 업 |
| 미분류 선택 | `현재 공정 ▾ 미분류` | 회색 칩 | 작업자가 "미분류로 촬영" 선택 시 |
| 오프라인 | `현재 공정 ▾ 판금 (오프라인)` | 칩 우측 오프라인 아이콘 표시 | 네트워크 미연결 상태. 기능은 정상 동작 |

**장점**
- 작업자(최성호) 탭 수 최소화: 같은 공정 계속 촬영 시 추가 조작 0회
- 직전 선택이 유지되어 공정 전환 빈도 낮은 현장에서 자연스러운 흐름
- 큰 칩 버튼 → 장갑 착용 환경에서도 오조작 없이 탭 가능
- 오프라인에서도 로컬 공정 메타 저장 가능

**단점**
- 최초 진입 시 기본 공정이 자동 선택되어 있어 작업자가 확인 없이 촬영할 경우 오분류 가능성
- 공정 전환을 잊고 계속 촬영하면 미검증 공정으로 대량 사진 누적 위험

**리스크 완화 장치**
- F-8 공정 확인 토스트: 30분/50장 누적 시 현재 공정 알림으로 오분류 조기 발견 유도
- 공정 칩이 항상 노출되어 현재 공정을 인지하고 촬영하는 환경 구성

### B안 — 자동 추정 + 사용자 확인

**개요**: 직전 촬영 패턴(시간 간격, 촬영 빈도, GPS 등)을 분석하여 현재 공정을 시스템이 자동 추정. 추정 결과를 작업자에게 확인 요청 후 공정 결정.

**화면 레이아웃**

```
┌─────────────────────────────────────────┐
│ ← 작업목록   A12가 3456 소나타         ⋮ │
├─────────────────────────────────────────┤
│ ┌─────────────────────────────────────┐ │
│ │  🤖 추정: 도장  [맞음 ✓] [아님 ✗] │ │  ← 추정 칩 + 즉시 확인 버튼
│ └─────────────────────────────────────┘ │
├─────────────────────────────────────────┤
│  [ 사진 썸네일 ]  [ 사진 썸네일 ]       │
│  ...                                    │
└─────────────────────────────────────────┘
```

**장점**
- 추정 정확도가 높다면 공정 전환 시에도 조작 없이 자동 분류 가능
- 데이터 누적 후 지속적 정확도 향상 기대

**단점**
- 추정 신호(GPS, 시간 패턴) 수집에 법무 검토 필요 (위치 정보 동의 등)
- 콜드 스타트 문제: 초기 데이터 부족 시 오추정 비율 높음
- 추정 결과가 틀렸을 때 작업자가 매번 수정해야 하는 추가 조작 발생
- 최성호(디지털 숙련도 낮음) 환경에서 "추정" 개념 자체가 혼란 유발 가능

**선결 조건**
- 업체별 촬영 패턴 데이터 3개월 이상 축적
- 위치 정보 수집 동의 정책 법무 검토 완료
- 공정 추정 ML 모델 개발 및 정확도 80% 이상 검증

### A안 — 기본 셋 + 업체별 추가/숨김 ★ 권장

**개요**: 위페어가 정의한 기본 공정 6개(초기/판금/도장/완성/하체/서류)를 기본값으로 제공하고, 업체별로 추가·이름변경·숨김·순서변경이 가능한 커스터마이징 구조.

**기본 공정 셋**

| 순번 | 공정명 | 설명 | 보험사 매핑 코드 |
|------|--------|------|---------------|
| 1 | 초기 | 입고 직후 차량 상태 촬영 | 표준 코드 01 |
| 2 | 판금 | 차체 복원 및 판금 작업 | 표준 코드 02 |
| 3 | 도장 | 도색 및 열처리 작업 | 표준 코드 03 |
| 4 | 완성 | 출고 전 최종 점검 | 표준 코드 04 |
| 5 | 하체 | 하체 작업 및 부품 조립 | 표준 코드 05 |
| 6 | 서류 | 보험 관련 문서 사진 | 표준 코드 06 |

**장점**
- 공업사마다 다른 현장 공정 흐름에 유연하게 대응 가능
- "하체" 등 사용 빈도 낮은 공정을 숨김 처리해 작업자 화면 단순화 가능
- 보험사 표준 매핑은 기본 6개 기준 고정 → 청구 정합성 유지
- 특수 공정(예: 유리 교체, 내장 수리)이 있는 업체도 수용 가능

**단점**
- 관리자가 공정 셋 관리 화면을 이해하고 설정해야 함 (초기 러닝 커브)
- 업체별 커스텀 공정 증가 시 보험사 매핑 '기타' 분류 비율 높아져 수동 처리 증가

**제어 장치**
- 커스텀 공정은 최대 10개(기본 6개 포함) 제한
- 기본 셋 삭제 불가 (숨김만 허용) → 보험사 매핑 안정성 보장
- 커스텀 공정은 자동으로 "기타" 분류 처리 후 관리자 AOS 수동 배정

### B안 — 고정 셋 (전사 표준 6개)

**개요**: 위페어가 정의한 6개 공정을 모든 업체에 동일하게 적용. 커스터마이징 불가.

**장점**
- 관리자가 공정 셋 관리 화면을 사용할 필요 없음 → 설정 단순화
- 전사 표준 데이터로 통계·분석 용이
- 보험사 표준 매핑 100% 자동 처리

**단점**
- 업체별 특수 공정(유리 교체, 내장 수리 등) 수용 불가
- 사용 빈도 낮은 공정("하체", "서류")이 작업자 화면에 항상 노출되어 선택 피로 증가
- 현장 용어와 다른 공정명 사용 시 수정 불가 → 오분류 리스크

## 3. 권장안 채택 및 근거

### 확정 권장안

| 구분 | 채택안 | 비고 |
|------|--------|------|
| 공정 선택 UX | **A안 — Sticky 모드** | MVP |
| 공정 셋 방식 | **A안 — 기본 셋 + 업체별 추가/숨김** | MVP |
| B안 자동 추정 모드 | Future 백로그 | 3개월 실사용 데이터 축적 후 검토 |

### 채택 근거

**A안 Sticky 모드 채택 이유**

1. **최성호(작업자) 최적화**: 공정 변경 빈도가 낮은 현장에서 추가 조작 없이 촬영 가능. 디지털 숙련도 낮은 55세 작업자가 "지금 어느 공정인지" 항상 확인 가능한 UI
2. **3탭 이내 목표 달성**: 차량 선택 → 갤러리 진입 → FAB 촬영의 기존 3탭 흐름 유지. 공정 전환 필요 시에만 칩 탭 1회 추가
3. **오프라인 대응**: 자동 추정(B안)은 데이터 서버 통신이 선행 조건이나 Sticky는 로컬 상태만으로 동작
4. **선결 조건 없음**: 자동 추정(B안)은 위치 정보 동의 법무 검토, ML 모델 개발 필요. A안은 즉시 구현 가능

**A안 기본 셋 + 업체별 추가/숨김 채택 이유**

1. **현장 다양성 수용**: 4개 업체 피드백 중 2개 업체에서 특수 공정(유리 교체, 내장 탈거) 존재 확인
2. **불필요한 공정 숨김**: "하체" 공정 사용 빈도 낮은 업체(2개)에서 숨김 처리 요구 → 작업자 화면 단순화
3. **보험사 매핑 안정성**: 기본 6개 고정으로 표준 코드 자동 매핑 보장. 커스텀은 "기타"로 제한적 수용
4. **[현장 검증 필요]**: "초기·완성·서류" 명칭은 현장 용어와 불일치 가능성 있음. 기획 단계 내 2~3개 업체 현장 인터뷰 통해 확정 필요 (PM PRD O4 미결 사항)

## 4. 기능 명세서

### F-APP-PRCFL-001. 공정 칩 표시 (Sticky 모드 — 갤러리/카메라 진입 시)

- **트리거**: 공정별 분류 옵션이 ON인 업체의 작업자가 차량 상세 갤러리 화면 또는 카메라 화면에 진입할 때
- **동작**:
  1. 화면 최상단(헤더 바로 아래)에 공정 칩 바 고정 표시
  2. 최초 진입 시: 관리자가 설정한 공정 목록 중 첫 번째 공정 자동 선택
  3. 직전 선택 공정이 있으면(세션 내) 해당 공정 유지
  4. 칩 레이블: "현재 공정 ▾ [공정명]"
- **결과**: 공정 칩이 갤러리/카메라 화면 상단에 항상 표시됨. 스크롤 시에도 칩 바 위치 고정
- **예외 처리**:
  - 공정별 분류 옵션이 OFF인 업체 → 공정 칩 미노출. 기존 갤러리 화면 그대로 표시
  - 공정 목록이 비어있는 경우(모든 공정 숨김 처리) → "미분류" 칩만 표시
  - 관리자가 공정 셋을 로딩 중인 경우 → 칩 영역 스켈레톤 로딩 200ms 이내 처리
- **플랫폼 예외**:
  - AOS: RecyclerView 위에 공정 칩 바 고정 배치 (ConstraintLayout 상단 고정)
  - iOS: CollectionView 상단 고정 (UICollectionViewCompositionalLayout 또는 Sticky Header)

### F-APP-PRCFL-002. 공정 변경 시트 열기 및 공정 선택

- **트리거**: 작업자가 공정 칩을 탭했을 때
- **동작**:
  1. 화면 하단에서 공정 변경 바텀 시트 슬라이드 업 애니메이션 표시
  2. 바텀 시트 내에 현재 표시 공정 목록(숨김 처리된 공정 제외) + "미분류로 촬영" 항목 표시
  3. 현재 선택된 공정 항목에 체크 아이콘 및 하이라이트 표시
  4. 작업자가 공정 항목 탭 시: 해당 공정 선택, 바텀 시트 자동 닫힘, 공정 칩 즉시 업데이트
  5. 배경(딤 처리 영역) 탭 또는 [X] 버튼 탭 시: 선택 변경 없이 바텀 시트 닫힘
- **결과**: 공정 칩이 선택된 공정명으로 업데이트됨. 이후 촬영 사진에는 새 공정 메타 적용
- **예외 처리**:
  - 공정 목록 로딩 실패 시 → "공정 목록을 불러오지 못했습니다. 다시 시도해주세요" 시트 내 인라인 메시지 표시
  - 네트워크 오프라인 상태 → 로컬 캐시된 공정 목록으로 표시. 인터넷 연결 없이도 선택 가능
- **플랫폼 예외**:
  - AOS: BottomSheetDialogFragment 사용. 피크 높이 화면의 50% ~ 80% 범위
  - iOS: UISheetPresentationController (iOS 15 이상) 또는 커스텀 바텀 시트

### F-APP-PRCFL-003. 공정 선택 유지(Sticky) 및 초기화 조건

- **트리거**: 작업자가 공정을 선택한 이후 계속되는 촬영 세션
- **동작**:
  1. 선택된 공정은 해당 차량의 갤러리/카메라 세션 내에서 지속 유지
  2. 같은 차량 → 다른 화면 이동 → 다시 갤러리 복귀 시 직전 선택 공정 유지
  3. 공정 유지 범위: 동일 차량 세션(앱 종료 또는 다른 차량 전환 전까지)
- **결과**: 동일 공정 연속 촬영 시 추가 조작 없이 계속 촬영 가능
- **예외 처리 — 초기화 조건**:
  - 앱 완전 종료(프로세스 킬) 후 재시작 시 → 기본 공정(첫 번째 공정)으로 초기화
  - 다른 차량 선택 후 돌아올 시 → 기본 공정으로 초기화
  - 관리자가 현재 선택 공정을 숨김 처리한 경우 → 기본 공정으로 자동 전환, 토스트 알림: "공정 설정이 변경되었습니다"
- **플랫폼 예외**:
  - AOS: ViewModel의 SavedStateHandle로 차량 ID 단위 공정 상태 관리. onSaveInstanceState에 포함
  - iOS: 차량 상세 View의 StateObject 내 공정 상태 관리. 씬 전환 간 유지

### F-APP-PRCFL-004. 사진 촬영 시 공정 메타 자동 저장

- **트리거**: 작업자가 FAB 버튼으로 카메라 촬영 후 사진 저장 완료 시, 또는 갤러리에서 사진 선택 완료 시
- **동작**:
  1. 현재 선택된 공정 값을 사진 레코드에 함께 저장
  2. 공정 메타 저장 방식: DB 레코드의 별도 필드로 관리 (EXIF 직접 주입 대신 서버/로컬 DB 분리 저장)
  3. 저장 항목: 공정명(텍스트), 공정 ID(코드), 촬영 시각, 차량 ID, 업체 ID
  4. 오프라인 상태: 로컬 DB에 공정 메타 포함 저장 → 업로드 큐에 공정 메타 페이로드 포함
- **결과**: 모든 사진에 공정 태그가 첨부된 상태로 로컬 저장. 업로드 시 서버와 구글 드라이브 라우팅에 사용
- **예외 처리**:
  - 공정 값이 null인 상태에서 촬영 시 → "미분류" 메타로 저장 (강제 차단 없음)
  - 메타 저장 실패 시(로컬 DB 오류) → 사진 저장은 유지, 공정 메타만 누락 처리. 관리자 알림 큐에 등록
- **플랫폼 예외**:
  - AOS: Room DB의 PhotoEntity에 processType, processId 필드 추가
  - iOS: CoreData의 Photo Entity에 동일 필드 추가

### F-APP-PRCFL-005. 미분류 처리 (공정 스킵 시 "미분류" 폴더 라우팅)

- **트리거**: 공정 메타 값이 null 또는 "미분류"인 사진이 구글 드라이브 업로드될 때
- **동작**:
  1. 차량 폴더 내에 "미분류" 하위 폴더로 라우팅
  2. 미분류 폴더는 명시적으로 "미분류로 촬영" 선택한 사진과 공정 메타 누락 사진 모두 포함
  3. 업로드 완료 후 관리자 앱에서 미분류 사진 수 뱃지 표시 (확인 필요: 별도 기획 필요)
- **결과**: 공정을 선택하지 않아도 사진 업로드가 정상 완료됨. 미분류 폴더에서 사후 정리 가능
- **예외 처리**:
  - 미분류 폴더 생성 실패 시 → 차량 루트 폴더에 직접 저장 후 서버 로그 기록
  - 미분류 비율이 업체 전체 20% 초과 시 → 관리자에게 앱 내 알림 (확인 필요: 알림 정책 별도 기획)
- **플랫폼 예외**:
  - 공통: 미분류 폴더명은 "미분류"로 고정 (다국어 대응 필요 시 별도 정책)

### F-APP-PRCFL-006. 구글 드라이브 공정별 하위 폴더 자동 생성·라우팅

- **트리거**: 공정별 분류 옵션이 ON인 차량의 사진이 구글 드라이브에 업로드될 때
- **동작**:
  1. 차량 폴더(`입고일_차량번호_차종`) 내에 공정명 하위 폴더 존재 여부 확인
  2. 폴더 미존재 시: 구글 드라이브 API로 해당 공정 폴더 신규 생성 (3초 이내 완료)
  3. 폴더 존재 시: 기존 폴더에 사진 업로드
  4. 사진 파일명: 기존 파일명 규칙 유지 (변경 없음)
  5. 빈 공정 폴더는 사전 생성하지 않음 — 최초 해당 공정 사진 업로드 시에만 생성
- **결과**: 구글 드라이브 차량 폴더 내 공정별 하위 폴더에 사진 자동 분류 완료

```
[구글 드라이브 폴더 구조 예시]
차량 폴더 (20260512_A12가3456_소나타)
├ 초기/
│  ├ 20260512_143012.jpg
│  └ 20260512_143105.jpg
├ 판금/
│  ├ 20260512_150233.jpg
│  └ 20260512_152044.jpg
├ 도장/
│  └ 20260512_161512.jpg
└ 미분류/
   └ 20260512_144230.jpg
```

- **예외 처리**:
  - 구글 드라이브 권한 오류 시 → 업로드 실패 토스트: "구글 드라이브 연결을 확인해주세요". 재시도 큐에 등록
  - 폴더명 중복 생성 시도 시 → 기존 폴더 사용 (중복 생성 방지 로직 필수)
  - 구글 드라이브 API 일시 오류(503 등) → 지수 백오프 재시도 (최대 3회)
- **플랫폼 예외**:
  - 공통: 구글 드라이브 API v3 사용. 폴더 생성은 `mimeType: application/vnd.google-apps.folder`

### F-APP-PRCFL-007. 공정 확인 토스트 (30분/50장 누적 시)

- **트리거**: 동일 공정으로 30분 이상 연속 촬영 중이거나, 동일 공정 사진 50장 이상 누적 시
- **동작**:
  1. 화면 하단 중앙에 토스트 메시지 노출: `"현재 공정: [공정명]. 계속 진행하시겠어요?"`
  2. 토스트에 [공정 변경] 텍스트 버튼 포함
  3. 5초 후 토스트 자동 소멸
  4. 작업자가 [공정 변경] 탭 시 공정 변경 시트 열림 (F-APP-PRCFL-002 동작)
  5. 토스트 무시 시 현재 공정 유지하고 촬영 계속
  6. 동일 트리거 조건 충족 후 토스트 재노출 쿨다운: 10분
- **결과**: 오분류 위험을 작업자가 직접 확인하도록 유도. 강제 차단 없이 선택권 보장
- **예외 처리**:
  - 카메라 촬영 중(뷰파인더 화면)에는 토스트 노출 지연 — 촬영 완료 후 갤러리 복귀 시 노출
  - 오프라인 상태에서도 로컬 촬영 카운트 기준으로 토스트 트리거 동작
- **플랫폼 예외**:
  - AOS: Snackbar 커스텀 또는 커스텀 Toast View 사용 (기본 Toast API 제한 대응)
  - iOS: 커스텀 토스트 컴포넌트 사용 (UIKit 기반)

### F-APP-PRCFL-008. 관리자 — 업체 단위 공정별 분류 옵션 토글

- **트리거**: 관리자 권한 사용자가 앱 > 설정 > 공정별 분류 화면에서 토글을 탭했을 때
- **동작**:
  - **OFF → ON 전환**:
    1. 확인 다이얼로그 노출 (F-APP-PRCFL-010 참고)
    2. 관리자가 [확인] 탭 시 토글 ON 상태로 전환
    3. 서버에 업체 단위 공정 분류 옵션 활성화 저장
    4. 해당 업체 소속 모든 작업자 앱에 즉시 적용
    5. 신규 입고 차량부터 공정 칩 UI 노출 시작
  - **ON → OFF 전환**:
    1. 확인 다이얼로그 노출: "공정별 분류를 끄면 신규 입고 차량은 단일 폴더로 저장됩니다. 기존 분류된 데이터는 유지됩니다."
    2. [확인] 탭 시 OFF 전환, 기존 차량 폴더 구조 변경 없음
- **결과**: 토글 상태가 업체 단위로 저장됨. 즉시 작업자 화면에 반영
- **예외 처리**:
  - 관리자 권한 없는 계정으로 설정 화면 진입 시 → 토글 비활성(Disabled) 표시, "관리자만 변경 가능합니다" 안내
  - 서버 저장 실패 시 → 토글 원상 복구, 에러 토스트: "설정 저장에 실패했습니다. 다시 시도해주세요"
- **플랫폼 예외**:
  - AOS/iOS 공통: 관리자 앱 설정 화면 (일반 작업자 앱에는 해당 설정 메뉴 미노출)

### F-APP-PRCFL-009. 관리자 — 공정 셋 관리 (추가/이름변경/숨김/순서변경)

- **트리거**: 관리자가 SCR-APP-PRCFL-003에서 [공정 관리] 버튼을 탭했을 때
- **동작**:
  - **공정 추가**: [+ 공정 추가] 버튼 탭 → 공정명 입력 텍스트 필드(최대 8자) → [추가] 확정. 총 공정 수 10개 미만일 때만 활성화
  - **이름 변경**: 공정 항목 우측 [편집] 아이콘 탭 → 공정명 인라인 편집 → [완료]로 확정
  - **숨김 처리**: 공정 항목 우측 [숨김] 토글 탭 → 작업자 화면에서 해당 공정 미노출. 기존 해당 공정으로 저장된 사진은 영향 없음
  - **순서 변경**: 공정 항목 우측 드래그 핸들 롱프레스 후 드래그 앤 드롭으로 순서 재정렬
  - **숨김 해제**: 숨겨진 공정 항목(회색 표시)에서 [표시] 토글 탭 → 다시 작업자 화면에 노출
- **결과**: 변경된 공정 셋이 서버에 저장되어 작업자 화면에 즉시 반영
- **예외 처리**:
  - 공정 이름 중복 입력 시 → "이미 사용 중인 공정 이름입니다" 인라인 에러 메시지
  - 공정 추가 시 10개 초과 시도 → [+ 공정 추가] 버튼 Disabled. "공정은 최대 10개까지 추가 가능합니다" 안내 텍스트
  - 기본 셋 6개는 삭제 불가 (숨김만 허용) — 삭제 버튼 미노출
  - 모든 공정 숨김 처리 시도 시 → "최소 1개 이상의 공정이 표시되어야 합니다" 경고 후 마지막 공정 숨김 차단
- **플랫폼 예외**:
  - AOS: DiffUtil + RecyclerView 드래그 앤 드롭 (ItemTouchHelper)
  - iOS: UITableView 편집 모드 또는 SwiftUI List의 .onMove 수식어

### F-APP-PRCFL-010. 관리자 — 옵션 ON 전환 시 적용 시점 안내

- **트리거**: 관리자가 공정별 분류 토글을 OFF → ON으로 전환 시도 시
- **동작**:
  1. 확인 다이얼로그 자동 노출 (토글 ON 상태 전환 이전에 차단)
  2. 다이얼로그 내용:
     - 제목: "공정별 분류를 켜시겠어요?"
     - 본문: "지금 이 시점 이후 새로 입고되는 차량부터 공정별 폴더로 저장됩니다.\n현재 진행 중인 차량은 기존 방식대로 저장됩니다."
     - 버튼: [취소] / [확인]
  3. [확인] 탭 시 토글 ON 전환 진행 (F-APP-PRCFL-008)
  4. [취소] 탭 시 다이얼로그 닫힘, 토글 상태 변경 없음
- **결과**: 관리자가 적용 범위를 확인하고 의도적으로 전환. 진행 중 차량 데이터 오염 방지

## 7. 예외 처리 및 빈 상태

### 공정 선택 없이 촬영 시 (미분류 폴더)

- **발생 조건**: Sticky 공정 상태가 "미분류"인 상태에서 사진 촬영
- **사용자에게 보이는 것**: 특별한 오류 없이 정상 촬영 완료. 공정 칩 "미분류로 촬영" 표시 유지
- **백그라운드 처리**: 사진 메타에 "미분류(UNCLASSIFIED)" 값 저장 → 업로드 시 구글 드라이브 "미분류" 폴더로 라우팅
- **작업자 UX**: 강제 차단 없음. 시스템이 자동 처리

### 오프라인 상태에서 공정 선택 후 촬영

- **발생 조건**: 네트워크 미연결 상태에서 공정 선택 및 촬영
- **처리 방식**: 로컬 캐시된 공정 목록으로 공정 변경 시트 동작. 공정 메타 로컬 DB에 저장. 업로드는 네트워크 복구 시 자동 재시도 큐에서 처리
- **사용자에게 보이는 것**: 공정 칩 우측에 오프라인 아이콘 표시 외 정상 화면 유지
- **주의사항**: 오프라인 중 관리자가 공정 셋 변경 시 작업자 캐시와 불일치 발생 가능 → 네트워크 복구 시 공정 셋 자동 동기화 후 칩 업데이트

### 관리자가 공정을 숨긴 후 작업자가 이미 해당 공정으로 저장한 사진이 있는 경우

- **발생 조건**: 관리자가 "하체" 공정을 숨김 처리. 기존에 "하체" 공정으로 저장된 사진 존재
- **처리 방식**: 기존 사진의 공정 메타 변경 없음 ("하체" 태그 유지). 구글 드라이브 "하체" 폴더도 그대로 유지
- **사용자에게 보이는 것**: 작업자 화면에서는 "하체" 공정 미노출 (숨김). 관리자 드라이브 폴더에는 기존 사진 정상 보관
- **관리자 안내**: 숨김 처리 시 "기존 [하체] 공정으로 저장된 사진은 그대로 유지됩니다" 안내 텍스트 표시

### 공정 셋 최대 개수(10개) 초과 시도

- **발생 조건**: 관리자가 공정 관리 화면에서 10개가 이미 등록된 상태에서 추가 시도
- **처리 방식**: [+ 공정 추가] 버튼 Disabled 상태 표시. 추가 불가 안내 문구 노출
- **사용자에게 보이는 것**: "공정은 최대 10개까지 추가할 수 있습니다. 사용하지 않는 공정은 숨김 처리해보세요." 안내 텍스트

### 구글 드라이브 권한 오류로 폴더 생성 실패 시

- **발생 조건**: 구글 드라이브 토큰 만료, 권한 부족, 드라이브 용량 초과 등

  - 업로드 실패 시 재시도 큐에 등록 (지수 백오프 3회)

- **복구 방법**: 관리자가 구글 드라이브 재연결 후 대기 중인 사진 일괄 재업로드
