## 1. 개선 배경 및 문제 정의

### 접수 피드백

- **접수 시점**: 앱 리뉴얼 후 실사용 1일차
- **피드백 출처**: 공항공업사, 한양공업사 (2개 업체)
- **사용자 피드백**: "검색어 입력 후 어디를 눌러야 할지 모르겠다"

### 현재 행동 흐름 (문제 시나리오)

```
앱 메인 진입
    ↓
작업목록 탭에서 작업검색 필드 선택
    ↓
차량번호 또는 차종명 입력
    ↓
화면에서 [검색] 버튼을 찾음 → 버튼이 보이지 않음
    ↓
키보드 [완료] 버튼을 우연히 발견하거나 → 검색 방법을 찾지 못하고 포기
```

### 문제 원인

리뉴얼 전에는 검색 필드 우측에 [검색] 버튼이 있어 직관적으로 검색 실행이 가능했으나,  
리뉴얼 후 버튼이 제거되면서 키보드의 [완료] 키만이 검색 트리거가 됨.

### 페르소나 영향도

| 페르소나 | 영향도 | 근거 |
|---------|--------|------|
| 최성호 (작업자, 55세) | **높음** | 디지털 숙련도 낮음. 가장 큰 버튼 위주 조작. 장갑 착용 상태에서 키보드 [완료] 발견 어려움 |
| 박정훈 (관리자, 50세) | 중간 | 디지털 숙련도 중간. 직관적 버튼 선호하나 발견 가능성은 상대적으로 높음 |

## 2. 개선 방향 옵션 분석

### A안 — 검색 필드 우측에 [검색] 버튼 상시 표시 ★ 권장

**개요**: SearchField 우측 끝에 [검색] 텍스트 버튼(또는 파란색 돋보기 아이콘 버튼) 고정 배치

**SearchField 레이아웃 변경**

```
현재:  [ 🔍  차량번호 또는 차종명 입력           ]
개선:  [ 🔍  차량번호 또는 차종명 입력    | 검색 ]
```

**상태 정의**

| 상태 | 검색 버튼 | 색상 | 탭 가능 여부 |
|------|----------|------|------------|
| Default (입력 없음) | 표시 | Gray (비활성) | 불가 |
| Typing (입력 중 1자 이상) | 표시 | Brand Blue (활성) | 가능 |
| With X button (입력 후) | 표시 | Brand Blue (활성) | 가능 |

**장점**
- 검색 실행 방법이 즉각적으로 보임
- 기존의 모바일 앱 검색 패턴과 일치 (네이버, 카카오 등)
- 최성호 페르소나 — 장갑 착용 / 한 손 조작 환경에서도 큰 터치 영역 확보 가능
- 키보드 [완료] 키와 병행 지원 가능 (기존 행동 흐름 유지)

**단점**
- SearchField 너비 일부 감소 → 플레이스홀더/입력 텍스트 표시 공간 축소
- 컴포넌트 구조 변경 필요 (SearchField 레이아웃 수정)

---

### B안 — 검색 아이콘 우측 이동 + 버튼화

**개요**: 기존 좌측 돋보기 아이콘을 우측으로 이동, 탭 가능한 버튼으로 전환

```
현재:  [ 🔍  차량번호 또는 차종명 입력           ]
개선:  [     차량번호 또는 차종명 입력        🔍 ]
```

**장점**
- 시각적 변화 최소화
- 우측 아이콘은 "액션 트리거"로 인식되는 패턴 활용

**단점**
- 아이콘만으로는 탭 가능 여부가 불분명 → 최성호 페르소나에게 여전히 불명확
- 입력 필드 내 검색 아이콘 제거 시 "검색 필드"임을 인지하는 단서 약화

---

### C안 — 키보드 액세서리 뷰 추가

**개요**: 네이티브 앱에서 키보드 위에 "검색" 버튼 바 추가 (iOS InputAccessoryView / Android 커스텀)

```
화면:  [ 🔍  차량번호 또는 차종명 입력           ]

키보드 위:  ┌─────────────────────────────┐
            │            검색              │
            └─────────────────────────────┘
            [ 키보드 영역 ]
```

**장점**
- 키보드가 활성화된 상태에서 검색 버튼이 엄지 존 근처에 위치
- 네이티브 UX 패턴과 일치

**단점**
- 키보드가 올라온 상태에서만 표시됨 → 발견 가능성 낮음
- iOS / Android 각각 개발 구현 필요 (공수 증가)
- 필드를 포커스하기 전에는 검색 방법이 여전히 불명확

## 3. 권장안: A안 채택

### 채택 근거

1. **최성호 페르소나 최적화**: 디지털 숙련도가 낮은 현장 작업자가 즉시 인지 가능
2. **Affordance 명확**: [검색] 텍스트 버튼은 기능을 레이블로 명시 → 오인 가능성 0
3. **검색 성공률 향상**: 버튼 발견 → 탭 → 검색 실행의 단순 흐름 완성
4. **키보드 [완료] 병행 지원**: 기존 행동에 익숙한 사용자도 그대로 사용 가능

## 4. 기능 명세서 (A안 기준)

### F-APP-SRCH-001. 검색 버튼 표시 및 검색 실행

- **트리거 1**: 사용자가 [검색] 버튼을 탭했을 때
- **트리거 2**: 키보드에서 [완료]/[검색] 키를 눌렀을 때
- **동작**: 입력된 텍스트로 작업 목록 검색 실행
- **결과**: 검색 결과 목록으로 필터링 및 표시, 드롭다운 닫힘
- **예외 처리**:
  - 검색어 0자 → [검색] 버튼 Disabled 상태 유지, 탭 불가
  - 검색 결과 없음 → Empty State 화면 표시 ("검색 결과가 없습니다")
  - 공백만 입력 → 검색 실행 불가, 버튼 Disabled 유지
- **플랫폼 예외**:
  - AOS: 키보드 [검색] 키(imeOptions: actionSearch) 지원
  - iOS: 키보드 [검색] 키(returnKeyType: .search) 지원

---

### F-APP-SRCH-002. 검색 버튼 활성/비활성 상태 전환

- **트리거**: 검색 필드 텍스트 변경 시
- **동작**:
  - 텍스트 0자: [검색] 버튼 Disabled 전환 (Gray, 탭 불가)
  - 텍스트 1자 이상: [검색] 버튼 Enabled 전환 (Brand Blue, 탭 가능)
- **결과**: 버튼 색상 및 탭 가능 여부 즉시 업데이트
- **예외 처리**:
  - 공백 문자만 입력 시 → Disabled 상태 유지

---

### F-APP-SRCH-003. 입력 텍스트 삭제 (X 버튼)

- **트리거**: 사용자가 검색 필드 내 [X] 버튼을 탭했을 때
- **동작**: 입력된 텍스트 전체 삭제, 커서 필드에 유지
- **결과**: Placeholder 텍스트 재표시, [검색] 버튼 Disabled 전환, 최근 검색 목록 표시
- **표시 조건**: 텍스트 1자 이상 입력된 경우에만 [X] 버튼 표시
- **플랫폼 예외**: 없음
