## 화면 목적

작업목록 탭의 검색 필드에서 검색 실행 CTA가 없어 사용자 혼란이 발생.  
3가지 개선 방향을 디자인하여 내부 비교 검토 후 최종안 확정.

## 진입 경로

- 작업목록 화면 (현재 화면)
- 작업 상세 화면 (검색 결과 항목 탭 시 이동)

## 페르소나

- **주 사용자**: 최성호 (작업자, 55세, 디지털 숙련도 낮음, 장갑 착용, 한 손 조작)
- **보조 사용자**: 박정훈 (관리자, 50세, 디지털 숙련도 중간)

| 요소 | 컴포넌트 | 설명 |
|------|---------|------|
| [↕ 입고일] | Dropdown_Desc | 소팅 버튼 (입고일/출고일/등록일순) |
| [↻] | Btn_Refresh | 새로고침 아이콘 버튼 |

### 문제 지점

- 검색 필드에 **검색 실행 버튼 없음** → 키보드 [완료] 키만으로 실행 가능
- "어디를 눌러야 할지 모르겠다" 피드백 접수 (공항공업사, 한양공업사)

## A안: SearchField 내 [검색] 버튼 추가 + 새로고침 버튼 헤더 이동

### 변경 개요

- [↻] 새로고침 버튼을 필터 바에서 **헤더 우측(🔔 알림 버튼 좌측)으로 이동**
- 확보된 공간에 SearchField 너비 확장
- SearchField 내 우측에 [검색] 텍스트 버튼 추가

### 레이아웃

**[S1] Default**
```

│  [↕ 입고일]  [🔍 작업검색              ✕]        │  ← 필터 바 (새로고침 제거)
├─────────────────────────────────────────────────┤
│       작업중              작업완료               │
│  작업 목록 카드                                  │
```

### 새로고침 버튼 이동 근거

- 필터 바에서 제거 → SearchField 너비 확장 + [검색] 버튼 공간 확보
- 헤더 우측(🔔 좌측)으로 이동 → 화면 전체 새로고침 기능과 의미적으로 부합
- 소팅·검색은 "탐색 액션", 새로고침은 "화면 전체 액션" → 위계 분리

### 사용 컴포넌트 (기존 디자인 요소만)

| 요소 | 컴포넌트 | 변경 여부 |
|------|---------|---------|
| 헤더 | 기존 헤더 컴포넌트 | 새로고침 버튼 위치만 추가 |
| 소팅 버튼 | Dropdown_Desc (기존) | 변경 없음 |
| 검색 필드 | Dropdown_Search (기존) | 내부에 [검색] 버튼 추가 |
| [검색] 버튼 | 기존 버튼 시스템 활용 | 신규 (기존 버튼 컴포넌트 활용) |
| [✕] 클리어 버튼 | 기존 close_small 아이콘 | 변경 없음 (이미 있음) |
| 새로고침 버튼 | Btn_Refresh (기존) | 위치만 헤더로 이동 |
