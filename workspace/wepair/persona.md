# 위페어 파트너스 페르소나 문서
프로젝트: 위페어 파트너스 서비스 기획 | 날짜: 2025-12-22 | 업데이트: 2026-04-23

---

## 서비스 정의

위페어 파트너스는 1급/2급 사고차량 수리 공업사를 위한 B2B SaaS 앱이다.
공업사 작업자가 수리 작업사진을 촬영·등록하고, 관리자가 고객에게 결제 비용을 전송하며 개인정보 동의를 수취하는 업무 흐름을 디지털화한다.

**핵심 가치**: 사진 촬영-등록-결제 청구-개인정보 동의 수취 흐름을 최소한의 조작으로 완료

---

## 설계 고려사항

현재 페르소나는 50대 중심이나, 실제 서비스에서 30~40대 관리자/작업자 유입 가능성을 열어두고 설계한다.
UI는 디지털 숙련도 낮음 기준으로 설계하되, 숙련 사용자가 답답함을 느끼지 않도록 숏컷/자동화 옵션을 제공한다.

## 페르소나

### 박정훈 (관리자) — 50세 / 남성

**직업**: 1급 종합정비업 공업사 대표
**지역**: 경기도 화성시

**주요 업무**
입고 등록, 작업 지시, 보험사 청구(AOS), 고객 응대

**디지털 숙련도**
중간 (개인 안드로이드 폰 + 사무실 PC 멀티 태스킹)

**핵심 키워드**
보험청구, 야간 종류, 실시간 관제, CCTV 대응

**배경 (Background)**
현장 기술자로 시작해 20년 만에 본인 공업사를 차린 베테랑 사장님. 현재는 현장보다는 사무실에서 보험사 견적 참여와 고객 응대, 경영에 집중함.

**목표 (Goals)**
- 사고수리 지연 누락으로 인한 보험 청구 번거(작업)를 0%로 만들기
- 퇴근 전 사진 분류 및 폴더링 작업을 자동화하여 야근을 없애기

**페인 포인트 (Pain Points)**

[재무 리스크] 보험 청구 번거 및 식감 공포
사고수리는 공정별 중빙 사진이 곧 매출. 하지만 작업자가 내부 관규이나 주요 부품 교체 사진을 누락하거나 적업을 한데내라리면, 보험사에 해당 수리비를 청구할 수 없어 공직적 손실. 출고 직전에야 사진이 없음을 발견하고 당황하는 상황 빈번

[행정 비효율] 사진 취합 및 폴더링
작업자 작업들이 카톡이나 개인 폰으로 찍어온 수백 장의 사진을 일일이 확인, 차량번호별로 분류하여 폴더에 넣는 작업이 매일 1~2시간의 소요. 이 단순 반복 작업 때문에 경영에 집중할 시간이 없어 야근을 해야만 함

[소통 부하] 실시간 진행 상황 파악 및 고객 응대
고객이 찾으러 오는지도 모르고 핵 대표는 그때마다 하던 일을 멈추고 현장에 가서 확인하거나 CCTV를 뒤져야 함. 또한 작업 지시 변경 사항이 구두로 전달되다보면서 누락되거나 오전달되는 상황이 발생

**해결책 (Solution)**

[재무 리스크 해결]
오프라인 공정 체크 & 자동 업로드: 인터넷 연결이 끊겨도 촬영한 사진을 스마트폰 로컬 저장소에 즉시 안전하게 저장. 이후 네트워크에 연결되는 즉시 백그라운드에서 구글 드라이브로 자동 업로드되어 데이터 유실을 0%로 차단

[행정 비효율 해결]
Auto-Filing: 작업자가 앱에서 특정 차량을 찍기만 하면, 업로드 시점에 [날짜_차량번호_차량모델명] 구조로 폴더가 자동 생성되어 저장. 실시간 공정 대시보드: 관리자가 현장에 가지 않고도 앱을 통해 어느 공정에 어떤 사진이 채워지고 있는지 실시간 확인 가능

[소통 부하 해결]
실시간 관제: 사무실 PC에서 현장뷰를 확인할 수 있어 굳이 현장에 가지 않고도 해당 차량이 어떤 작업이 들어갔는지 실시간 확인 가능

### 최성호 (작업자) — 55세 / 남성

**직업**: 1급 종합정비업 공업사 부장
**지역**: 경기도 화성시

**주요 업무**
피그라인 차체 복원(판금), 도색 및 열처리, 부품 조립

**디지털 숙련도**
낮음 (복잡한 앱은 즉시 포기, 글보다 큰 버튼 선호)

**핵심 키워드**
길간 적용, 보고 기피성, 수리 업무 집중, 한손 촬영

**배경 (Background)**
25년 경력의 베테랑 판금/도장 작업자. 디지털 숙련도는 낮으며, 주로 안드로이드 개인 휴대폰을 사용함. 항상 작업복과 장갑을 착용하고 소음과 먼지, 오염이 심한 가혹한 현장에서 근무. 현장에서 이동하며 한 손으로 기기를 조작하는 비중이 매우 높음. 앱 내의 긴 글을 읽지 않고 화면에서 가장 큰 버튼 위주로 조작

**목표 (Goals)**
- 수리 본업 집중: 빠짐없는 작업목록에 통해 현장 균형 흐름을 유지한다
- 작업 통보한 순간대나 사전을 '추가'한 최고(정리/분류/설명 없이), 기록 의무를 최소화한다
- 1년 이상) 사진이 자동으로 정리·저장되어, 관리자가 PC 폴더/AOS로 바로 쓰게 만든다(전달 질문/재요청 감소)

**페인 포인트 (Pain Points)**

불확실한 피드백
소음이 심한 현장에서 사진이 제대로 찍히고 저장되었는지 확인이 어려움

조작 번거로움
장갑을 낀 상태, 또는 시끄러운 상황에서 작은 버튼을 눌러야 하거나, 잘못 찍었을 때 다시 촬영하고 등록하는 과정이 매우 번거로움

작업 대상 찾기 어려움
작업 대상 차량이 많을 경우 촬영에 필요한 차량을 리스트에서 찾는데 시간이 오래 걸림

낮은 앱 성능
앱이 느리거나 사용성이 복잡하여 사용을 포기하고 기존 방식으로 작업하려고 함(카톡 전달 등)

**해결책 (Solution)**

불확실한 피드백 해결
시각/촉각 피드백 강화: 촬영 성공 시 화면 전체에 명확한 시각 신호를 제공하거나 진동 피드백을 주어 저장 여부를 파악 가능하게 함

조작 번거로움 해결
한 손 취적화 UI: 화면의 가장 크고 뚜렷한 곳에 촬영 버튼을 배치, 텍스트 입력을 최소화하여 한 손으로도 조작 가능하게 설계

작업 대상 찾기 해결
정보 구조화: 차량 리스트에서 센터명과 차량번호(특히 뒷자리 4자리)를 크게 표시하여 직관적으로 대상 파악 가능하도록 설계

## 물리/공간적 환경

### 환경 전제
본 서비스는 1급과 2급의 대한민국 사고수리 공장 환경을 전제로 정의하였다.

공급 유형: 판금/도장을 주로 하는 수리 100%, 부품만 교체 및 공임 비중 약 10~20%, 기타 7~8개
보험 수리 비중: 전체 수리의 70~80%

### 페르소나별 물리 환경

**관리자 환경**
- 주 사용 디바이스: 본인 소유 7개 사무실 PC + 안드로이드, 기타 개인 스마트폰
- 입력방식: 키보드, 마우스 중심
- 사용 자세: 착석하여 사용
- 손 상태: 깨끗한 상태
- 소음: 중간(사무실, 전화, 현장 소음 유입)
- 네트워크 상태: 유선 or WiFi
- 시간 압박: 한시적 지속시간이나 특이 압박

**작업자 환경**
- 주 사용 디바이스: 안드로이드, 기타 개인 없는 공용 스마트폰
- 입력방식: 손가락 터치
- 사용 자세: 서있거나 이동 중
- 손 상태: 장갑 착용, 기름
- 소음: 매우 큼
- 네트워크 상태: 불안정
- 조도: 현장 보따라 어두운 경우 많음

### 공간적 특성

**관리자 공간적 특성**
- 사무실 ↔ 현장 환경 오가는 것이 구조
- CCTV 확인, 전화, PC 화면 동시에 사용
- 하나의 화면이나 하나 전체에 흐름을 관리를 원함

**작업자 공간적 특성**
- 차량 도어, 내부, 트렁크 오가며 촬영
- 주로 부스, 플로윤 등 공간 이동하며 작동
- 낮은 조도, 강한 소재 등 비표준 환경 비도별로 촬영

## 주요 과업 행동 시나리오

### 관리자 시나리오

**시나리오 1. 오전 운영 시작: 오늘 작업현장 세팅 + 리스크 차량 선별**

현재 입고되어 있는(또는 오전 중), 오늘 입고/작업 차량이 계속 추가된다. 관리자는 오늘 알아야 되었는지도, 어디까지 진행됐는지를 파악해야 한다.

행동:
- 앱 또는 PC에서 작업목록을 풀어온 오늘 입고 차량의 항목 등록됐는지 확인
- 차량번호/입고일/모델명이 빠짐없이 확인 (플로이드 카카 기르먼 나중에 못 찾음)
- 최근에 사진이 추가되지 않는 차량 있는지 진행(진전 실시간)
- 보험/판금 기능성이 높은 차량을 우선 확인 목록으로 마음속에 태우하여

지시기 기준 생성:
- 작업자가 입고동록(OCR)로 하여 작업목록에 자바로 프로 등록 기키하번호로-날짜-모델명로 구글클라우드 폴더 + PC 로컬 폴더더 생성됨

**시나리오 2. 진행 모니터링(현): 현장특쾌 + 작업목록으로 진행 적도 파악**

보험사/교래 통화 중 "지금 어디까지 됐나요?"질문이 나오고, 현장에 계속 현인이 현장의 현황 흐름을 확인이 필요. 대표는 상황을 실시간 패악하여 판단해야 한다.

행동:
- 앱에서 작업목록을 열고, 확인이 필요한 차량을 선택한다
- 현장특쾌(타임라인)를 볼때 사진이 추가된 시각 이후로 흐름을 확인한다
- 지금부터 업데이트/접수가 필요한 사항들이 있는지 파악한다
- 작업화에서 갤러리 화면으로 넘어가 사진을 더 자세히 보고, 보험사/교래에게 실시간 관련을 들을 수 있다

지시기 기준 생성:
- 작업자가 갤러리에서 FAB로 사진을 추가하면 현장특쾌에 시간순으로 변경하여 관련 신호가 가능
- 앱트로 지지하면 알아니라도 관리자는 업로드가 늘는 중인지, 여기 기록이 없는 건지 분명히 볼 수 있어야 아이만 들어야

지시 부하:
- 네트워크 지연으로 찍었는데 아직 안 올라와 → 관리자가 정보로 오판해 현장에 어 불필요한 물음을 넣을 수 있음

**시나리오 3. 보험 청구기(AOS) 대응(PC): 폴더로 즉시 전환 → AOS에 삽입 → 청구**

보험사에서 AOS 기반으로 재료 제출을 요구한다. 관리자는 앱에서 한 장씩 정리할 사진이 없고, PC 폴더에 바로 집어서 AOS에 넣는 게 핵인 플로쿠다.

행동:
- PC에서 대상 차량을 찾는다 (차량번호-입고일-차량모델명으로 검색/탐색)
- 폴더 안 사진을 바로쪽 풀로어 해서 제재에 올 사진을 고른다
- AOS 프로그램을 열고 해당 청구 건을 생성/업데이트한다
- PC 폴더에서 사진을 AOS에 작업자 사진을 불러 삽입한다
- AOS에서 최소 전력(손수/살명 등)를 확인 후 청구 전환한다

지시기 기준 생성:
- 사진이 구글클라우드로 저장되다 PC 로컬 폴더로 동기화되어야 하고+삽 업로드가 없기 힘들어
- 폴더 구조/파일명이 완정하게 AOS 작업 시간이 크게 줄어듦

지시 부하:
- 앱에서는 사진이 있는데 PC 폴더에서 안 찾겨 사람(등기이기 거리 기어) → 관리자는 앱 현장특쾌/갤러리에서 줄여온 그 것에 몇 찍 확인 후 → PC 동기화가 기다리지는 상황
- 폴더 구성/파일명이 일정하지 않으면 관리자는 가지 않고도 앱을 통해 어느 공정에 특정 차량이 어느 공정에 있는지 확인이 불가
- 동일 차량번호가 여러 건(동발 입고, 납부 지연 등) → 폴더의 규칙이 없으면 관리자는 어떤 케이스인지 구별이 안 돼

**시나리오 4. 당월 마감/정산: 판매/관리/리스크 케이스만 남기기**

업무 매일 시간, 대표는 모든 것을 완벽히 정리하지 않았다. 대신 내일 문제될 건(참기 지연, 지료 부족, 분쟁 가능)을 최소화하려 한다.

행동:
- 앱에서 작업목록/현장특쾌를 오늘 차량들이 업무이들을 마지막으로 확인한다
- 입도이도 (진/지래 보험사) 처리된 것들과 이후 활동이 없는 차량들 빠뜨리지 않는다
- 보험 청구가 완료된 건은 AOS 처리 완료 기준으로 잔료된리 한다
- 다음날 우선 확인 차량을 메모/속성(또는 내부 메모)로 남긴다

지시기 기준 생성:
- 앱(현장특쾌)이는 전들 신호또는 동안
- PC 폴더는 청구 완료가 기터임
- 관리자는 메뉴를 바꾸거나 기름하지 않는 비중이 높아지지 않아야 한다

### 작업자 시나리오

**시나리오 1. 오전 입고 처리: 입고등록(OCR)로 작업목록 생성**

오전, 차량이 연속 입고되어 전달을 빠르게 작업문을 만들어야 한다. 출의/수기/필드 기록은 건거를고 누락이 척다. 작업자는 최소 입력으로 작업목록에 올리려는 것이 목표다.

행동:
- 앱에서 입고등록을 눌른다
- 카메라가 차량번호를 활용한 활영한다
- 차량번호가 OCR로 자동 입력되면, 작업자는 눌러서 확인한다
- 입고일을 선택/확인하고, 차량모델명을 입력한다
- 등록 완료를 누르고, 작업목록에 항목이 생긴 것을 확인한 직 바로 작업 일무로 이동한다

지시 부하:
- OCR 결과로 차량번호가 자동 입력되어 입력 부담이 줄어듦
- 등록이 완료되면 작업목록 항목이 생성되고, 해당 기(차량번호-입고일-모델명)으로 폴더로 기(클라우드)되어 진행됨
- OCR 오인식: 작업자는 즉시 수기 수정 후 등록
- 클래 입고/재입고: 이미 있는 차량이면 새로 만들기보다 기존 항 목록에 사진을 추가하게 함

**시나리오 2. 작업 착수 전 준비: 작업목록에서 차량 선택 → 상세 확인**

작업자는 여러 차량을 동시에 담당한다. 지금 어떤 차량을 찍고 있는지 작업자면 사진이 영향의 장에서 벗어 열리면 헷갈릴 수 있어, 복잡한 확인 절차는 안 된다면 한다.

행동:
- 앱의 작업목록에서 대상 차량을 찾는다(차량번호 중심)
- 작업목록에서 해당 차량의 카드를 눌러 등록된다(선택한 확인)
- 상세 현장(갤러리에 진입하면, 작업자는 대화 확인 없이 바로 촬영으로 넘어감
- 여러 차량을 동시에 담당하는 상황이면, 성인의 차량번호/모델명을 통해 확인한다

지시기 기준 생성:
- 차량번호(숫자)에서/쉐에 차량번호가 가장 눈에 띄게 표시되어야 함
- 작업자가 빠르게 오가도 사진의 항목에 정확히 귀속되는지 확인한다
- 작업명이 비슷하거나 변경가 있었다면, 사진의 다른 항목에 들어갈 수 있음 → 관리자/관리자가 정규 루트 불리(에 사진이후 기보추가)

**시나리오 3. 작업 중 기록: 갤러리에서 FAB 카메라 기능으로 사진 추가**

작업 중/중간 중에 빌 별한 장면을 빠르게 문서화 문제가 있지만, 작업자는 촬영 후 전술을 전술을 걸을 수 없다. 복잡한 행동 + 추가의 지식 행동도도로 끊느냐고.

행동:
- 차량 상세(갤러리) 화면에서 FAB 비튼을 누른다
- 카메라가 기가면 필요한 장면을 연속 촬영한다
- 다음 작업으로 이동한다 (업로드 여부를 확인하지 않는다)

지시기 기준 생성:
- 촬영된 사진은 즉시 제일 작업목록-상세연면/갤러리에 귀속
- 업로드 시 흐름 처임 → 플로이드 큐 → 자동 업로드/처리되
- 업로드가 완료되면 구글 클라우드의 차량 폴더 기준으로 처리
- 이후 PC 로컬 폴더로 동기화/생성되어 관리자가 접근 가능하게 됨
- 작업자가 추가한 사진은 관리자의 현장특쾌 타임라인에 시간순으로 변경되어 진행 신호가 됨

지시 부하:
- 네트워크 불안정: 업로드가 되어도 작업자는 신경 쓰지 않을 → 시스템이 큐/재시도로 백필하면 됨
- 많은 사진 찍어 업로드 중도가 낮고 작업 중 기다리면 바로 다음 입고 시 다시 다음 취한

**시나리오 4. 요청 대응/마감: 관리자 질문을 플로는 현장 문앱**

작업자는 첫 번 말 정리를 하지 않는다. 대신 대표(관리자)가 보험사/고래의 취합 중 확인이 필요하면, 작업자는 잡에게 확인될 수 있다 이러한 케이스도 현장에선 최소 대답만.

행동:
- 관리자에게 '사진 올라왔냐?' 갑자기 묻는 경우 생기면, 앱에서 해당 차량 상세(갤러리)에서 확인 후 → '지금 봐도 있어요' 뒤에 상태를 알릴 수 있음
- 앱에서 '없어요 못 올렸어요' 갑자기 묻는 경우 생기면, 아직 사진 올리지 않았다는 걸 떠서 빠르고, 완전한 한번 영어/마이너스한 쪽 흐름에서 다시 올려 기기기 시켜도 주도로
- 이번 작업에도 별도 정리가 있는 동시(관리자/관리자분은 사진을 관리하면 사진을/관리자 영역)
- 작업자의 최소 행동만으로도 플라우드 저장, PC 동 기화, AOS 청구에 삽입이 정리가 이루어지는 제도에 기획을 잡고 현장이 완성된다

## 성공 지표

### 관리자(박정훈) 성공 지표
- 보험 청구 처리 시간: 기존 대비 50% 단축
- 사진 정리 소요 시간: 1건당 3분 → 30초 이내
- 월 누락 청구 건수: 0건

### 작업자(최성호) 성공 지표
- 사진 등록 탭 수: 3탭 이내 완료
- 등록 소요 시간: 촬영~완료 1분 이내
- 재촬영 요청 수: 주 1회 이하

1. 환경이 다른 사용자는 같은 기능이라도 다른 UX 설계가 필요하다
