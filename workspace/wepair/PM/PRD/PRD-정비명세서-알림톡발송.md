# PRD — 정비명세서(선견적) 알림톡 발송 및 이력 로그

**서비스**: 위페어 파트너스 (앱)  
**작성일**: 2026-05-08  
**작성자**: PM 페르소나 (Claude 세션)  
**상태**: 초안 확정 — 디자인 진행 중

---

## 1. 제품/기능 개요

작업 상세 화면에서 담당자가 정비명세서(PDF)를 선택하여 고객에게 카카오 알림톡으로 발송하고, 발송 이력을 조회·재발송할 수 있는 기능.

---

## 2. 배경 및 문제 정의

- 현재 정비명세서는 웹에서만 발송 가능 → 현장 담당자가 앱에서 즉시 처리 불가
- 고객에게 수기로 파일을 전달하거나 전화로 안내하는 비효율 발생
- 동의서 발송 기능이 이미 앱에 존재 → 동일 패턴으로 명세서 발송 기능 추가 가능

---

## 3. 타겟 사용자

| 페르소나 | 역할 | 핵심 니즈 |
|---------|------|---------|
| 박정훈 | 공업사 대표·관리자 | 현장에서 고객 커뮤니케이션 즉시 처리 |
| 최성호 | 작업자·부장 | 3탭 이내 완료, 단순 조작 |

---

## 4. 목표 (Goals) / 비목표 (Non-Goals)

**Goals**
- 앱에서 정비명세서 알림톡 발송 가능
- 발송 이력(파일명·일시·상태) 조회 가능
- 웹·앱 동등한 사용성 (web-app parity)

**Non-Goals**
- 명세서 파일 직접 생성/편집 (뷰어만 제공)
- 카카오 알림톡 템플릿 커스터마이징
- 다중 수신자 일괄 발송

---

## 5. 성공 지표

| 지표 | 목표 |
|------|------|
| 앱 발송 전환율 | 전체 정비명세서 발송의 30% 이상 앱 경유 |
| 발송 완료율 | 발송 시도 대비 완료 95% 이상 |
| 이력 재확인율 | 발송 완료 후 이력 조회 이탈률 20% 미만 |

---

## 6. 핵심 유저 시나리오

1. 담당자가 작업 상세 → 정비명세서 발송 섹션에서 **발송** 버튼 탭
2. 웹 연동 파일이 있으면 → 발송 확인 화면에 자동 첨부 (Option 4 흐름)
3. 웹 연동 파일이 없으면 → 파일 선택 화면 진입
4. 확인 후 **이 내용으로 발송** 탭 → 알림톡 발송
5. 완료 다이얼로그 → 확인
6. 작업 상세 복귀 → 발송완료 상태 표시
7. 추후 발송 이력 재확인 시 → 발송 이력 링크 탭 → 이력 화면

---

## 7. 기능 요구사항

| ID | 기능 | 우선순위 |
|----|------|---------|
| F-01 | 작업 상세 > 정비명세서 발송 섹션 추가 (미발송/발송완료 상태 분기) | Must |
| F-02 | 웹 연동 파일 자동 첨부 (발송 확인 화면 진입 시) | Must |
| F-03 | 앱 직접 파일 업로드 (웹 파일 없을 때 or 변경 시) | Must |
| F-04 | 알림톡 발송 API 연동 (수신자: 차주 연락처 자동 입력) | Must |
| F-05 | 발송 완료 다이얼로그 | Must |
| F-06 | 발송 이력 목록 조회 (파일명·일시·성공/실패 상태) | Must |
| F-07 | 이력에서 재발송 | Should |
| F-08 | 발송 실패 시 재시도 안내 | Should |

---

## 8. 비기능 요구사항

- 발송 API 응답 3초 이내
- PDF 파일 크기 제한: 10MB 이하
- 이력 보관: 90일

---

## 9. 제약조건 / 의존성

- 카카오 알림톡 템플릿 사전 등록 필요 (개발팀 별도 진행)
- 웹에서 업로드한 파일의 앱 연동 API 필요
- 기존 동의서 발송 컴포넌트(Card_Info_Business, Button) 재사용
