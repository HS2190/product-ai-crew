## 0. 이 제품에서 카피가 지는 책임 (왜 톤이 중요한가)

이 제품의 차별은 기능이 아니라 **"솔직해도 괜찮다는 감각"**(PRD §8.1)이다. 그 감각은 대부분 *말*로 만들어진다.

- 우민지(P3 선택 참석자)가 `가급적 회피`를 누를 수 있는 이유는 색이 황토라서가 아니라, 그 옆에 **"안 돼도 회의는 진행돼요"**가 먼저 있기 때문이다.
- 카피 한 줄이 압박을 주면 디자인의 빨강 배제·황토 처리가 무의미해진다. → **카피가 conventions의 마지막 방어선**이다.

따라서 이 가이드는 "예쁜 문장"이 아니라 **압박을 만들지 않는 문장**을 규칙으로 둔다.

## 1. 보이스 퍼스널리티

| 키워드 | 이 제품에서의 의미 | 안티패턴 |
|--------|------------------|---------|
| **안심을 먼저 준다 (Reassuring first)** | 요청·입력보다 "괜찮다"를 앞에 둔다 | 입력부터 들이밀기, 의무 먼저 |
| **압박하지 않는 (Non-pressuring)** | 독촉·강요·죄책감 어휘 0 | "꼭", "반드시", "정말요?", "다른 분들이 기다려요" |
| **명료한 (Clear)** | 한 문장에 한 메시지, 다음 행동 명시 | 장황한 안내, 모호한 에러 |
| **차분히 따뜻한 (Warm but composed)** | 따뜻하되 과장 없음 | 느낌표 남발, 이모지 감탄, 과한 친근함 |

### 1.1 키 원칙 — 이 제품 버전

```
딱딱함  ──────●───────  가벼움      (중앙보다 약간 따뜻 쪽)
격식체  ───────●──────  구어체      (-해요체로 통일)
경고적  ●─────────────  안심적      (★ 끝까지 안심 쪽 — 부정 강도에도)
```

전문적이되 차갑지 않게, 따뜻하되 가볍지 않게. **그리고 무엇보다, 무엇을 눌러도 사용자를 탓하지 않게.**

## 2. 존댓말 체계 (전 서비스 통일)

- **종결어미**: `-해요` 체로 통일. `-합니다`/`-하십시오` 금지.
  - ✗ `응답이 마감되었습니다` → ✓ `응답이 마감됐어요`
- **버튼 레이블**: 동사 기본형 + `-기`/`-하기` 또는 명사형. (`응답 제출`, `이 시간으로 확정`, `다시 시도`)
- **취소·닫기**: 항상 `취소` 고정.
- **주어**: 사용자를 부를 때 **"당신"을 안심 문맥에서만** 제한적으로 쓴다. 안심 카피는 호명이 효과적이지만("당신이 안 돼도"), UI 일반 문구에서는 주어를 생략해 담백하게.
  - 안심: ✓ `안 돼도 회의는 열려요` (주어 생략형도 가능 — 길이 제약 시 우선)
  - 일반: ✓ `응답을 전달했어요` (주어 생략)

> designer-profile(담백한 문어체·AI 톤 회피) 반영: 병렬구조 남발("빠르고, 쉽고, 안전하게")·강조용 따옴표·이모지 감탄을 피한다.

## 3. ★ 강도 어휘 사전 (IntensityScale.label 확정)

강도 라벨은 `IntensityScale` 배열의 `label` 필드다(screen-plan §0.1). UX 라이터가 확정하되, **가변 N단계 규약을 깨지 않는다** — 라벨은 데이터로 주입되며 화면에 하드코딩하지 않는다.

### 3.1 4단계 데모 기본 라벨 (확정)

| `id` | 확정 라벨 | `ariaLabel`(스크린리더) | 어휘 선택 근거 |
|------|----------|------------------------|---------------|
| `prefer` | **선호** | "선호, 이 시간이 좋아요" | 가장 짧고 중립적인 긍정어. "최고/베스트" 같은 과장 배제 |
| `ok` | **가능** | "가능, 이 시간도 괜찮아요" | "보통"이 아니라 "가능" — 중립 사실 진술. 부정 뉘앙스 0 |
| `avoid` | **가급적 회피** | "가급적 회피, 가능하면 피하고 싶어요" | conventions 어휘 그대로. "싫음"·"별로" 금지. "가급적"이 강요받지 않는 여지를 남김 |
| `hard-no` | **불가** | "불가, 이 시간은 어려워요" | PRD는 "절대 불가"지만 라벨은 **"불가"로 축약**(아래 근거). aria엔 "어려워요"로 톤 완화 |

### 3.2 라벨 어휘 결정 근거 (3가지 판단)

1. **`avoid` = "가급적 회피"** — PRD §8.3 어휘를 그대로 채택. "가급적"이 핵심이다. "회피"만 쓰면 단정적이지만 "가급적 회피"는 *여지*를 남겨 압박을 덜어낸다.
2. **`hard-no` = "불가"** (≠ PRD의 "절대 불가") — 칩 라벨은 길이 제약이 크다(4칩 균등분배, 모바일 420px). "절대 불가"는 5자라 칩에서 줄바꿈 위험 + "절대"라는 강한 부사가 conventions의 *중립 어휘* 원칙과 마찰. → **칩 라벨은 "불가"(2자)**, 범례·aria에서 "이 시간은 어려워요"로 풀어 설명한다. (강도 정보는 `softHard==hard`로 데이터가 보장하므로, 라벨이 "절대"를 안 써도 추천 로직은 동일하게 제외 처리한다 — feature-spec STEP1.)
3. **가치판단 어휘 전면 금지** — "싫음/별로/최악/꺼림" 같은 감정·평가어를 라벨·코멘트·집계 어디에도 쓰지 않는다. 강도는 *시간에 대한 사실*이지 *감정*이 아니다.

### 3.3 3단계 전환 시 (가변 규약)

3단계로 바뀌면 배열만 교체한다(화면·코드 불변). 라벨 권장: **선호 / 가능 / 불가**. (`avoid`가 빠지고 `hard-no`만 부정으로 남음.) UX 라이터는 어떤 단계 수에서도 "중립·비감정·여지 남김" 원칙만 지키면 된다.

## 4. ★ 안심·비공개 카피의 동작 일치 규칙 (과대 보증 금지 — v1.1 핵심)

안심·비공개·상태 고지 문구는 **feature-spec의 실제 동작과 정확히 일치**해야 한다. 동작보다 더 강하게 약속하면 거짓 안심이고, 약하게 쓰면 차별점이 전달되지 않는다. 아래는 동작↔카피 대조표다.

| 카피가 주는 인상 | feature-spec 실제 동작 | 허용 카피 | 금지 카피(과대 보증) |
|-----------------|----------------------|----------|---------------------|
| 응답이 안 보인다 | F-WEB-DASH-003-003: optional 응답을 **개인 단위 비표시, 주최자는 집계로만** 봄. 다른 참석자에겐 노출 안 됨. | `다른 참석자에게는 보이지 않아요` / `주최자에게는 집계로만 전달돼요` | `완벽 익명` / `아무도 볼 수 없어요` / `절대 안전` |
| 익명성 임계 | F-WEB-DASH-003-003: 선택 응답이 **1명뿐인 슬롯**은 집계가 곧 개인 식별이라 강도 비표시("선택 1명 응답"). 임계 2·3명은 미결. | (주최자 화면) `선택 1명 응답` (강도 가림) | 임계를 "항상 익명"으로 일반화하지 말 것 |
| 빠져도 됨 | F-MOB-RESP-003-001: optional 참석자는 본인 없이도 회의 성립. | `안 돼도 회의는 진행돼요` | `당신은 중요하지 않아요`(비하) / `안 와도 그만이에요`(가벼이) |
| 비공개 지속 | F-MOB-RESP-003-002: RESP-001 머무는 동안 "비공개" 지속 노출. 부정 강도 선택에도 무경고. | `이 응답은 비공개예요` | `암호화돼 100% 안전` (mock이며 암호화 보증 없음) |
| 리마인더 | F-WEB-DASH-004-002: **실발송 없음**(mock), 상태 배지만 변경. | `리마인드 보냄(데모)` | `알림을 보냈어요` (실제로 안 보냄 → 거짓) |

### 4.1 비공개 카피의 정확한 경계 (가장 조심할 지점)

- **참석자에게**(RESP): "다른 **참석자**에게는 보이지 않아요"라고 쓴다. 주최자는 *집계로* 보므로 "아무에게도 안 보여요"는 거짓이다. 주최자 존재를 숨기지 않되, 개인 식별이 안 된다는 사실을 전한다.
  - ✓ `응답은 다른 참석자에게 보이지 않아요. 주최자는 모인 응답을 집계로만 봐요.`
  - ✗ `아무도 당신의 응답을 볼 수 없어요` (주최자 집계 노출과 불일치)
- **주최자에게**(DASH): "선택 참석자 응답은 **집계로만** 표시돼요"라고 명시한다. 개인을 못 본다는 *제약*을 주최자에게도 솔직히 고지한다(비공개 경계 = 양쪽에 같은 사실).
- **1명 임계**: 주최자 화면에서 선택 1명뿐이면 "선택 1명 응답"만. 이때 "집계"라는 단어는 1명에 대해선 부적절하므로 강도 자체를 가린다. 카피는 분포를 말하지 않고 *응답 있음*만 알린다.

## 5. 컴포넌트별 라이팅 규칙

**[버튼]** — 동작 동사, 2~8자. 모바일 하단 CTA는 풀폭이라 6자 내외 권장.
- ✓ `응답 제출`, `이 시간으로 확정`(확정 버튼은 맥락 중요해 예외적 길게 허용), `다시 시도`, `링크 복사`
- 취소는 `취소` 고정.

**[플레이스홀더]** — 예시·형식 안내. `입력하세요` 단독 금지.
- ✓ 이름: `이름을 적어 주세요` (이메일 형식 아님 — 무가입 이름이라 형식 예시 불필요, 행동 안내로)
- ✓ 코멘트: `사정을 짧게 남겨도 돼요` (의무 아님을 "~도 돼요"로 전달)

**[에러]** — 원인 + 다음 행동. 사용자 탓 금지. **황토 토스트**(빨강 아님).
- ✓ `잠시 후 다시 시도해 주세요` (제출 실패 — 입력값은 유지되니 불안 주지 않음)
- ✓ `이 링크는 더 이상 유효하지 않아요. 주최자에게 알려 주세요` (만료 — 다음 행동 명시)

**[빈상태]** — 왜 비었는지 + 무엇을 하면 되는지. **여기서도 압박 금지**(주최자에게도).
- ✓ `아직 응답이 없어요. 링크를 공유해 보세요` (응답 0 — "독촉하세요" 아님)

**[알림/성공/토스트]** — 간결. 과장 감탄·이모지 금지.
- ✓ `응답을 전달했어요`, `복사됐어요`
- ✗ `완료되었습니다!!!`, `성공적으로 전송되었어요 🎉`

**[안심 배너]** — 안심을 *먼저*, 그다음 사실. 경고 톤·황토 아님(중립·따뜻, 디자인 §4 RESP-000).
- ✓ `안 돼도 회의는 진행돼요. 솔직하게 답해도 괜찮아요`

**[비공개 고지]** — 동작 일치(§4). 상주 노출은 짧게, 게이트는 풀어서.

**[경고 배너 — WarningBanner]** — 주의는 알리되 *거부·차단 톤 금지*. 황토. 느낌표 남용 금지.
- ✓ `필수 참석자 응답을 기다리는 중이에요. 지금 추천은 잠정값이에요`
- ✗ `경고! 필수 응답이 없습니다` (경고 톤)

## 6. 금지 표현 목록 (이 제품 특화 + 공통)

| 금지 표현 | 이유 | 대체 |
|----------|------|------|

| `꼭` / `반드시` / `필수로 응답` | 압박·강요 | `응답해 주세요`(담백) 또는 생략 |
| `다른 분들이 기다려요` / `당신 때문에` | 죄책감 유발 | 사용하지 않음 |
| `완벽 익명` / `절대 안전` / `아무도 못 봐요` | 동작 과대 보증(§4) | `다른 참석자에게 보이지 않아요` |
| `알림을 보냈어요`(리마인더) | mock인데 실발송 보증 → 거짓 | `리마인드 보냄(데모)` |
| `경고!` / `주의!` + 느낌표 | 경고 톤(회피=거부 아님 위반) | 담담한 평서문 |
| `귀하` / `본 서비스` / `~의 경우` | 번역투·격식 | 주어 생략 / `이 서비스` / `~하면` |
| `클릭하세요` | 디바이스 종속(모바일 웹) | `눌러 주세요` / `선택해 주세요` |
| 이모지 감탄 `🎉` `✅` | designer-profile AI톤 회피·과장 | 텍스트만 |

## 7. 수정조사 분류 기준 (디자인/기획 placeholder 검토용)

| 유형 | 설명 |
|------|------|
| `A. 키 불일치` | 다른 화면과 같은 개념인데 표현이 다름 (비공개 고지 등) |
| `B. 딱딱한 표현` | `-되었습니다` 등 |
| `C. 모호한 에러` | 원인·해결 없는 에러 |
