## 공통 데이터 모델 — IntensityScale (강도 가변 규약, screen-plan §0.1)

모든 강도 관련 기능은 `IntensityScale` 배열을 단일 진실 공급원으로 참조한다. **단계 수(3↔4)는 이 배열 길이로만 결정**되며, 어떤 기능 명세도 "4단계"를 가정하지 않는다.

```
IntensityScale[].{ id, label, order, polarity, token, weight, ariaLabel, shape }
```

- 입력(F-MOB-RESP-002), 집계 막대(F-WEB-DASH-002), 범례, 추천 점수(F-WEB-DASH-003)는 모두 이 배열을 순회한다.
- 데모 기본 4단계: prefer / ok / avoid / hard-no. 3단계 전환 시 배열만 교체, 명세·화면·코드 불변.

## FR-001 — 선호 강도 입력 모델 (강도 빈틈)

> 해결: 박서준(P2) 이분법 한계 / 우민지(P3) 솔직한 회피 표현. 화면 SCR-MOB-RESP-001.

#### F-MOB-RESP-000-001. 링크 진입 및 역할·안심 게이트
- 트리거: 참석자가 외부 공유 링크를 모바일 브라우저로 연다.
- 동작: 링크 유효성(mock) 검증 → 회의 정보·본인 역할 배지 표시. 역할이 선택이면 안심·비공개 메시지를 강조 렌더.
- 결과: SCR-MOB-RESP-000 기본 상태 노출. [응답 시작] 활성.
- 예외 처리:
  - 만료/무효 링크 → "이 링크는 더 이상 유효하지 않아요" + 주최자 문의 안내, 응답 차단
  - 이미 마감 → "응답이 마감되었습니다"
  - 후보 슬롯 0개 → 빈 상태("아직 후보 시간이 없어요") + 응답 차단
- 플랫폼 예외:
  - Mobile Web: 핵심 액션 하단 엄지 존. 한 손 조작.
  - Desktop Web: 중앙 정렬 모바일 폭 유지(참석자 동선은 모바일 전용 설계).
- 관련 컴포넌트: RoleBadge, ReassuranceBanner, PrivacyNotice, PrimaryButton

#### F-MOB-RESP-001-002. 슬롯별 강도 입력 (핵심)
- 트리거: 참석자가 슬롯 카드의 강도 칩(`IntensityChipGroup`의 한 칩)을 탭.
- 동작: 해당 슬롯의 강도를 선택값으로 설정, 카드에 색·형태·라벨로 반영(WCAG: 색 단독 금지). 칩 개수는 `IntensityScale` 길이대로 렌더.
- 결과: 슬롯 카드 선택 상태 갱신, 진행 표시("N/전체") 증가.
- 예외 처리:
  - 같은 칩 재탭 → 선택 해제(무응답 복귀). 거짓 응답 강요 금지.
  - 부정 강도(avoid/hard-no) 선택 → **경고·확인 다이얼로그·죄책감 카피 금지**(PRD §8.2, 우민지 보호). 중립 색/형태로만 반영.
  - 미선택 슬롯 = "무응답"으로 취급(빈 값 허용).
- 플랫폼 예외:
  - Mobile Web: 큰 탭 타깃(최소 44pt 권장), 세로 스크롤.
  - Desktop Web: 동일 컴포넌트, 호버 상태 추가 가능 [디자인 추정].
- 관련 컴포넌트: SlotCard, IntensityChipGroup(가변), ProgressIndicator

#### F-MOB-RESP-001-003. 응답 제출
- 트리거: 참석자가 하단 고정 [응답 제출] 탭.
- 동작: 현재 입력값 저장(mock) → 완료 화면 이동.
- 결과: SCR-MOB-RESP-002 완료. 선택 참석자에겐 비공개 전달 재확인 카피.
- 예외 처리:
  - 일부 슬롯만 응답 → "응답하지 않은 슬롯이 있어요. 그대로 제출할까요?"(중립, 강요 금지) → 제출/보완 선택.
  - 제출 실패(mock 드묾) → 인라인 토스트 + **입력값 보존**, 재시도.
  - 마감 후 제출 시도 → "응답이 마감되었습니다", 제출 차단.
- 플랫폼 예외: Mobile/Desktop 동일. 브라우저 뒤로가기 시 입력값 임시 보존.
- 관련 컴포넌트: SubmitButton, ConfirmSheet, Toast

## FR-002 — 필수/선택 역할 + 역할 반영 추천 로직 (역할 빈틈)

> 해결: 김도현(P1) 역할 구분 부재 → 일정 지연. 화면 SCR-WEB-ORG-001, SCR-WEB-DASH-001.

#### F-WEB-ORG-001-001. 참석자 역할 지정
- 트리거: 주최자가 참석자 행의 필수/선택 토글을 탭.
- 동작: 해당 참석자의 role을 required/optional로 설정.
- 결과: 토글 상태 즉시 반영. 추천 로직 계산에 반영(hard 제약 vs 가중).
- 예외 처리:
  - 필수 0명 → 경고 안내("필수 인원이 없으면 모든 응답이 동등 취급돼요"). 강제 차단 아님.
  - 참석자 0명 → [조율 만들기] 비활성.
- 플랫폼 예외: Mobile Web 행 토글 / Desktop Web 표 형태로 다인원 밀도 높게.
- 관련 컴포넌트: AttendeeRow, RoleToggle

#### F-WEB-DASH-001-002. 역할 반영 추천 정렬 (deterministic, screen-plan §0.3)
- 트리거: 대시보드 진입 또는 새 응답 수신.
- 동작:
  1. **제외는 오직 필수 hard-no만** [확정]: 슬롯에 required 응답 중 `hard-no` 1건이라도 있으면 그 슬롯을 추천 후보에서 **제외**(강등 아님). 그 외 모든 조합(필수 soft, 선택 hard-no, 선택 soft)은 제외하지 않고 **감점**만 한다. 근거: 필수 전원 참석을 구조적으로 보장하되, 선택 참석자가 전원 불가여도 회의는 성립.
  2. **감점=가중 점수**: 제외되지 않은 슬롯은 각 응답의 `IntensityScale.weight` 합으로 점수 산정. optional의 hard-no, 필수의 avoid 등 부정 강도는 weight 감점으로 반영(빠져도/불편해도 성립).
  3. **결정적 정렬**: 점수 내림차순. 동률 tie-break 고정 순서 = ① 필수 prefer 수 → ② 미응답 적은 순 → ③ 슬롯 시작시각 빠른 순. 무작위 없음 → 동일 입력 동일 결과(NFR-004).
- 결과: 추천 슬롯 리스트가 점수순으로 렌더, 1순위 배지.
- 예외 처리:
  - 응답 0건 → 빈 상태("응답이 모이면 추천이 표시돼요").
  - 모든 슬롯이 필수 hard-no → 추천 없음 + "필수 인원이 모두 가능한 시간이 없어요" 안내, 차선(감점) 슬롯 제시.
  - 점수 계산은 `weight`만 참조하므로 강도 단계 수 변경에도 함수 불변(screen-plan §0.1 규칙5).
- 플랫폼 예외: Mobile 카드 리스트 / Desktop 표. 계산 로직 동일.
- 관련 컴포넌트: RecommendedSlotList, SlotScoreBadge

## FR-003 — 선택 참석자 솔직함 보호 (솔직함 빈틈) ★핵심

> 해결: 우민지(P3) 공개 압박·거짓 응답·안심 부재. 화면 RESP-000/001, DASH-001. NFR-002(비공개 체감).

#### F-MOB-RESP-003-001. 안심 메시지 표시
- 트리거: 역할이 optional인 참석자가 RESP-000/001 진입.
- 동작: "당신이 안 돼도 회의는 진행됩니다" 안심 배너 + "당신의 응답은 다른 참석자에게 보이지 않아요" 비공개 고지를 강조 렌더(required엔 약하게/생략).
- 결과: 선택 참석자가 빠져도 됨·비공개를 첫 화면에서 인지(Flow A 체감3·4).
- 예외 처리: 역할 미지정 참석자 → 기본은 안심 메시지 노출(보수적, 솔직함 우선).
- 플랫폼 예외: Mobile/Desktop 동일. 모바일에서 배너가 콘텐츠를 가리지 않게 [디자인 추정].
- 관련 컴포넌트: ReassuranceBanner, PrivacyNotice

#### F-MOB-RESP-003-002. 응답 비공개 처리 (체감 지속)
- 트리거: 선택 참석자가 강도 입력 화면(RESP-001)에 머무는 동안.
- 동작: "이 응답은 비공개예요" 표시를 화면에 지속 노출(NFR-002 체감). 부정 강도 선택 시에도 무경고(F-MOB-RESP-001-002와 일관).
- 결과: 솔직함의 비용이 낮다는 인식 지속(Flow A 체감5·6).
- 예외 처리: 없음(상시 노출). 시각적 방해 최소화.
- 관련 컴포넌트: PrivacyNotice(persistent)

#### F-WEB-DASH-003-003. 대시보드 비공개 경계 (집계만 노출)
- 트리거: 주최자가 대시보드에서 슬롯/응답을 본다.
- 동작: optional 참석자의 강도·코멘트·불참을 **개인 단위로 표시하지 않고 집계로만** 렌더(PRD §10 "집계만 노출" 채택). "선택 참석자 응답은 집계로만 표시됩니다" 고지.
- 결과: 주최자는 의사결정에 필요한 집계는 얻되, 우민지의 개인 신호는 보호(세그먼트 긴장 절충, persona §세그먼트 긴장).
- 예외 처리:
  - 선택 참석자가 1명뿐인 슬롯 → 집계가 곧 개인 식별 위험 → [확인 필요] 최소 익명성 임계(예: 1명이면 "선택 1명 응답"만, 강도 비표시) 디자이너 협의.
- 플랫폼 예외: Mobile/Desktop 동일 규칙.
- 관련 컴포넌트: IntensityDistributionBar(집계), PrivacyBoundaryNotice

#### F-WEB-DASH-005-001. 강도 분포 집계 표시 (가변 N단계)

- 예외 처리:

  - 필수 hard-no 포함 슬롯 → 경고 배지 + 확정 시 재확인.
- 플랫폼 예외: Mobile 시트 / Desktop 모달.
