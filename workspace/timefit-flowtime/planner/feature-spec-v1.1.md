## 공통 데이터 모델 — IntensityScale (강도 가변 규약, screen-plan §0.1)

모든 강도 관련 기능은 `IntensityScale` 배열을 단일 진실 공급원으로 참조한다. **단계 수(3↔4)는 이 배열 길이로만 결정**되며, 어떤 기능 명세도 "4단계"를 가정하지 않는다.

```
IntensityScale[].{ id, label, order, polarity, token, weight, softHard, ariaLabel, shape }
```

- 입력(F-MOB-RESP-001-002), 집계 막대(F-WEB-DASH-005-001), 범례, 추천 점수(F-WEB-DASH-002-002)는 모두 이 배열을 순회한다.
- 데모 기본 4단계: prefer / ok / avoid / hard-no. 3단계 전환 시 배열만 교체, 명세·화면·코드 불변.
- **`softHard`**: 제외 판정(추천 STEP1)이 `softHard==hard`에 종속된다. `polarity`(색 계열)와 분리된 필드다 — 4단계에서 avoid·hard-no 둘 다 `polarity=−`지만 hard-no만 `softHard=hard`다.

## FR-001 — 선호 강도 입력 모델 (강도 빈틈)

> 해결: 박서준(P2) 이분법 한계 / 우민지(P3) 솔직한 회피 표현. 화면 SCR-MOB-RESP-001.

#### F-MOB-RESP-000-001. 링크 진입 및 역할·안심 게이트
- 트리거: 참석자가 외부 공유 링크를 모바일 브라우저로 연다.
- 동작: 링크 유효성(mock) 검증 → 회의 정보·본인 역할 배지 표시. 역할이 선택이면 안심·비공개 메시지를 강조 렌더.
- 결과: SCR-MOB-RESP-000 Default 노출. [응답 시작] 활성(이름 입력 후).
- 상태: Default(정보+입력) / Loading(검증 스켈레톤) / Error(만료·마감) / Empty(슬롯 0개) / Disabled(이름 미입력 시 [응답 시작]) / 성공=RESP-001 전이.
- 예외 처리:
  - 만료/무효 링크 → "이 링크는 더 이상 유효하지 않아요" + 주최자 문의 안내, 응답 차단
  - 이미 마감 → "응답이 마감되었습니다"
  - 후보 슬롯 0개 → Empty("아직 후보 시간이 없어요") + 응답 차단
- 플랫폼 예외:
  - Mobile Web: 핵심 액션 하단 엄지 존. 한 손 조작.
  - Desktop Web: 중앙 정렬 모바일 폭 유지(참석자 동선은 모바일 전용 설계).
- 관련 컴포넌트: RoleBadge, ReassuranceBanner, PrivacyNotice, PrimaryButton

#### F-MOB-RESP-001-002. 슬롯별 강도 입력 (핵심)

- 동작: 해당 슬롯의 강도를 선택값으로 설정, 카드에 색·형태·라벨로 반영(WCAG: 색 단독 금지). 칩 개수는 `IntensityScale` 길이대로 렌더.
- 결과: 슬롯 카드 선택 상태 갱신, 진행 표시("N/전체") 증가.
- 상태: Default(미선택) / Loading(슬롯 목록 스켈레톤) / Error(제출 실패—입력값 보존) / Empty=해당 없음(게이트서 차단) / Disabled=해당 없음(무응답 제출 허용) / 성공=RESP-002 전이.
- 예외 처리:
  - 같은 칩 재탭 → 선택 해제(무응답 복귀). 거짓 응답 강요 금지.
  - 부정 강도(avoid/hard-no) 선택 → **경고·확인 다이얼로그·죄책감 카피 금지**(PRD §8.2, conventions "회피는 거부가 아님", 우민지 보호). **황토(`#B5852A`) 중립 색/형태로만** 반영, 빨강 배제.
  - 미선택 슬롯 = "무응답"으로 취급(빈 값 허용).
- 플랫폼 예외:
  - Mobile Web: 큰 탭 타깃(최소 44pt 권장), 세로 스크롤.
  - Desktop Web: 동일 컴포넌트, 호버 상태 추가 가능 [디자인 추정].

#### F-MOB-RESP-001-003. 응답 제출
- 트리거: 참석자가 하단 고정 [응답 제출] 탭.

- 결과: SCR-MOB-RESP-002 완료. 선택 참석자에겐 비공개 전달 재확인 카피.
- 상태: Default / Loading(전송) / Error(전송 실패—입력값 보존, 재시도) / Empty=해당 없음 / Disabled(마감 후) / 성공=완료 화면.
- 예외 처리:
  - 일부 슬롯만 응답 → "응답하지 않은 슬롯이 있어요. 그대로 제출할까요?"(중립, 강요 금지) → 제출/보완 선택.

  - 마감 후 제출 시도 → "응답이 마감되었습니다", 제출 차단.
- 플랫폼 예외: Mobile/Desktop 동일. 브라우저 뒤로가기 시 입력값 임시 보존(screen-plan §5.1).

## FR-002 — 필수/선택 역할 + 역할 반영 추천 로직 (역할 빈틈)

> 해결: 김도현(P1) 역할 구분 부재 → 일정 지연. 화면 SCR-WEB-ORG-001, SCR-WEB-DASH-001.

#### F-WEB-ORG-001-001. 참석자 역할 지정
- 트리거: 주최자가 참석자 행의 필수/선택 토글을 탭.
- 동작: 해당 참석자의 role을 required/optional로 설정.
- 결과: 토글 상태 즉시 반영. 추천 로직 계산에 반영(hard 제약 vs 가중).
- 상태: Default / Loading=해당 없음(로컬 토글) / Error=해당 없음(로컬) / Empty(참석자 0명—[조율 만들기] 비활성) / Disabled([조율 만들기]: 슬롯/참석자 0) / 성공=ORG-002 전이.
- 예외 처리:
  - 필수 0명 → 경고 안내("필수 인원이 없으면 모든 응답이 동등 취급돼요"). 강제 차단 아님.
  - 참석자 0명 → [조율 만들기] 비활성.
- 플랫폼 예외: Mobile Web 행 토글 / Desktop Web 표 형태로 다인원 밀도 높게.
- 관련 컴포넌트: AttendeeRow, RoleToggle

#### F-WEB-DASH-002-002. 역할 반영 추천 정렬 (deterministic, screen-plan §0.3 — 단일 확정 규칙)
> **flowtime decisions(2026-06-29) 그대로. "제외 OR 감점" 양다리 없음.** 아래 STEP 1~4는 동일 입력→동일 출력(NFR-004).

- 트리거: 대시보드 진입 또는 새 응답 수신.
- 동작 (의사코드):
  ```
  STEP 1 (자격) — 각 슬롯에 대해:
    if (required 응답 중 softHard==hard 가 1건이라도 존재) → slot.status = excluded
    else → slot.status = candidate
    // 제외는 오직 이 조건만. 필수 soft·선택 hard-no·선택 soft 는 제외 안 함.

  STEP 2 (점수) — status==candidate 슬롯만:
    slot.score = Σ( IntensityScale[응답].weight )   // 응답한 모든 참석자(필수+선택)
    // 부정 강도는 음수 weight 로 감점되어 점수에 남음. 미응답 = 0 기여.

  STEP 3 (정렬) — candidate 슬롯을 정렬:
    1차: score 내림차순
    동률 tie-break(순차, 갈리면 멈춤):
      ① required 'prefer' 응답 수 많은 슬롯
      ② 미응답 인원 적은 슬롯
      ③ 슬롯 시작시각 빠른 슬롯
      ④ 슬롯 생성순(인덱스) 빠른 슬롯   // 완전 결정성 최종 결정자
    → 순서 유일 결정(무작위 0)

  STEP 4 (표시):
    candidate → 추천 리스트(점수·순위 배지)
    excluded → "필수 참석자가 불가한 시간" 접힘 영역(황토 배지, 거부 톤 금지)
  ```
- 결과: 추천 슬롯 리스트가 점수순으로 렌더, 1순위 배지. 제외 슬롯은 별도 영역.
- 상태: Default(정렬됨) / Loading(계산 스켈레톤) / Error(로드 실패) / Empty(응답 0건 placeholder) / Disabled(확정 마감 후 읽기전용) / 성공=DASH-002 전이.
- 예외 처리 (엣지케이스 — 각 단일 결과):
  - 응답 0건 → Empty("응답이 모이면 추천이 표시돼요").
  - 전원 불가(모든 슬롯 excluded) → 추천 비움 + "필수 참석자가 모두 가능한 시간이 아직 없어요" + 제외 슬롯 목록 + [후보 시간 추가하기].
  - 필수 1명 hard-no → 그 슬롯만 excluded(STEP1), 나머지 정상.
  - 필수 응답 0(선택만) → 추천 *잠정* + "필수 참석자 응답 대기 중" 경고 배너.
  - 점수 전부 동률 → STEP3 tie-break ①→②→③→④로 유일 정렬(무작위 절대 아님).
  - 점수 계산은 `weight`/`softHard`만 참조 → 강도 단계 수 변경에도 함수 불변(screen-plan §0.1 규칙5).
- 플랫폼 예외: Mobile 카드 리스트 / Desktop 표. 계산 로직 동일.
- 관련 컴포넌트: RecommendedSlotList, SlotScoreBadge, ExcludedSlotSection

## FR-003 — 선택 참석자 솔직함 보호 (솔직함 빈틈) ★핵심

> 해결: 우민지(P3) 공개 압박·거짓 응답·안심 부재. 화면 RESP-000/001, DASH-001. NFR-002(비공개 체감).

#### F-MOB-RESP-003-001. 안심 메시지 표시
- 트리거: 역할이 optional인 참석자가 RESP-000/001 진입.
- 동작: "당신이 안 돼도 회의는 진행됩니다" 안심 배너 + "당신의 응답은 다른 참석자에게 보이지 않아요" 비공개 고지를 강조 렌더(required엔 약하게/생략).
- 결과: 선택 참석자가 빠져도 됨·비공개를 첫 화면에서 인지(Flow A 체감3·4).
- 상태: Default(노출) / Loading·Error·Empty·Disabled=해당 없음(상시 정적 카피, 데이터 의존 없음) / 성공=인지(별도 상태 없음).
- 예외 처리: 역할 미지정 참석자 → 기본은 안심 메시지 노출(보수적, 솔직함 우선).
- 플랫폼 예외: Mobile/Desktop 동일. 모바일에서 배너가 콘텐츠를 가리지 않게 [디자인 추정].
- 관련 컴포넌트: ReassuranceBanner, PrivacyNotice

#### F-MOB-RESP-003-002. 응답 비공개 처리 (체감 지속)
- 트리거: 선택 참석자가 강도 입력 화면(RESP-001)에 머무는 동안.
- 동작: "이 응답은 비공개예요" 표시를 화면에 지속 노출(NFR-002 체감). 부정 강도 선택 시에도 무경고(F-MOB-RESP-001-002와 일관).
- 결과: 솔직함의 비용이 낮다는 인식 지속(Flow A 체감5·6).
- 상태: Default(상시 노출) / 그 외 상태=해당 없음(정적 지속 표시).
- 예외 처리: 없음(상시 노출). 시각적 방해 최소화.
- 관련 컴포넌트: PrivacyNotice(persistent)

#### F-WEB-DASH-003-003. 대시보드 비공개 경계 (집계만 노출 + 최소 익명성 임계)
- 트리거: 주최자가 대시보드에서 슬롯/응답을 본다.
- 동작: optional 참석자의 강도·코멘트·불참을 **개인 단위로 표시하지 않고 집계로만** 렌더(PRD §10 "집계만 노출" 채택). "선택 참석자 응답은 집계로만 표시됩니다" 고지.
- 결과: 주최자는 의사결정에 필요한 집계는 얻되, 우민지의 개인 신호는 보호(세그먼트 긴장 절충, persona §세그먼트 긴장).
- 상태: Default(집계) / 최소 익명성 발동 상태 / 그 외=해당 없음(표시 규칙).
- 예외 처리:
  - **선택 참석자가 그 슬롯에 1명뿐** → 집계가 곧 개인 식별 위험 → 강도 분포 막대 대신 "선택 1명 응답"만 표시(강도 비표시). 임계값(1명/2명/3명?)은 [확인 필요]로 디자이너 협의(screen-plan §7).
- 플랫폼 예외: Mobile/Desktop 동일 규칙.
- 관련 컴포넌트: IntensityDistributionBar(집계), PrivacyBoundaryNotice

## FR-004 — 모바일 초경량 응답 + 리마인더(mock, Should)

> 해결: 박서준(P2) 낮은 마찰 / 김도현(P1) 미응답 독촉 부담. 응답 경량은 Must급, 리마인더는 mock 축소(PRD §6). (PRD에서 FR-005가 모바일+리마인더이나, 본 명세는 화면 기준으로 응답경량을 여기 묶고 대시보드 출력부는 FR-005로 둔다.)

#### F-MOB-RESP-004-001. 초경량 응답 인터랙션
- 트리거: 참석자가 RESP-001에서 슬롯 응답.
