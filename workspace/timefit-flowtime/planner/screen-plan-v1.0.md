## 0. 이 단계의 핵심 점검 항목 — 설계 원칙 (반드시 디자이너·Engineer가 따른다)

### 0.1 ★ 강도 척도는 가변(3~4단계)이다 — 컴포넌트가 단계 수를 파라미터로 받는다

PM은 4단계(선호 prefer / 가능 ok / 가급적 회피 avoid / 불가 hard-no)를 제안했으나 **확정이 아니다**(PRD §10 [확인 필요], 사용성 테스트로 3↔4단계 검증). 따라서 강도와 관련된 모든 화면·컴포넌트·집계 표시는 **단계 수가 3↔4로 바뀌어도 레이아웃·집계·범례가 깨지지 않도록** 설계한다.

**추상화 규약 — `IntensityScale` (단일 진실 공급원, single source of truth)**

강도 척도를 화면에 하드코딩하지 않고, 아래 형태의 **데이터 배열**로 분리한다. 모든 강도 UI(입력 칩, 집계 막대, 범례, 추천 정렬)는 이 배열을 순회(map)해 렌더한다.

```
IntensityScale = [
  { id, label, order, polarity, token, weight, ariaLabel, shape }
]
```

| 키 | 의미 | 3단계 예 | 4단계 예 |
|----|------|---------|---------|
| `id` | 불변 식별자(데이터/집계 키) | prefer / ok / hard-no | prefer / ok / avoid / hard-no |
| `label` | 표시 라벨(UX라이터가 확정) | 선호 / 가능 / 불가 | 선호 / 가능 / 가급적 회피 / 불가 |
| `order` | 정렬 순서(긍정→부정) | 0,1,2 | 0,1,2,3 |
| `polarity` | 긍정/중립/부정 — 색 계열 결정 | +,0,− | +,0,−,− |
| `token` | 디자인 토큰 참조(색·명도) | 데이터로만 주입 | 데이터로만 주입 |
| `weight` | 추천 점수 계산용 가중치 | +2,0,−∞(hard) | +2,+1,−1,−∞(hard) |
| `shape` | 색 외 형태 구분(접근성, WCAG) | 형태 토큰 | 형태 토큰 |

**설계 규칙 (검증 체크리스트)**

1. **레이아웃은 N단계에 종속되지 않는다.** 입력 칩은 1행 가로 스크롤 또는 wrap. 3개든 4개든 동일 컴포넌트가 흡수한다. (절대 "4칸 고정 그리드"로 그리지 않는다.)
2. **집계 표시(대시보드)도 N단계 종속 금지.** 슬롯별 분포는 stacked bar 또는 분절 막대로, `IntensityScale`를 순회해 segment를 쌓는다. 단계가 줄면 segment 수만 줄고 막대 폭은 100%로 유지된다.
3. **범례(legend)는 척도 배열에서 자동 생성**한다. 라벨·색·형태를 손으로 적지 않는다.
4. **색은 데이터로 주입, 컴포넌트에 하드코딩 금지.** `polarity`/`token`만 본다. 단계 추가/삭제 시 코드 변경 없이 배열만 수정.
5. **추천 점수 계산은 `weight`만 참조.** 단, **필수 참석자의 `hard-no`만** 슬롯 자격 박탈(제외)이고, 그 외 모든 부정 강도는 `weight` 감점으로 처리한다(§0.3 참조). 단계 수가 바뀌어도 계산 함수는 동일.
6. **순서·접근성은 `order`/`shape`/`ariaLabel`로 보장.** 색약 사용자도 형태·라벨로 강도 구분 가능(PRD §8.3 WCAG).

> 즉 화면 기획·디자인·구현 전 과정에서 "강도 단계 = 4"라는 가정을 코드/레이아웃 어디에도 박지 않는다. 1차 데모는 4단계로 시연하되, 3단계로 전환해도 같은 화면이 그대로 동작해야 한다. **이것이 이번 기획 단계의 1순위 점검 항목이다.**

### 0.2 "30초"는 설계 목표지 측정값이 아니다

플로우를 그 목표가 **관측 가능하도록** 설계한다 — 응답 1건당 **탭 수와 입력 단계 수를 최소화**한다(목표: 슬롯 1개 응답 = 탭 1회). 단정적 수치("30초 걸린다")로 화면에 적지 않는다. 응답 시작·완료 시점을 이벤트로 표시할 지점을 화면에 마련한다(KPI 관측, PRD §7).

### 0.3 "선택=가중치" 추천 로직의 화면·명세 수준 동작 (PRD FR-002 / NFR-004)

PRD에서 미정의된 산정 규칙을 아래로 **구체화**한다. 결정성(동일 입력→동일 결과, NFR-004)을 보장한다.

- **제외는 오직 "필수 참석자의 hard-no(절대 불가)"만** [확정]: 한 슬롯에 필수 참석자 중 1명이라도 `hard-no`면 그 슬롯은 **추천 후보에서 제외**한다. 그 외 모든 조합 — 필수 soft(avoid 등), 선택 hard-no, 선택 soft — 은 **전부 감점**으로 처리하고 후보에는 남긴다. **근거**: 필수 전원 참석을 구조적으로 보장하면서, 선택 참석자가 전원 불가여도 회의는 성립하게 하기 위함. ("제외 또는 감점" 양다리를 이 한 줄로 단일화 — NFR-004 결정성.)
- **선택 참석자(optional) = 가중 점수**: 각 응답의 `IntensityScale.weight` 합으로 슬롯 점수를 만든다. 선택 참석자의 hard-no는 슬롯을 제외하지 않고 **감점**만 한다(빠져도 회의 성립).
- **결정적 정렬(deterministic)**: 슬롯 점수 동률 시 **고정 tie-break 순서**(예: ① 필수 prefer 수 → ② 미응답 적은 순 → ③ 슬롯 시작시각 빠른 순). 동일 입력이면 항상 같은 순서로 정렬된다. 무작위 요소 없음.
- 점수식 자체는 `IntensityScale.weight`만 참조하므로 강도 단계 수가 바뀌어도 로직 불변(0.1과 일관).

상세 산정 규칙은 feature-spec의 F-WEB-DASH-001-002에 명세한다.

> **집계 막대 vs 추천 weight 분리** [Reviewer 보완]: `IntensityDistributionBar`(집계 막대)는 "각 강도에 몇 명이 응답했는지" **건수 분포**를 그린다 — 색은 `polarity`, 정렬은 `order`로 그리며 `weight`를 막대 높이에 쓰지 않는다(hard의 제외 신호를 막대에 반영 금지). 추천 점수는 `weight` 합산으로 계산한다. **둘은 다른 계산이다.**

## 1. IA (Information Architecture)

서비스는 **두 개의 독립 진입점**을 가진다. 계정·로그인 없음(PRD §4 In Scope, 외부 개방).

```
timefit-flowtime
│
├─ [주최자 동선] (모바일 우선 · PC 겸용)
│   SCR-WEB-ORG-001  조율 생성 (후보 슬롯·참석자·역할 설정)
│        └→ SCR-WEB-ORG-002  조율 링크 공유
│        └→ SCR-WEB-DASH-001 주최자 집계 대시보드 (추천 슬롯·미응답 현황)
│                 └→ SCR-WEB-DASH-002 슬롯 확정 (확정 모달/시트)
│                 └→ SCR-WEB-DASH-003 확정 완료
│
└─ [참석자 동선] (모바일 웹 전용 · 무가입)
    SCR-MOB-RESP-000  링크 진입 / 이름·역할 확인 (게이트)
        └→ SCR-MOB-RESP-001  슬롯 응답 (강도 입력 — 핵심)
              └→ SCR-MOB-RESP-001b  슬롯 코멘트(선택, FR-006)
        └→ SCR-MOB-RESP-002  응답 완료
```

> 플랫폼 표기: `MOB` = 모바일 웹(참석자), `WEB` = 웹(주최자, 모바일 우선·PC 겸용). 본 서비스는 네이티브 앱이 아니므로 AOS/iOS 구분 대신 **모바일 웹 / 데스크톱 웹** 반응형으로 다룬다(브레이크포인트 §6).

## 2. 참석자 동선 화면 기획

> 핵심 타겟: **우민지(P3 선택 참석자) — 솔직함 보호**. 부수 수혜: 박서준(P2 필수, 강도 표현·낮은 마찰).

### SCR-MOB-RESP-000 — 링크 진입 / 이름·역할 확인 (게이트)

- **화면 목적**: 무가입 참석자가 조율 링크로 들어와 자신을 식별하고, **자신의 역할(필수/선택)과 솔직함 보호 약속을 첫 화면에서 인지**한다.
- **진입 경로**: 외부 공유 링크(메신저/메일) → 모바일 브라우저
- **관련 화면**: → SCR-MOB-RESP-001(응답 시작)
- **화면 구성 요소**
  - 회의 제목 · 주최자명 · 후보 기간 요약
  - 이름 입력 필드(또는 주최자가 미리 넣은 명단에서 본인 선택)
  - **역할 배지**: "필수 참석자" / "선택 참석자" — 본인 역할을 명확히 표시
  - **★ 안심 메시지 (선택 참석자에게만 강조 노출)**: "당신이 안 돼도 회의는 진행됩니다. 솔직하게 답해도 괜찮아요." (FR-003 / 우민지 Pain Point 직접 해소)
  - **★ 비공개 고지 (선택 참석자)**: "당신의 응답은 다른 참석자에게 보이지 않아요." (NFR-002 비공개 체감)
  - [응답 시작] 버튼 — 하단 엄지 존(모바일 한 손 조작, planner 가이드 §물리/공간)
- **상태 정의**
  - **기본**: 회의 정보 + 이름 입력 + 역할/안심 메시지
  - **로딩**: 링크 검증 중 스켈레톤(제목·기간 자리 표시)
  - **에러**: ① 잘못된/만료 링크 → "이 링크는 더 이상 유효하지 않아요" + 주최자 문의 안내 ② 이미 마감된 조율 → "응답이 마감되었습니다"
  - **빈 상태**: 후보 슬롯이 0개인 링크(주최자가 미설정) → "아직 후보 시간이 등록되지 않았어요. 주최자에게 알려주세요." → 응답 진행 차단
- **핵심 인터랙션**: 역할이 "선택"이면 안심·비공개 메시지를 **시각적으로 더 강조**(색 블록/아이콘). "필수"면 강도 표현 안내 위주.

### SCR-MOB-RESP-001 — 슬롯 응답 (강도 입력) ★핵심 화면

- **화면 목적**: 각 후보 슬롯에 **선호 강도를 최소 탭으로 입력**. 응답 마찰 최소화(목표: 슬롯당 탭 1회).
- **진입 경로**: SCR-MOB-RESP-000 → [응답 시작]
- **관련 화면**: → SCR-MOB-RESP-001b(코멘트) / → SCR-MOB-RESP-002(완료)
- **화면 구성 요소**
  - 상단: 진행 표시("3/8 슬롯 응답") — 30초 목표 관측 지점(0.2)
  - **슬롯 카드 리스트**(세로 스크롤): 각 카드 = 날짜·시간 + **강도 입력 컨트롤**
  - **강도 입력 컨트롤 = `IntensityChipGroup`**: `IntensityScale` 배열을 순회해 칩 렌더(3단계면 칩 3개, 4단계면 4개 — §0.1). 칩은 큰 탭 타깃(모바일). 선택 시 카드에 색·형태로 반영.
  - 코멘트 아이콘(FR-006, 선택): 탭 시 SCR-MOB-RESP-001b
  - 하단 고정 [응답 제출] 버튼(엄지 존) — 응답한 슬롯 수 실시간 표시
  - **★ 비공개 리마인더(선택 참석자)**: 화면 상·하단에 은은히 "이 응답은 비공개예요" 지속 노출(NFR-002)
- **상태 정의**
  - **기본**: 모든 슬롯 미선택(중립 표시). 강도 미선택은 "무응답"이며 거짓 응답을 강요하지 않는다.
  - **로딩**: 슬롯 목록 로딩 스켈레톤 카드
  - **에러**: 제출 실패(mock에선 거의 없음) → 인라인 토스트 "잠시 후 다시 시도해 주세요", 입력값 유지(데이터 소실 금지)
  - **빈 상태**: 후보 슬롯 0개 → SCR-MOB-RESP-000에서 이미 차단(여기로 안 옴)
  - **부분 응답 상태**: 일부 슬롯만 선택하고 제출 시도 → "응답하지 않은 슬롯이 있어요. 그대로 제출할까요?"(강요 아님, 부정 뉘앙스 금지 — PRD §8.2)
- **핵심 인터랙션**
  - 강도 칩 탭 = 즉시 선택 반영(저장은 제출 시 또는 자동 임시저장). 같은 칩 재탭 = 선택 해제(무응답 복귀).
  - **부정 강도(avoid/hard-no) 선택 시 경고·죄책감 유발 금지**(PRD §8.2, 우민지 보호) — 빨강 경고색·"정말요?" 확인 다이얼로그 금지. 중립적 색/형태로만 반영.
  - 강도 칩은 색만이 아니라 **형태·라벨**로도 구분(WCAG, §0.1의 `shape`).

### SCR-MOB-RESP-001b — 슬롯 코멘트 (FR-006, 선택)

- **화면 목적**: 슬롯에 짧은 사정 첨부(메신저로 새는 맥락 모으기). Nice to Have.
- **진입**: 슬롯 카드의 코멘트 아이콘
- **구성**: 텍스트 입력(짧게), [저장]/[취소]. 글자수 가벼운 제한.
- **상태**: 기본(빈 입력) / 입력 중 / 저장됨(카드에 코멘트 아이콘 활성). 에러: mock 범위라 입력값 유지만.
- **비공개 일관성**: 선택 참석자의 코멘트도 다른 참석자에게 비공개(주최자는 집계/익명 맥락으로만, §3 협의 항목).

### SCR-MOB-RESP-002 — 응답 완료

- **화면 목적**: 응답 종료 확인 + 안심 마무리.
- **진입**: SCR-MOB-RESP-001 [응답 제출]
- **구성**: 완료 체크 + "응답이 전달되었어요" + (선택 참석자) "당신의 응답은 비공개로 안전하게 전달됐어요" 재확인 / 응답 수정 링크(마감 전).
- **상태**: 기본(완료) / 로딩(전송 중) / 에러(전송 실패 → 재시도, 입력값 보존) / 마감 후 진입 → "응답이 마감되었습니다".
- **인터랙션**: [응답 수정](마감 전만 노출) → SCR-MOB-RESP-001 재진입, 기존 입력 복원.

## 3. 주최자 동선 화면 기획

> 타겟: **김도현(P1 주최자)** — 필수 인원 기준 빠른 확정, 강도·역할 한 화면 가시화, 미응답 추적.

### SCR-WEB-ORG-001 — 조율 생성

- **화면 목적**: 후보 슬롯·참석자·역할을 설정해 조율을 만든다.
- **진입**: 서비스 첫 진입(주최자)
- **관련 화면**: → SCR-WEB-ORG-002(링크 공유)
- **구성 요소**
  - 회의 제목
  - **후보 슬롯 추가**(날짜·시간 멀티 선택)
  - **참석자 입력 + 역할 지정**: 참석자별 **필수/선택 토글**(FR-002, PRD §10 — 주최자 지정 방식 채택)
  - (선택) **강도 단계 수 설정 [확인 필요·데모 기본 4단계]**: 데모에선 고정 노출 가능. 단계 수는 `IntensityScale` 데이터로 주입되므로 향후 3단계 전환 시 화면 불변(§0.1).
  - [조율 만들기] 버튼
- **상태**: 기본(빈 폼) / 입력 중(검증) / 에러(슬롯 0개·참석자 0명이면 [만들기] 비활성 + 안내) / 로딩(생성 중).
- **빈 상태**: 신규 = 빈 폼 + "후보 시간을 추가해 주세요" 안내.
- **인터랙션**: 필수/선택 토글 즉시 반영. 필수 0명 경고("필수 인원이 없으면 모든 응답이 동등 취급돼요" — 추천 로직 의미 안내, 강요 아님).

### SCR-WEB-ORG-002 — 조율 링크 공유

- **목적**: 생성된 조율 링크를 복사/공유.
- **구성**: 링크 + [복사] + 공유 안내("이 링크를 받은 사람은 가입 없이 응답해요") + → [대시보드 보기].
- **상태**: 기본 / 복사 완료 토스트 / 에러(거의 없음).

### SCR-WEB-DASH-001 — 주최자 집계 대시보드 ★핵심 화면 (FR-005)

- **화면 목적**: 강도·역할이 반영된 **추천 슬롯 정렬**과 **미응답 현황**을 한 화면에서 보고 의사결정. 6~12명에서도 가독성 유지(NFR-003).
- **진입**: SCR-WEB-ORG-002 / 저장된 대시보드 링크
- **관련 화면**: → SCR-WEB-DASH-002(확정)
- **구성 요소**
  - 상단 요약: 응답 N/전체, 미응답 인원 수, 마감까지
  - **추천 슬롯 리스트(점수 내림차순, deterministic §0.3)**: 슬롯별
    - 슬롯 점수 / 추천 순위 배지
    - **강도 분포 막대 = `IntensityDistributionBar`**: `IntensityScale` 순회 stacked bar(§0.1 규칙2 — 단계 수 종속 금지). 필수/선택을 구분해 두 줄 또는 그룹 표시(NFR-003).
    - **필수 인원 충족 표시**: "필수 5/5 가능" 같은 hard 제약 결과(§0.3). 필수 hard-no 있으면 제외/경고 배지.
    - 미응답 영향 표시
  - **범례**: `IntensityScale`에서 자동 생성(§0.1 규칙3)
  - **★ 비공개 경계 명시**: 선택 참석자 데이터는 **개인 단위가 아니라 집계로만** 표시(PRD §10 — "집계만 노출" 채택, 우민지 보호 유지). "선택 참석자 응답은 집계로만 표시됩니다" 고지.
  - 미응답자 리마인더 영역(FR-004, mock 상태 표시 — Should): "리마인드 보냄(데모)" 상태 배지.
- **상태 정의**
  - **기본**: 응답 일부/전체 수집, 추천 정렬 표시.
  - **로딩**: 집계 계산 스켈레톤.
  - **에러**: mock 범위 — 데이터 로드 실패 시 "현황을 불러오지 못했어요" + 재시도.
  - **★ 빈 상태(응답 0건)**: "아직 응답이 없어요. 링크를 공유해 보세요." + [링크 다시 공유] + 미응답 명단. (추천 슬롯 영역은 "응답이 모이면 추천이 표시돼요" placeholder — 강도 단계 수 무관하게 동작)
  - **부분 빈 상태**: 필수 응답만 있고 선택 무응답 → 추천은 필수 기준으로 우선 표시.
- **핵심 인터랙션**
  - 슬롯 탭 → 상세(강도 분포·필수 충족·코멘트 집계). 선택 참석자 개인 식별 불가(비공개 일관).
  - 정렬 토글(추천순/시간순) — 단, 기본은 deterministic 추천순. 정렬 바꿔도 추천 점수 계산은 불변.
  - 미응답자 [리마인드](mock: 상태만 변경, 실발송 없음 — PRD Out of Scope).
  - **PC 겸용**: 데스크톱에선 슬롯을 표(행=슬롯, 열=강도 분포·필수 충족)로 밀도 높게, 모바일에선 카드 리스트로(반응형 §6).

### SCR-WEB-DASH-002 — 슬롯 확정 (확정 시트/모달)

- **목적**: 추천 슬롯 중 하나를 최종 확정.
- **진입**: 대시보드 슬롯의 [이 시간으로 확정]
- **구성**: 확정 대상 슬롯 요약 + 필수 인원 충족 재확인 + (필수 hard-no 있을 시) 경고 + [확정] / [취소].
- **상태**: 기본 / 확정 진행(로딩) / 확정 완료 → SCR-WEB-DASH-003 / 에러(재시도).
- **인터랙션**: 필수 인원 미충족 슬롯 확정 시 **경고 후 진행 허용**(주최자 권한 — 강제 차단 아님). 확정 후 응답 마감 처리.

### SCR-WEB-DASH-003 — 확정 완료

- **목적**: 확정 결과 안내 + 공유.
- **구성**: 확정 시간 + 참석자에게 공유할 안내 문구 + [결과 공유 링크 복사].
- **상태**: 기본 / 공유 완료 토스트.

## 4. 핵심 User Flow

### Flow A — 선택 참석자 우민지의 무가입 응답 (★ 솔직함 보호가 체감되는 지점)

```
[메신저로 링크 수신]
      │
      ▼
[SCR-MOB-RESP-000 진입 게이트]
   • 무가입 — 이름만 확인/선택  ← (체감1) 계정 만들 필요 없음, 마찰 0
   • 역할 배지 "선택 참석자"     ← (체감2) "나는 선택이구나" 인지
   • ★ 안심 메시지: "당신이 안 돼도 회의는 진행됩니다"  ← (체감3) 빠져도 된다는 안심 (우민지 Pain "빠져도 된다는 안심 없음" 해소)
   • ★ 비공개 고지: "응답은 다른 참석자에게 안 보여요"   ← (체감4) 솔직함의 비용↓ (Pain "응답 공개로 솔직함 비용 높음" 해소)
      │ [응답 시작]
      ▼
[SCR-MOB-RESP-001 강도 입력]
   • 슬롯 카드마다 강도 칩 탭 1회  ← 마찰 최소(0.2)
   • avoid/hard-no 눌러도 경고·죄책감 없음  ← (체감5) 솔직히 "회피" 표시 가능 (Pain "거짓 가능 응답" 해소 — 우민지 핵심)
   • 화면 내내 "이 응답은 비공개" 지속 노출  ← (체감6) 솔직함 보호 지속 체감 (NFR-002)
      │ (선택) 코멘트 첨부 → RESP-001b
      │ [응답 제출]
      ▼
[SCR-MOB-RESP-002 완료]
   • "당신의 응답은 비공개로 안전하게 전달됐어요"  ← (체감7) 마무리 안심
   • (마감 전) [응답 수정] 가능
      ▼
   [종료]  — 우민지의 개인 강도는 주최자에게도 '집계로만' 들어감(개인 식별 불가, §3 DASH-001)

예외 경로:
  • 만료/마감 링크 → RESP-000 에러 상태 → 종료(주최자 문의 안내)
  • 후보 슬롯 0개 → RESP-000 빈 상태 → 응답 차단
  • 일부 슬롯만 응답 후 제출 → "그대로 제출할까요?"(강요 없음) → 제출 또는 보완
```

**솔직함 보호 체감 지점 요약**: 무가입(체감1) → 역할 인지(2) → 안심 메시지(3) → 비공개 고지(4) → 부정 강도 무경고 입력(5) → 비공개 지속 노출(6) → 완료 재확인(7). 7개 지점에서 우민지의 3대 Pain(공개 압박·거짓 응답·안심 부재)을 단계적으로 해소한다.

### Flow B — 주최자 김도현의 대시보드 → 슬롯 확정

```
[SCR-WEB-ORG-001 조율 생성]
   • 후보 슬롯 추가 + 참석자 필수/선택 토글 지정  ← 필수 인원 기준 확정의 출발점 (Pain "역할 구분 없음" 해소)
      │ [조율 만들기]
      ▼
[SCR-WEB-ORG-002 링크 공유] → 메신저로 배포
      ▼
[SCR-WEB-DASH-001 집계 대시보드]
   • (빈 상태) 응답 0 → "링크 공유해 보세요" + 미응답 명단
   • (응답 수집) 추천 슬롯이 점수순(deterministic)으로 정렬  ← 한 화면에서 강도·역할 가시화 (Pain "메신저 수집·정리" 해소)
   • 슬롯별: 강도 분포 막대 + "필수 5/5 가능" + 미응답 영향
   • 선택 참석자는 집계로만 — 개인 식별 불가  ← 우민지 비공개 보호와 일관
   • 미응답자 [리마인드](mock)  ← Pain "일일이 독촉" 해소
      │ 추천 1순위 슬롯 [이 시간으로 확정]
      ▼
[SCR-WEB-DASH-002 확정 시트]
   • 필수 인원 충족 재확인 / (미충족 시) 경고 후 진행 허용
      │ [확정]
      ▼
[SCR-WEB-DASH-003 확정 완료] → 결과 공유 링크 복사 → 응답 마감
      ▼
   [종료]

예외 경로:
  • 필수 hard-no 슬롯 → 추천에서 제외/경고 배지 (§0.3 hard 제약)
  • 필수 인원 미충족 슬롯 확정 시도 → 경고 후 주최자 판단으로 진행 가능
  • 응답 0건 → 빈 상태, 확정 불가 (추천 placeholder)
```

## 6. 반응형 / 플랫폼 예외 (모바일 우선)

- **브레이크포인트**: Mobile(< 768px) 기준 설계 → Tablet(768~1024) → Desktop(≥ 1024) 확장.
- **참석자 동선(RESP-\*)**: **모바일 웹 전용 설계.** 데스크톱에서도 동작하되 중앙 정렬 모바일 폭 유지(한 손 조작·이동 중 사용 가정 — persona 박서준/우민지 사용 환경).
- **주최자 동선(DASH-\*)**: 모바일 우선. **PC 겸용** — 데스크톱에선 6~12명 밀도를 표(테이블) 레이아웃으로, 모바일에선 카드 리스트로(NFR-003 가독성). 강도 분포·필수 충족은 두 레이아웃 모두에서 `IntensityScale` 기반으로 동일 렌더.
- **브라우저 뒤로가기**: 응답 중 뒤로가기 → 입력값 임시 보존(데이터 소실 방지). 대시보드 뒤로가기 → 직전 화면.
- **세션**: 무가입이므로 로그인 세션 없음. 링크 자체가 접근 키(mock). 만료/마감은 링크 상태로 처리.
- **오프라인**: mock 데이터라 네트워크 의존 낮음. 제출 실패 시 입력값 보존 + 재시도(RESP-001/002 에러 상태).
- **[확인 필요]**: 데모에서 다크모드 지원 여부, 한국어 외 다국어 — 디자이너 단계 협의.

## 7. [확인 필요] 항목 (디자이너·UX라이터·Engineer로 전달)

- [확인 필요] **강도 단계 수 데모 기본값** — 4단계로 시연 제안. 단, `IntensityScale` 데이터 주입 구조라 3단계 전환 시 화면 불변(§0.1). 사용성 테스트 후 확정(PRD §10).
- [확인 필요] 선택 참석자 코멘트의 주최자 노출 범위 — 집계/익명 맥락으로만 제안(우민지 비공개 일관). 디자이너·UX라이터 협의.
