## 0. 이 단계의 핵심 점검 항목 — 설계 원칙 (반드시 디자이너·Engineer가 따른다)

### 0.1 ★ 강도 척도는 가변(3~4단계)이다 — 컴포넌트가 단계 수를 파라미터로 받는다

PM은 4단계(선호 prefer / 가능 ok / 가급적 회피 avoid / 절대 불가 hard-no)를 제안했으나 **확정이 아니다**(PRD §10 [확인 필요], 사용성 테스트로 3↔4단계 검증). 따라서 강도와 관련된 모든 화면·컴포넌트·집계 표시는 **단계 수가 3↔4로 바뀌어도 레이아웃·집계·범례가 깨지지 않도록** 설계한다.

> flowtime decisions는 **soft/hard 구분**(soft=회피 류, hard=절대 불가)을 확정했다. 미결은 *해상도·라벨링*뿐이다. 따라서 본 기획은 soft/hard 2축은 고정하고, 단계 수만 가변으로 둔다.

**추상화 규약 — `IntensityScale` (단일 진실 공급원, single source of truth)**

강도 척도를 화면에 하드코딩하지 않고, 아래 형태의 **데이터 배열**로 분리한다. 모든 강도 UI(입력 칩, 집계 막대, 범례, 추천 정렬)는 이 배열을 순회(map)해 렌더한다.

```
IntensityScale = [
  { id, label, order, polarity, token, weight, ariaLabel, shape }
]
```

| 키 | 의미 | 3단계 예 | 4단계 예 |
|----|------|---------|---------|
| `id` | 불변 식별자(데이터/집계 키) | prefer / ok / hard-no | prefer / ok / avoid / hard-no |
| `label` | 표시 라벨(UX라이터가 확정) | 선호 / 가능 / 절대 불가 | 선호 / 가능 / 가급적 회피 / 절대 불가 |
| `order` | 정렬 순서(긍정→부정) | 0,1,2 | 0,1,2,3 |
| `polarity` | 긍정/중립/부정 — 색 계열 결정 | +,0,− | +,0,−,− |
| `token` | 디자인 토큰 참조(색·명도) | 데이터로만 주입 | 데이터로만 주입 |
| `weight` | 추천 점수 계산용 가중치 | +2,0,−∞(hard) | +2,+1,−1,−∞(hard) |
| `softHard` | soft/hard 구분(제외 판정용) | soft/soft/hard | soft/soft/soft/hard |
| `shape` | 색 외 형태 구분(접근성, WCAG) | 형태 토큰 | 형태 토큰 |

> `softHard`를 v1.1에서 명시 필드로 추가한다. 추천 로직의 "제외" 판정(§0.3)이 `polarity`가 아니라 `softHard==hard`에 종속되기 때문이다. 단계 수가 늘어도 어떤 단계가 hard인지 데이터로만 결정된다.

**설계 규칙 (검증 체크리스트)**

1. **레이아웃은 N단계에 종속되지 않는다.** 입력 칩은 1행 가로 스크롤 또는 wrap. 3개든 4개든 동일 컴포넌트가 흡수한다. (절대 "4칸 고정 그리드"로 그리지 않는다.)
2. **집계 표시(대시보드)도 N단계 종속 금지.** 슬롯별 분포는 stacked bar 또는 분절 막대로, `IntensityScale`를 순회해 segment를 쌓는다. 단계가 줄면 segment 수만 줄고 막대 폭은 100%로 유지된다.
3. **범례(legend)는 척도 배열에서 자동 생성**한다. 라벨·색·형태를 손으로 적지 않는다.
4. **색은 데이터로 주입, 컴포넌트에 하드코딩 금지.** `polarity`/`token`만 본다. 단계 추가/삭제 시 코드 변경 없이 배열만 수정.
5. **추천 점수 계산은 `weight`·`softHard`만 참조.** 단, **필수 참석자의 `softHard==hard`만** 슬롯 자격 박탈(제외)이고, 그 외 모든 부정 강도는 `weight` 감점으로 처리한다(§0.3 참조). 단계 수가 바뀌어도 계산 함수는 동일.
6. **순서·접근성은 `order`/`shape`/`ariaLabel`로 보장.** 색약 사용자도 형태·라벨로 강도 구분 가능(PRD §8.3 WCAG).

> 즉 화면 기획·디자인·구현 전 과정에서 "강도 단계 = 4"라는 가정을 코드/레이아웃 어디에도 박지 않는다. 1차 데모는 4단계로 시연하되, 3단계로 전환해도 같은 화면이 그대로 동작해야 한다. **이것이 이번 기획 단계의 1순위 점검 항목이다.**

### 0.2 "30초"는 설계 목표지 측정값이 아니다

플로우를 그 목표가 **관측 가능하도록** 설계한다 — 응답 1건당 **탭 수와 입력 단계 수를 최소화**한다(목표: 슬롯 1개 응답 = 탭 1회). 단정적 수치("30초 걸린다")로 화면에 적지 않는다. 응답 시작(첫 슬롯 진입)·완료(제출) 시점을 이벤트로 표시할 지점을 화면에 마련한다(KPI 관측, PRD §7).

### 0.3 ★ 추천 로직 — 단일 확정 규칙 (PRD FR-002 / NFR-004 / flowtime decisions 2026-06-29)

> **이 규칙은 flowtime이 이미 확정한 결정이다. 본 기획은 재론·변경하지 않고 그대로 단일 규칙으로 명세한다. "제외 OR 감점"의 양다리는 존재하지 않는다.**

추천 점수와 정렬을 아래 **4단계 결정 절차**로 못박는다. 동일 입력은 항상 동일 출력(deterministic, NFR-004). 무작위 요소 없음.

**STEP 1 — 슬롯 자격 판정 (제외는 단 하나의 조건만)**
- 한 슬롯에 **필수(required) 참석자 중 1명이라도 `softHard==hard`(절대 불가)** 응답이 있으면 → 그 슬롯은 **추천 후보에서 제외**(`status: excluded`).
- 그 외 *모든* 조합은 제외하지 않는다:
  - 필수 참석자의 soft 부정(가급적 회피) → **제외 안 함, 감점**
  - 선택(optional) 참석자의 hard-no(절대 불가) → **제외 안 함, 감점**
  - 선택 참석자의 soft 부정(회피) → **제외 안 함, 감점**
- **근거**: 필수 전원 참석을 구조적으로 보장하면서, 선택 참석자가 전원 불가여도 회의는 성립하게 하기 위함.

**STEP 2 — 점수 계산 (제외되지 않은 슬롯만)**
- 슬롯 점수 = 그 슬롯에 응답한 모든 참석자의 `IntensityScale.weight` 합.
- 부정 강도(필수 soft·선택 hard-no·선택 soft)는 음수 weight로 **감점**된다(STEP 1에서 제외되지 않았으므로 점수에는 남는다).
- 미응답은 점수에 0 기여(가산·감산 없음). 단 tie-break(STEP 3)에서 미응답 수를 본다.

**STEP 3 — 결정적 정렬 (점수 내림차순 + 고정 tie-break)**
- 1차 정렬: 슬롯 점수 **내림차순**.
- 동률이면 아래 **고정 우선순위로 순차 비교**(앞 기준에서 갈리면 멈춤):
  1. **필수(required) `prefer` 응답 수** 많은 슬롯 우선
  2. **미응답 인원 수** 적은 슬롯 우선
  3. **슬롯 시작시각** 빠른 슬롯 우선
  4. (그래도 동률이면) **슬롯 생성 순서(인덱스)** 빠른 슬롯 우선 ← *완전 결정성을 위한 최종 결정자(v1.1 추가)*
- 4단계까지 두면 어떤 입력에서도 순서가 유일하게 결정된다(무작위 0).

**STEP 4 — 표시**
- 제외된 슬롯(STEP 1)은 추천 리스트 본문에서 빼고, 하단 "필수 참석자가 불가한 시간" 접힘 영역에 **황토 배지**와 함께 사유 표기(거부·경고 톤 금지, conventions "회피는 거부가 아님").
- 점수·순위 배지는 추천 리스트에만 부여한다.

> **집계 막대 vs 추천 weight 분리** [Reviewer 보완 유지]: `IntensityDistributionBar`(집계 막대)는 "각 강도에 몇 명이 응답했는지" **건수 분포**를 그린다 — 색은 `polarity`, 정렬은 `order`로 그리며 `weight`를 막대 높이에 쓰지 않는다(hard의 제외 신호를 막대에 반영 금지). 추천 점수는 STEP 2의 `weight` 합산으로 계산한다. **둘은 다른 계산이다.**

> 상세 산정 규칙·의사코드는 feature-spec의 `F-WEB-DASH-002-002`에 명세한다.

### 0.4 ★ 추천 로직의 엣지케이스 — 단일 결과로 확정 (양다리 금지)

§0.3 규칙을 경계 조건에 적용한 결과를 미리 못박는다. 각 케이스는 *하나의 결과*만 가진다.

| 엣지케이스 | 입력 조건 | 확정된 처리(단일) | 표시 |
|-----------|----------|-----------------|------|
| **응답 0건** | 아무도 응답 안 함 | 추천 계산 안 함. 빈 상태. | "아직 응답이 없어요" + [링크 다시 공유] + 미응답 명단 (DASH-001 Empty) |
| **전원 불가(모든 슬롯 제외)** | 모든 후보 슬롯에 필수 hard-no 1건 이상 | 추천 리스트 비됨. 제외 사유 안내. | "필수 참석자가 모두 가능한 시간이 아직 없어요" + 제외 슬롯 목록(황토 배지) + [후보 시간 추가하기] 안내 (DASH-001 부분 빈 상태) |
| **필수 1명 hard-no** | 한 슬롯에 필수 중 정확히 1명이 hard-no | STEP 1대로 **그 슬롯만 제외**(다른 슬롯은 영향 없음). 부분 제외. | 해당 슬롯만 제외 영역으로, 나머지는 정상 추천 |
| **선택만 1명 응답** | 필수 전원 미응답 + 선택 1명만 응답 | 추천은 계산하되 *잠정*. "필수 응답 대기 중" 상태로 신뢰도 낮음 표시. 비공개 임계 발동(아래). | "필수 참석자 응답을 기다리는 중이에요. 현재 추천은 잠정값입니다" + DASH의 비공개 임계(F-DASH-003-003) 적용 |
| **선택 참석자가 그 슬롯에 1명뿐** | 집계가 곧 개인 식별 위험 | **개인 강도 비표시**, "선택 1명 응답"만(F-DASH-003-003 최소 익명성 임계). | 강도 분포 막대 대신 "선택 1명 응답" 텍스트 |
| **응답은 있으나 필수 응답 0** | 선택만 다수 응답, 필수 0 | 추천 *잠정* 표시 + "필수 참석자 응답 대기" 경고 배지. 확정은 막지 않되 경고. | DASH 상단 경고 배너 |
| **점수 전부 동률** | 모든 슬롯 점수 같음 | STEP 3 tie-break 1→2→3→4로 *유일* 정렬(절대 무작위 아님) | 정상 순위 |

> 위 표의 각 행은 "A 또는 B"가 없다. 모두 단일 결과다. 진짜 미결(임계 수치 등)은 §7 [확인 필요]로 분리했다.

## 1. IA (Information Architecture)

서비스는 **두 개의 독립 진입점**을 가진다. 계정·로그인 없음(PRD §4 In Scope, 외부 개방).

```
timefit-flowtime
│
├─ [주최자 동선] (모바일 우선 · PC 겸용)
│   SCR-WEB-ORG-001  조율 생성 (후보 슬롯·참석자·역할 설정)
│        └→ SCR-WEB-ORG-002  조율 링크 공유
│        └→ SCR-WEB-DASH-001 주최자 집계 대시보드 (추천 슬롯·미응답 현황)
│                 └→ SCR-WEB-DASH-002 슬롯 확정 (확정 모달/시트)
│                 └→ SCR-WEB-DASH-003 확정 완료
│
└─ [참석자 동선] (모바일 웹 전용 · 무가입)
    SCR-MOB-RESP-000  링크 진입 / 이름·역할 확인 (게이트)
        └→ SCR-MOB-RESP-001  슬롯 응답 (강도 입력 — 핵심)
              └→ SCR-MOB-RESP-001b  슬롯 코멘트(선택, FR-006)
        └→ SCR-MOB-RESP-002  응답 완료
```

> 플랫폼 표기: `MOB` = 모바일 웹(참석자), `WEB` = 웹(주최자, 모바일 우선·PC 겸용). 본 서비스는 네이티브 앱이 아니므로 AOS/iOS 구분 대신 **모바일 웹 / 데스크톱 웹** 반응형으로 다룬다(브레이크포인트 §6).

## 2. 참석자 동선 화면 기획

> 핵심 타겟: **우민지(P3 선택 참석자) — 솔직함 보호**. 부수 수혜: 박서준(P2 필수, 강도 표현·낮은 마찰).
> 각 화면의 상태 정의는 default / loading / error / empty / disabled / 성공 **6종을 모두** 기재하고, 해당 없는 상태는 "해당 없음(사유)"로 명시한다(강화 규칙 1).

### SCR-MOB-RESP-000 — 링크 진입 / 이름·역할 확인 (게이트)

- **화면 목적**: 무가입 참석자가 조율 링크로 들어와 자신을 식별하고, **자신의 역할(필수/선택)과 솔직함 보호 약속을 첫 화면에서 인지**한다.
- **진입 경로**: 외부 공유 링크(메신저/메일) → 모바일 브라우저
- **관련 화면**: → SCR-MOB-RESP-001(응답 시작) / 전이 규칙은 §5
- **화면 구성 요소**
  - 회의 제목 · 주최자명 · 후보 기간 요약
  - 이름 입력 필드(또는 주최자가 미리 넣은 명단에서 본인 선택)
  - **역할 배지**: "필수 참석자" / "선택 참석자" — 본인 역할을 명확히 표시
  - **★ 안심 메시지 (선택 참석자에게만 강조 노출)**: "당신이 안 돼도 회의는 진행됩니다. 솔직하게 답해도 괜찮아요." (FR-004 / 우민지 Pain Point 직접 해소)
  - **★ 비공개 고지 (선택 참석자)**: "당신의 응답은 다른 참석자에게 보이지 않아요." (NFR-002 비공개 체감)
  - [응답 시작] 버튼 — 하단 엄지 존(모바일 한 손 조작)
- **상태 정의 (6종 전수)**
  - **Default**: 회의 정보 + 이름 입력 + 역할/안심 메시지. [응답 시작] 활성.
  - **Loading**: 링크 검증 중 스켈레톤(제목·기간 자리 표시).
  - **Error**: ① 잘못된/만료 링크 → "이 링크는 더 이상 유효하지 않아요" + 주최자 문의 안내 ② 이미 마감된 조율 → "응답이 마감되었습니다" (둘 다 응답 진행 차단)
  - **Empty**: 후보 슬롯이 0개인 링크(주최자 미설정) → "아직 후보 시간이 등록되지 않았어요. 주최자에게 알려주세요." → 응답 진행 차단
  - **Disabled**: 이름 미입력/미선택 시 [응답 시작] 비활성(입력 유도 헬퍼 텍스트). 마감된 조율이면 [응답 시작] 영구 비활성.
  - **성공**: 별도 성공 화면 없음 — 이 화면의 "성공"은 [응답 시작] 탭으로 RESP-001 전이하는 것(전이가 성공 상태). **해당 없음(이 화면은 게이트라 자체 완료 상태가 없고, 다음 화면 진입이 성공에 해당)**.
- **핵심 인터랙션**: 역할이 "선택"이면 안심·비공개 메시지를 **시각적으로 더 강조**(색 블록/아이콘, 황토 계열 — 빨강 금지). "필수"면 강도 표현 안내 위주.

### SCR-MOB-RESP-001 — 슬롯 응답 (강도 입력) ★핵심 화면

- **화면 목적**: 각 후보 슬롯에 **선호 강도를 최소 탭으로 입력**. 응답 마찰 최소화(목표: 슬롯당 탭 1회).
- **진입 경로**: SCR-MOB-RESP-000 → [응답 시작] / 또는 RESP-002의 [응답 수정](마감 전)
- **관련 화면**: → SCR-MOB-RESP-001b(코멘트) / → SCR-MOB-RESP-002(완료) / 전이 §5
- **화면 구성 요소**
  - 상단: 진행 표시("3/8 슬롯 응답") — 30초 목표 관측 지점(0.2)
  - **슬롯 카드 리스트**(세로 스크롤): 각 카드 = 날짜·시간 + **강도 입력 컨트롤**
  - **강도 입력 컨트롤 = `IntensityChipGroup`**: `IntensityScale` 배열을 순회해 칩 렌더(3단계면 칩 3개, 4단계면 4개 — §0.1). 칩은 큰 탭 타깃(모바일). 선택 시 카드에 색·형태로 반영.
  - 코멘트 아이콘(FR-006, 선택): 탭 시 SCR-MOB-RESP-001b
  - 하단 고정 [응답 제출] 버튼(엄지 존) — 응답한 슬롯 수 실시간 표시
  - **★ 비공개 리마인더(선택 참석자)**: 화면 상·하단에 은은히 "이 응답은 비공개예요" 지속 노출(NFR-002)
- **상태 정의 (6종 전수)**
  - **Default**: 모든 슬롯 미선택(중립 표시). 강도 미선택은 "무응답"이며 거짓 응답을 강요하지 않는다.
  - **Loading**: 슬롯 목록 로딩 스켈레톤 카드.
  - **Error**: 제출 실패(mock에선 드묾) → 인라인 토스트 "잠시 후 다시 시도해 주세요", **입력값 유지**(데이터 소실 금지).
  - **Empty**: 후보 슬롯 0개 → **해당 없음(RESP-000 게이트의 Empty에서 이미 차단되어 이 화면에는 진입하지 못함)**. 방어적으로 진입 시 RESP-000으로 되돌림.
  - **Disabled**: 응답한 슬롯이 0개일 때 [응답 제출]은 비활성이 아니라 "한 슬롯도 선택 안 하고 제출" 확인으로 처리(무응답 제출 허용 — 강요 금지). 따라서 제출 버튼 disabled는 **해당 없음(거짓 응답 강요 방지를 위해 무응답 제출도 허용)**. 마감 후 진입 시 전체 입력 disabled + 안내.
  - **부분 응답(성공 직전) 상태**: 일부 슬롯만 선택하고 제출 시도 → "응답하지 않은 슬롯이 있어요. 그대로 제출할까요?"(강요 아님, 부정 뉘앙스 금지 — PRD §8.2)
  - **성공**: [응답 제출] 후 RESP-002로 전이(전송 성공). 자체 inline 성공 표시는 없고 완료 화면이 성공 상태를 담당.
- **핵심 인터랙션**
  - 강도 칩 탭 = 즉시 선택 반영(저장은 제출 시 또는 자동 임시저장). 같은 칩 재탭 = 선택 해제(무응답 복귀).
  - **부정 강도(avoid/hard-no) 선택 시 경고·죄책감 유발 금지**(PRD §8.2, conventions "회피는 거부가 아님", 우민지 보호) — 빨강 경고색·"정말요?" 확인 다이얼로그 금지. **황토 계열 중립 색/형태로만** 반영.
  - 강도 칩은 색만이 아니라 **형태·라벨**로도 구분(WCAG, §0.1의 `shape`).

### SCR-MOB-RESP-001b — 슬롯 코멘트 (FR-006, 선택)

  - **Empty**: 코멘트 미입력 상태가 곧 Empty(placeholder "사정을 짧게 남겨도 돼요").
  - **Disabled**: 빈 입력일 때 [저장] 비활성.
  - **성공**: [저장] 시 슬롯 카드에 코멘트 아이콘 활성 + RESP-001 복귀.
- **비공개 일관성**: 선택 참석자의 코멘트도 다른 참석자에게 비공개(주최자는 집계/익명 맥락으로만, §3·§7 협의 항목).

### SCR-MOB-RESP-002 — 응답 완료

## 3. 주최자 동선 화면 기획

> 타겟: **김도현(P1 주최자)** — 필수 인원 기준 빠른 확정, 강도·역할 한 화면 가시화, 미응답 추적.

### SCR-WEB-ORG-001 — 조율 생성

- **화면 목적**: 후보 슬롯·참석자·역할을 설정해 조율을 만든다.
- **진입**: 서비스 첫 진입(주최자)
- **관련 화면**: → SCR-WEB-ORG-002(링크 공유) / 전이 §5
- **구성 요소**
  - 회의 제목
  - **후보 슬롯 추가**(날짜·시간 멀티 선택)
  - **참석자 입력 + 역할 지정**: 참석자별 **필수/선택 토글**(FR-002, PRD §10 — 주최자 지정 방식 채택)
  - (선택) **강도 단계 수 설정 [확인 필요·데모 기본 4단계]**: 데모에선 고정 노출 가능. 단계 수는 `IntensityScale` 데이터로 주입되므로 향후 3단계 전환 시 화면 불변(§0.1).
  - [조율 만들기] 버튼
- **상태 정의 (6종 전수)**
  - **Default**: 빈 폼 또는 작성 중 폼.
  - **Loading**: 생성 처리 중(mock 짧음) — [조율 만들기] 스피너.
  - **Error**: 생성 실패(mock 드묾) → "조율을 만들지 못했어요. 다시 시도해 주세요", 입력값 보존.
  - **Empty**: 신규 진입 = 빈 폼 + "후보 시간을 추가해 주세요" 안내.
  - **Disabled**: 슬롯 0개 또는 참석자 0명이면 [조율 만들기] 비활성 + 사유 안내.
  - **성공**: 생성 완료 → ORG-002 링크 공유로 전이.
- **인터랙션**: 필수/선택 토글 즉시 반영. 필수 0명 경고("필수 인원이 없으면 모든 응답이 동등 취급돼요" — 추천 로직 의미 안내, 강요 아님). 경고지 차단 아님.

### SCR-WEB-ORG-002 — 조율 링크 공유

- **목적**: 생성된 조율 링크를 복사/공유.
- **진입**: ORG-001 성공 / 전이 §5
- **구성**: 링크 + [복사] + 공유 안내("이 링크를 받은 사람은 가입 없이 응답해요") + → [대시보드 보기].
- **상태 정의 (6종 전수)**
  - **Default**: 링크 + 복사 버튼.
  - **Loading**: **해당 없음(링크는 ORG-001에서 이미 생성됨, 추가 로딩 없음)**.
  - **Error**: 복사 실패(브라우저 권한) → "복사하지 못했어요. 길게 눌러 직접 복사해 주세요" 폴백.
  - **Empty**: **해당 없음(링크가 항상 존재하는 상태로만 진입)**.
  - **Disabled**: **해당 없음(모든 액션 상시 가능)**.
  - **성공**: [복사] 시 "복사됨" 토스트.

### SCR-WEB-DASH-001 — 주최자 집계 대시보드 ★핵심 화면 (FR-003·FR-005)

- **화면 목적**: 강도·역할이 반영된 **추천 슬롯 정렬**과 **미응답 현황**을 한 화면에서 보고 의사결정. 6~12명에서도 가독성 유지(NFR-003).
- **진입**: SCR-WEB-ORG-002 / 저장된 대시보드 링크 / 전이 §5
- **관련 화면**: → SCR-WEB-DASH-002(확정)
- **구성 요소**
  - 상단 요약: 응답 N/전체, 미응답 인원 수, 마감까지
  - **추천 슬롯 리스트(점수 내림차순, deterministic §0.3 STEP3)**: 슬롯별
    - 슬롯 점수 / 추천 순위 배지
    - **강도 분포 막대 = `IntensityDistributionBar`**: `IntensityScale` 순회 stacked bar(§0.1 규칙2 — 단계 수 종속 금지). 필수/선택을 구분해 두 줄 또는 그룹 표시(NFR-003).
    - **필수 인원 충족 표시**: "필수 5/5 가능" 같은 hard 제약 결과(§0.3 STEP1).
    - 미응답 영향 표시
  - **제외 슬롯 접힘 영역**(§0.3 STEP4): "필수 참석자가 불가한 시간" — 황토 배지, 거부 톤 금지.
  - **범례**: `IntensityScale`에서 자동 생성(§0.1 규칙3)
  - **★ 비공개 경계 명시**: 선택 참석자 데이터는 **개인 단위가 아니라 집계로만** 표시(PRD §10 — "집계만 노출" 채택, 우민지 보호 유지). "선택 참석자 응답은 집계로만 표시됩니다" 고지.
  - 미응답자 리마인더 영역(FR-005, mock 상태 표시 — Should): "리마인드 보냄(데모)" 상태 배지.
- **상태 정의 (6종 전수)**
  - **Default**: 응답 일부/전체 수집, 추천 정렬 표시.
  - **Loading**: 집계 계산 스켈레톤.
  - **Error**: mock 범위 — 데이터 로드 실패 시 "현황을 불러오지 못했어요" + 재시도.
  - **Empty(응답 0건)**: "아직 응답이 없어요. 링크를 공유해 보세요." + [링크 다시 공유] + 미응답 명단. (추천 슬롯 영역은 "응답이 모이면 추천이 표시돼요" placeholder — 강도 단계 수 무관 동작) 〔§0.4 응답 0건〕
  - **부분 빈 상태(필수 미응답)**: 선택만 응답·필수 0 → 추천 *잠정* 표시 + "필수 참석자 응답 대기 중" 경고 배너 〔§0.4 선택만 응답〕
  - **전원 불가 상태**: 모든 슬롯이 필수 hard-no로 제외 → "필수 참석자가 모두 가능한 시간이 아직 없어요" + 제외 슬롯 목록 + [후보 시간 추가하기] 안내 〔§0.4 전원 불가〕
  - **Disabled**: 이미 응답한 참석자의 [리마인드] 비활성. 확정 완료(마감) 후 진입 시 [확정] 류 액션 disabled + 확정 결과 표시.
  - **성공**: 슬롯 [이 시간으로 확정] → DASH-002 전이.
- **핵심 인터랙션**
  - 슬롯 탭 → 상세(강도 분포·필수 충족·코멘트 집계). 선택 참석자 개인 식별 불가(비공개 일관).
  - 정렬 토글(추천순/시간순) — 기본은 deterministic 추천순. 정렬 바꿔도 추천 점수 계산은 불변.
  - 미응답자 [리마인드](mock: 상태만 변경, 실발송 없음 — PRD Out of Scope).
  - **PC 겸용**: 데스크톱에선 슬롯을 표(행=슬롯, 열=강도 분포·필수 충족)로 밀도 높게, 모바일에선 카드 리스트로(반응형 §6).

### SCR-WEB-DASH-002 — 슬롯 확정 (확정 시트/모달)

- **목적**: 추천 슬롯 중 하나를 최종 확정.
- **진입**: 대시보드 슬롯의 [이 시간으로 확정] / 전이 §5
- **구성**: 확정 대상 슬롯 요약 + 필수 인원 충족 재확인 + (필수 hard-no/미충족 시) 경고 + [확정] / [취소].
- **상태 정의 (6종 전수)**
  - **Default**: 확정 대상 요약 + [확정]/[취소].
  - **Loading**: 확정 처리 중(mock 짧음).
  - **Error**: 확정 실패 → "확정하지 못했어요. 다시 시도해 주세요", 시트 유지.
  - **Empty**: **해당 없음(확정 대상 슬롯이 반드시 전달되어 진입)**.
  - **Disabled**: 처리 중 [확정] 중복 클릭 방지로 일시 비활성.
  - **성공**: 확정 완료 → DASH-003 전이 + 응답 마감 처리.
- **인터랙션**: 필수 인원 미충족 슬롯 확정 시 **경고 후 진행 허용**(주최자 권한 — 강제 차단 아님). 확정 후 응답 마감 처리.

### SCR-WEB-DASH-003 — 확정 완료

- **목적**: 확정 결과 안내 + 공유.
- **진입**: DASH-002 성공 / 전이 §5
- **구성**: 확정 시간 + 참석자에게 공유할 안내 문구 + [결과 공유 링크 복사].
- **상태 정의 (6종 전수)**
  - **Default / 성공**: 확정 시간 표시(이 화면 default가 곧 성공 상태).
  - **Loading**: **해당 없음(확정은 DASH-002에서 끝남)**.
  - **Error**: 공유 링크 복사 실패 → 폴백 안내.
  - **Empty**: **해당 없음(확정 결과 화면)**.
  - **Disabled**: **해당 없음**.
- **인터랙션**: [결과 공유 링크 복사] → "복사됨" 토스트.

## 5. ★ 화면 전이 규칙 (강화 규칙 4 — 트리거·조건·뒤로가기 정본)

각 전이의 **트리거 / 진입 조건 / 뒤로가기 동작**을 못박는다. 플로우가 끊기지 않게 한다.

### 5.1 참석자 동선 (모바일 웹)

| From → To | 트리거 | 진입 조건 | 뒤로가기 동작 |
|-----------|--------|----------|--------------|
| (외부) → RESP-000 | 링크 클릭 | 링크 유효(mock) | 브라우저 이탈 |
| RESP-000 → RESP-001 | [응답 시작] 탭 | 이름 입력/선택 완료 + 슬롯 ≥1 + 미마감 | (브라우저 백) → RESP-000, 이름 입력값 유지 |
| RESP-001 → RESP-001b | 슬롯 코멘트 아이콘 탭 | 항상 | [취소]/백 → RESP-001, 코멘트 미저장 폐기 확인 |
| RESP-001b → RESP-001 | [저장] 또는 [취소] | — | (위와 동일) |
| RESP-001 → RESP-002 | [응답 제출] 탭 | 제출 성공(부분 응답이면 확인 시트 통과) | (브라우저 백) → RESP-001, **입력값 복원**(소실 금지) |

- **공통**: 무가입이라 로그인 세션 없음. 링크가 접근 키. 만료/마감은 어느 화면에서든 Error/Disabled로 가드.

### 5.2 주최자 동선 (모바일 우선·PC 겸용)

| From → To | 트리거 | 진입 조건 | 뒤로가기 동작 |
|-----------|--------|----------|--------------|
| (첫 진입) → ORG-001 | 서비스 진입 | — | 브라우저 이탈 |

| DASH-003 → (종료/공유) | [결과 공유 링크 복사] | — | 백 → DASH-001(읽기전용·확정 표시) |

- **브라우저 뒤로가기**: 대시보드 계열은 직전 화면으로, 단 확정 후 마감 상태는 보존.

## 6. 반응형 / 플랫폼 예외 (모바일 우선)

- **브레이크포인트**: Mobile(< 768px) 기준 설계 → Tablet(768~1024) → Desktop(≥ 1024) 확장.
- **참석자 동선(RESP-\*)**: **모바일 웹 전용 설계.** 데스크톱에서도 동작하되 중앙 정렬 모바일 폭 유지(한 손 조작·이동 중 사용 가정 — persona 박서준/우민지 사용 환경).
- **주최자 동선(DASH-\*)**: 모바일 우선. **PC 겸용** — 데스크톱에선 6~12명 밀도를 표(테이블) 레이아웃으로, 모바일에선 카드 리스트로(NFR-003 가독성). 강도 분포·필수 충족은 두 레이아웃 모두에서 `IntensityScale` 기반으로 동일 렌더.
- **브라우저 뒤로가기**: §5 전이 표의 뒤로가기 열을 정본으로 따른다. 응답 중 뒤로가기 → 입력값 임시 보존(데이터 소실 방지).
- **세션**: 무가입이므로 로그인 세션 없음. 링크 자체가 접근 키(mock). 만료/마감은 링크 상태로 처리.
- **오프라인**: mock 데이터라 네트워크 의존 낮음. 제출 실패 시 입력값 보존 + 재시도(RESP-001/002 Error 상태).
- **[확인 필요]**: 데모에서 다크모드 지원 여부, 한국어 외 다국어 — 디자이너 단계 협의.

## 7. [확인 필요] 항목 (진짜 미결만 — 디자이너·UX라이터·Engineer로 전달)

> 아래는 *양다리를 남긴 것이 아니라*, 현 단계에서 결정 근거가 부족해 다음 단계 협의가 필요한 **진짜 미결**이다. 추천 로직(§0.3)·엣지케이스(§0.4)는 모두 단일 확정했으므로 여기 없다.

- **[확인 필요] 미결: 강도 단계 수 데모 기본값을 4단계로 확정할지** — 4단계 제안. `IntensityScale` 주입 구조라 3단계 전환 시 화면 불변(§0.1). 사용성 테스트 후 확정(PRD §10). soft/hard 2축은 decisions로 이미 고정.
- **[확인 필요] 미결: 선택 참석자 최소 익명성 임계값** — 한 슬롯에 선택 응답이 몇 명 이하일 때 강도를 가리고 "선택 N명 응답"만 표시할지. *1명일 때 강도 비표시*를 제안(§0.4)하나, 2명·3명 임계는 디자이너·UX라이터 협의 필요.
- **[확인 필요] 미결: 선택 참석자 코멘트의 주최자 노출 범위** — 집계/익명 맥락으로만 제안(우민지 비공개 일관). 디자이너·UX라이터 확정.
- **[확인 필요] 미결: 추천 tie-break STEP3의 1·2 우선순위 순서** — "필수 prefer 수 → 미응답 적은 순 → 시작시각 → 생성순"을 제안. STEP4(생성순)는 완전 결정성 보장 최종자라 고정이나, 1·2의 상대 우선은 Engineer·주최자 관점에서 재확인 가능. *단 어떤 순서로 확정하든 단일 순서여야 함(양다리 금지)*.
- **[확인 필요] 미결: 전원 불가 시 주최자 재편집 동선** — DASH-001에서 [후보 시간 추가하기]로 ORG-001류 편집으로 돌아갈지, 새 조율을 만들지. 데모 범위 협의.
- **[확인 필요] 미결: 확정 후 재오픈/재확정 허용 여부** — 데모는 비가역(§5.2)으로 단순화. 실제 운영 시 재확정 정책은 후속.
- **[확인 필요] 미결: 강도 칩 색·형태 토큰 구체값** — `polarity` 기반, 부정 강도는 **황토(`#B5852A`)**, 빨강 배제(conventions·NFR-005). 채도 빼기 + 형태/라벨 병기. 디자이너 확정.
- **[확인 필요] 미결: 미응답 리마인더 mock 표현 한도** — 상태 배지로만(실발송 Out of Scope). Engineer 협의.
