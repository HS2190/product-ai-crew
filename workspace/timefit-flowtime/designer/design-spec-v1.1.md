## 0. 적용한 디자인 스킬 — minimalist-ui (왜 골랐나)

### 0.1 스킬 선택 근거 (라벨 동어반복 아님 — 기획의 구체적 특징과 연결)

- **주최자 대시보드는 6~12명 강도·역할 집계를 한 화면에 얹어야 한다**(NFR-003). 정보 위계가 성패를 가르는 화면이다. 장식·그림자·컬러 블록이 들어오면 강도 분포 막대와 추천 순위라는 핵심 신호가 묻힌다. → 색을 *의미에만* 쓰고 구조는 1px 라인과 여백으로 가르는 minimalist-ui의 에디토리얼 위계가 정확히 맞는다.
- **브랜드 인상은 "효율"이 아니라 "안심과 배려"**(PRD §8.1). 채도 높은 SaaS 톤·경고색은 오히려 압박을 준다. minimalist-ui의 웜 모노크롬 + 극히 절제된 파스텔은 "차분·신뢰"(§8.2 시각 인상)를 코드 없이 만든다.
- **"회피는 거부가 아님"**(conventions)을 시각으로 옮기려면 부정 강도가 *경고처럼 보이지 않아야* 한다. minimalist-ui는 큰 컬러 배경·붉은 강조를 금지하므로, 부정 강도를 황토 라인/저채도 칩으로 조용히 처리하기에 구조적으로 부합한다.
- **대안 비교**: `high-end-visual-design`은 "비싼" 에이전시 감도라 랜딩엔 좋지만 데이터 집계 화면에 과장 위험(브랜드가 효율보다 배려인데 화려함이 역효과). `industrial-brutalist-ui`는 데이터 밀도엔 강하나 raw·기계적 톤이 "안심·배려"와 정면 충돌. → minimalist-ui 1순위.

### 0.2 override (conventions 강제) — minimalist-ui 위에 얹는 1건

minimalist-ui 팔레트의 **Pale Red(`#FDEBEC`/`#9F2F2D`)는 사용하지 않는다.** flowtime conventions가 빨강을 팔레트에서 배제하므로, **부정 강도·에러·경고는 황토(`#B5852A`) 계열**로 대체한다. 나머지 minimalist 원칙(웜 모노크롬, 무거운 그림자 금지, 1px 라인, 플랫, 타이포 위계, bento 구조)은 그대로 적용한다.

### 0.3 minimalist-ui를 어디에 적용했나 (구체)

| minimalist 원칙 | 이 제품에서의 구체 적용 |
|----------------|----------------------|
| 색 = 희소 자원, 의미에만 | 캔버스·카드·텍스트는 전부 웜 모노크롬. 색은 **강도(`prefer` 세이지 / 부정 황토)**, **역할 배지**, **추천 1순위**에만 쓴다. 그 외 UI는 무채색. |
| 무거운 그림자 금지 | `shadow-md/lg` 전면 금지. 카드 구분은 `1px solid #EAEAEA`. hover만 `0 2px 8px rgba(0,0,0,0.04)` 초저강도. (component-spec elevation 토큰) |
| 1px 라인 구조 | 슬롯 카드·대시보드 표·제외 영역·아코디언 전부 컬러 박스 대신 1px 디바이더로 분절. |
| 타이포 위계 | 회의 제목·완료 카피는 에디토리얼 세리프(Newsreader), 본문·UI는 지오메트릭 산세리프, 슬롯 시각·점수·"N/전체"는 모노스페이스(tabular). |
| 플랫·bento | 대시보드 상단 요약을 비대칭 bento 3칸(응답률 / 미응답 / 마감)으로. 둥근 모서리 8~12px crisp, pill은 배지에만. |
| 파스텔 절제 | 역할 배지·`prefer` 칩만 저채도 파스텔(세이지·뮤트블루). 부정은 파스텔 대신 황토 라인. |

> Figma 산출 시 "오토레이아웃·컴포넌트/Variant·시멘틱 네이밍·토큰화·반응형 제약 적용"은 §9 자기보고 및 component-spec의 각 컴포넌트 Figma 노트에 명시한다.

### 1.2 색 — Semantic (의미 토큰, IntensityScale 매핑)

강도 색은 데이터로 주입된다. 4단계 데모 매핑(3단계 전환 시 배열만 교체):

| `id` | `polarity` | `softHard` | 배경 토큰 | 라벨·아이콘 전경(fg) | 테두리(border) | `shape`(색 외 단서) |
|------|-----------|-----------|----------|--------------------|----------------|--------------------|
| `prefer` | + | soft | `--c-sage-bg` | `--c-sage` (5.56:1) | — | 채운 원 ● |
| `ok` | 0 | soft | `--c-neutral-ok-bg` | `--c-neutral-ok` (4.59:1) | — | 빈 원 ○ |
| `avoid` | − | soft | `--c-clay-bg` | `--c-clay-ink` (5.39:1) | `--c-clay-line`(연함) | 사선 빗금 ◐ (해치) |
| `hard-no` | − | **hard** | `--c-clay-bg` | `--c-clay-ink` (5.39:1) | `--c-clay`(진함) | 빗금 + 짧은 슬래시 ⊘ (가장 강한 형태 단서) |

- **라벨 가독성과 soft/hard 구분을 다른 채널로 분리**(Reviewer A2): avoid·hard-no **둘 다 라벨·아이콘 전경은 `--c-clay-ink`(5.39:1, AA)**로 통일해 저시력 사용자도 라벨을 읽을 수 있게 한다. soft/hard 구분은 fg 명도가 아니라 **① 형태(◐ vs ⊘) + ② 테두리 채도(`--c-clay-line` 연함 vs `--c-clay` 진함)**로 옮긴다. → 라벨 가독성과 강도 구분이 같은 토큰에서 충돌하지 않는다.
- `--c-clay`(2.8:1)는 **라인·아이콘 채움·hard-no 테두리**에만 쓰고 라벨 텍스트로는 쓰지 않는다. 테두리는 비텍스트 그래픽(WCAG 1.4.11 ≥3:1 대상이나, 강도는 형태+라벨로 1차 식별되어 테두리는 보조 단서)이다.
- 의미 토큰: `--intensity-{id}-bg`, `--intensity-{id}-fg`(=`--c-clay-ink` for avoid/hard-no), `--intensity-{id}-border`, `--intensity-{id}-shape`.

### 1.6 모션

- 스크롤 진입: `translateY(12px)+opacity0 → 600ms cubic-bezier(0.16,1,0.3,1)`. IntersectionObserver.
- 칩 선택: `transform: scale(0.97)` active, 색 전이 160ms. **레이아웃 속성 애니메이션 금지**(transform/opacity만).
- 리스트 stagger: `delay = index*80ms`.
- 부정 강도 선택에 **흔들림·경고 모션 절대 금지**(conventions). 긍정과 동일한 차분한 전이.
- 모션 민감 사용자: `prefers-reduced-motion` 시 진입 애니메이션 제거, 즉시 표시.

### 2.2 레드라인

- 상단 바: 고정(sticky top), 높이 56, 하단 1px `--c-line`. 진행 텍스트 우측 정렬, mono tabular.
- 비공개 리마인더: 선택 참석자만. 높이 hug, pad `--space-3`, 배경 `--c-surface-2`, **황토·빨강 아님 — 중립**(고지지 경고 아님).
- 슬롯 카드: 폭 fill(좌우 `--space-4` 마진), 카드 간 gap `--space-3`, radius `--radius-card`, border 1px `--c-line`, 그림자 없음.
- 칩: 한 행, gap `--space-2`, 각 칩 height 44, hug 내용+pad `--space-3`. 칩 그룹은 가로 fill 균등 분배(4개면 4등분, 3개면 3등분 — N 종속 금지).
- 하단 CTA: fixed bottom, pad `--space-4`, 버튼 height 52, radius `--radius-btn`, 배경 `--c-ink`, 텍스트 `--c-white`.

### 2.3 상태 (6종)

| 상태 | 표현 |
|------|------|
| Default | 모든 슬롯 미선택(칩 무채 아웃라인). "무응답"이 정상. |

| 성공 | 제출 → RESP-002 전이. |

### 2.4 인터랙션·상태 전이 (★ 명시)

- **강도 칩 탭 = 즉시 반영**. 같은 칩 재탭 = 선택 해제(무응답 복귀). → component-spec `IntensityChip` 상태 머신.
- **강도 칩 순환은 강제하지 않는다**: 칩은 단일 선택 라디오. 탭한 칩이 선택, 재탭으로 해제. ("prefer→ok→avoid→hard-no 순환"식 단일 토글이 아니라, 4칩 중 1택 + 해제 모델 — 모바일에서 한 칩 한 탭이 가장 적은 동작.)
- **부정 강도(`avoid`/`hard-no`) 선택 시**: 황토 칩으로 *조용히* 반영. **확인 다이얼로그·흔들림·"정말요?"·죄책감 카피 절대 금지**(conventions, 우민지 보호). 긍정 선택과 동일한 전이 곡선.
- 코멘트 링크 탭 → RESP-001b 시트 슬라이드업. 저장 시 카드에 코멘트 칩 활성.
- 일부만 응답 후 [응답 제출] → `ConfirmSheet` "응답하지 않은 슬롯이 있어요. 그대로 제출할까요?"(중립, [그대로 제출]/[더 채우기]). 무응답 전체 제출도 동일 확인 1회 후 허용.
- 브라우저 뒤로가기 → 입력값 임시 보존(소실 금지, screen-plan §5.1).

### 3.4 인터랙션·상태 전이 (★ 명시)

- 슬롯 탭/행 클릭 → 상세(강도 분포·필수 충족·코멘트 집계). **선택 참석자 개인 식별 불가**(비공개 일관).
- 정렬 토글(추천순↔시간순): 표시 순서만 바뀌고 **추천 점수 계산은 불변**(deterministic). 토글은 segmented, 기본 추천순.
- **제외 슬롯 vs 감점 후보의 시각 위계 구분**(decisions): 제외 슬롯은 *본문 밖* 접힘 영역 + 황토 [제외] 배지. 감점된(부정 강도 섞인) 후보는 본문 안에 머물되 점수·분포막대로만 낮게 표시 — 배지 없음. → 제외(자격 박탈)와 감점(점수 낮음)이 한눈에 다른 층위로 보인다.
- 제외 영역은 기본 접힘. 펼침 = 아코디언(컬러 박스 없이 1px line, `+`/`−` 아이콘).
- [리마인드](mock): 탭 → 즉시 "리마인드 보냄(데모)" 배지로 상태 변경, 실발송 없음. 이미 응답자 비활성.
- 확정 슬롯 탭 → ConfirmSheet(모바일)/모달(데스크톱). 필수 미충족·제외 슬롯이면 **경고 후 진행 허용**(차단 아님, 주최자 권한).

### 3.5 강도 분포 막대 ≠ 추천 weight (분리 — screen-plan §0.3)

`IntensityDistributionBar`는 **건수 분포**다: 각 강도에 몇 명이 응답했는지를 `order`로 정렬·`polarity`로 색칠한 stacked segment. `weight`(추천 점수용)를 막대 높이/폭에 반영하지 않는다. 추천 점수 +9는 카드의 **점수 배지**가 담당한다. 둘은 다른 시각 요소다(막대=분포, 배지=점수).

## 5. 반응형 / 접근성 / 다크모드

### 5.1 반응형
- 브레이크포인트: Mobile <768 / Tablet 768–1023 / Desktop ≥1024.
- 참석자(RESP-*): 모바일 전용 설계. 데스크톱에서도 420px 중앙 정렬 유지.
- 주최자(DASH-*): 모바일 카드 ↔ 데스크톱 표. 강도 분포·필수 충족은 두 레이아웃 모두 `IntensityScale` 기반 동일 렌더.

### 5.2 접근성 (WCAG)
- **강도 = 색 단독 금지**: 모든 강도는 `shape`(●/○/◐/⊘) + `label` 병기. 색약 사용자도 형태·라벨로 구분.

#### 대비 실측 표 (단정 문장 → 측정값으로 교체, Reviewer A1)

모든 칩 라벨·본문 텍스트 전경/배경 쌍을 실측했다. 일반 텍스트 AA 기준은 ≥4.5:1, 비활성 텍스트는 WCAG 1.4.3에서 면제.

| 쌍(전경 on 배경) | hex | 대비 | 판정 |
|------------------|-----|------|------|
| 본문 `--c-ink` on `--c-bone` | `#1F2421` / `#F7F6F3` | **14.58:1** | AAA ✅ |
| `prefer` 라벨 `--c-sage` on `--c-sage-bg` | `#496447` / `#E7EEE6` | **5.56:1** | AA ✅ (v1.0 `#5E7A5C`=4.03 미달 → 다운) |
| `ok` 라벨 `--c-neutral-ok` on `--c-neutral-ok-bg` | `#676B65` / `#ECECEA` | **4.59:1** | AA ✅ (v1.0 `#8A8F88`=2.79 미달 → 다운) |
| `avoid`·`hard-no` 라벨 `--c-clay-ink` on `--c-clay-bg` | `#7A5A16` / `#F3ECD9` | **5.39:1** | AA ✅ (v1.0 avoid가 `--c-clay`=2.8 미달이던 것을 `--c-clay-ink`로 교체) |
| 필수 역할 배지 `--c-role-required` on `--c-role-required-bg` | `#2F5D6E` / `#E2EDF1` | **6.05:1** | AA ✅ |
| 제외 배지 텍스트 `--c-clay-ink` on `--c-clay-bg` | `#7A5A16` / `#F3ECD9` | **5.39:1** | AA ✅ |
| 비활성 `--c-ink-faint` on `--c-surface-2` | `#9A9E98` / `#F9F9F8` | 2.58:1 | **면제** (WCAG 1.4.3 — 비활성 컨트롤 텍스트는 대비 요건 제외. disabled 상태에만 사용, 활성 라벨엔 미사용) |

- **수정 요지**: v1.0에서 ok·avoid·prefer 라벨 전경이 실측 AA 미달이었다(2.79 / 2.8 / 4.03). 형태·라벨 단서는 1차 방어선이나 라벨 텍스트 자체가 AA를 못 넘기면 저시력 사용자에게 라벨이 안 읽히므로, 세 전경 토큰을 한 단계 어둡게 재정의해 **모두 ≥4.5:1 실측 통과**로 맞췄다. `--c-clay`(2.8)는 라벨에서 빼고 라인/아이콘/테두리 전용으로 강등했다.
- 비텍스트 그래픽(칩 테두리·분포막대 세그먼트)은 WCAG 1.4.11(≥3:1) 대상이나, 강도는 형태+라벨로 1차 식별되므로 테두리·채도는 보조 단서다. hard-no 테두리 `--c-clay`(2.8:1)는 형태(⊘)+라벨이 식별을 담당해 단독 의존하지 않는다.
- 탭 타깃 ≥ 44×44px(칩·버튼·토글).
- aria: 칩 그룹 `role="radiogroup"`, 칩 `role="radio" aria-checked`, `aria-label`=IntensityScale.ariaLabel(예 "가급적 회피, 부정, 부드러운 강도"). 분포막대 `role="img" aria-label`로 "필수 선호 3명, 가능 2명…" 요약 제공.
- `prefers-reduced-motion` 존중.

### 5.3 다크모드 [확인 필요]
- 데모 범위에서 다크모드는 **미지원**(라이트 단일)을 제안. 토큰 구조는 시멘틱이라 후속 다크 추가 가능. (screen-plan §6 미결 → 디자이너 의견: 데모는 라이트 고정.)

## 6. open questions (디자이너 의견 첨부 — 단정 아닌 가설)

- 최소 익명성 임계: 1명일 때 강도 비표시는 확정. **2명 임계도 권장**(가설: 2명이면 한 명이 다른 한 명 강도 역추론 가능). 사용성 테스트로 검증 후 확정.
- 강도 4→3단계 전환 시 칩 균등 분배가 3칩에서 너무 넓어 보일 수 있음 → 3단계면 칩 max-width 캡 두는 안 검토(가설).
- 부정 강도 황토가 `prefer` 세이지와 함께 있을 때 색약 시뮬레이션 1회 더 검증 필요(형태 단서가 1차 방어선이라 통과 예상이나 확인).

## 8. Figma 반영 상태 (정직 보고)

이번 세션에서 **Figma 쓰기 도구(use_figma / generate_figma_design / get_screenshot 등)가 이 에이전트 컨텍스트에 노출되지 않았다.** figma MCP 서버는 CLI 레벨에서 "connected"이나, 도구가 호출 가능한 상태로 로드되지 않아(ToolSearch·ReadMcpResourceTool 모두 접근 불가) 실제 프레임을 그릴 수 없었다.

- 따라서 이 마크다운 스펙(design-spec + component-spec)을 **정본**으로 완성했다. (정본은 언제나 마크다운 — 디자이너 가이드 §아웃풋)
- Figma는 **미산출(blocked 아님, 부분 완료)**. 도구가 연결되면 §9의 Figma 제작 표준 매핑(component-spec의 각 컴포넌트 Figma 노트 + 본 문서 토큰 = Variables)대로 page `0:1` 아래 새 프레임으로 바로 옮길 수 있도록 모든 시멘틱 네이밍·Variant·토큰을 스펙에 미리 명시해 두었다.
- 대상: fileKey `VWfy2l2HcftyFEpwFbrmAj`, page `0:1`. 어제 캡처(5-2/6-2)는 무시.

## 9. Figma 제작 표준 매핑 (도구 연결 시 그대로 적용)

도구가 열리면 아래대로 그린다(스펙에 선반영 완료):

1. **오토레이아웃**: 모든 프레임 Auto Layout. 슬롯 리스트=세로 gap 12, 칩 그룹=가로 gap 8 fill 균등, 대시보드 표=세로 행 stack. padding=토큰.
2. **컴포넌트 조립**: component-spec의 컴포넌트와 1:1. 반복 요소(슬롯 카드·칩·배지·분포막대)는 Component+인스턴스.
3. **Variant**: `chip/intensity`(prefer/ok/avoid/hard-no + selected/unselected), `badge/role`(required/optional), `badge/status`(rank-1/excluded/reminder-sent), `btn`(primary/secondary/ghost × default/hover/active/disabled).
4. **시멘틱 네이밍**: `chip/intensity/avoid`, `card/slot/recommended`, `bar/distribution`, `badge/excluded`, `section/excluded`, `bento/summary`, `btn/primary`. 자동이름 금지.
5. **Variables(토큰)**: §1 토큰 전부 Figma Variables로. 색=`color/intensity/avoid` 등, 간격=`space/4`, 라운드=`radius/card`, 타이포=Text Styles. design-spec 토큰명과 일치.
6. **반응형 제약**: 슬롯 카드 width=fill, 칩=fill 균등, 상단바=fill+fixed height, CTA=fill bottom-anchored. 대시보드 표 열=일부 fixed(순위·점수) 일부 fill(분포막대).
