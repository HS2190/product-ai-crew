## 0. 디자인 원칙 (이 제품의 시각 언어)

PRD §8을 디자인 결정으로 번역한 5개 원칙. 모든 컴포넌트·화면은 이 원칙으로 검증한다.

1. **안심이 먼저(Reassurance-first)** — 압박·독촉·죄책감을 주는 시각 신호를 쓰지 않는다. 부정 응답(avoid/hard-no)에 빨강 경고·진동·확인 다이얼로그·느낌표를 붙이지 않는다. "회피는 거부가 아니다."
2. **비공개를 보이게(Visible privacy)** — 선택 참석자에게 "내 응답이 안 보인다"는 사실을 *지속적으로* 시각화한다. 1회 고지가 아니라 화면에 상주하는 은은한 단서로 체감시킨다(NFR-002).
3. **강도는 데이터, 색은 주입(Scale as data)** — 강도 척도는 3↔4단계 가변. UI는 `IntensityScale` 배열을 순회해 렌더하고, 색·형태·라벨을 하드코딩하지 않는다(screen-plan §0.1).
4. **색 없이도 읽힌다(Color-independent)** — 모든 강도·상태는 색 외에 형태(shape)·라벨·아이콘으로 이중 부호화한다(WCAG 1.4.1).
5. **엄지로 끝낸다(One-thumb)** — 참석자 핵심 액션은 하단 엄지 존, 터치 타깃 ≥44px, 슬롯 응답은 탭 1회.

## 1. 디자인 토큰

토큰은 의미 기반(semantic)으로 정의한다. Engineer는 이를 CSS 변수 / Tailwind theme / 디자인 변수로 1:1 매핑한다. **원시(primitive) → 의미(semantic)** 2계층.

### 1.1 컬러 — 원시 팔레트 (Primitive)

차분하고 신뢰감 있는 톤. 따뜻한 니어화이트 캔버스 + 차분한 청록(teal) 단일 브랜드 + 절제된 강도 색. 순수 #000/#FFF는 피한다.

| `--c-surface` | `#FFFFFF` | 카드·시트·입력 내부 |
| `--c-surface-sunken` | `#F2F4F4` | 가라앉은 영역(미응답 트랙, placeholder 바탕) |

> 청록(teal)을 브랜드로 택한 근거: 신뢰·차분의 인상을 주면서 빨강/주황 같은 경고 연상을 피한다. "배려·안심" 브랜드 정체성(PRD §8.1)과 직결.

### 1.2 컬러 — 강도 척도 (IntensityScale palette) ★핵심

강도 색은 **polarity(긍정/중립/부정)** 기준으로 *명도·채도가 점진 변하는 연속 스케일*이다. **부정 강도에 빨강 계열을 쓰지 않는다**(PRD §8.2 "회피는 거부가 아님"). 대신 같은 색상(hue) 계열에서 *채도를 빼서* "긍정←중립→가라앉음"으로 읽히게 한다 — 거부가 아니라 "덜 선호"로 읽힌다.

데모 기본 4단계 매핑(`IntensityScale`의 `token` 필드가 가리키는 값):

| id | polarity | 색 토큰 | HEX(채움) | HEX(텍스트/보더) | 형태(shape) | 의미 |
|----|----------|--------|-----------|------------------|-------------|------|
| `prefer` | `+` | `--int-prefer` | `#1F8A82` | `#0F4F4A` | ● 채운 원 + ✓ | 선호(가장 진한 브랜드 청록) |
| `ok` | `0` | `--int-ok` | `#7FB8B3` | `#2F5C58` | ◐ 반채움 원 | 가능(연한 청록) |
| `avoid` | `−` | `--int-avoid` | `#C7B8A6` | `#6E5C45` | ◇ 빗금 마름모 | 가급적 회피(중성 토프/베이지 — 경고색 아님) |
| `hard-no` | `−` | `--int-hardno` | `#8C8C8C` | `#4A4A4A` | ✕ 외곽선 사각 | 불가(무채색 회색 — 빨강 아님) |

> **3단계 전환 시**(prefer/ok/hard-no): `avoid`만 배열에서 제거. 색·형태는 위 표의 해당 id 값을 그대로 재사용. 컴포넌트는 배열을 순회하므로 코드·레이아웃 불변(§0.1 규칙1·4).

**스케일 토큰을 배열로 정의(단일 진실 공급원).** Engineer는 아래를 그대로 데이터로 주입한다(라벨은 UX라이터 확정 전 placeholder):

```
intensityScaleTokens = [
  { id:'prefer',  fill:'--int-prefer',  text:'#0F4F4A', shape:'circle-check', polarity:'+', weight:+2 },
  { id:'ok',      fill:'--int-ok',      text:'#2F5C58', shape:'half-circle',  polarity:'0', weight:+1 },
  { id:'avoid',   fill:'--int-avoid',   text:'#6E5C45', shape:'diamond-hatch',polarity:'-', weight:-1 },
  { id:'hard-no', fill:'--int-hardno',  text:'#4A4A4A', shape:'square-x',     polarity:'-', weight:-Infinity(hard) }
]
```

> `weight`는 추천 점수 계산용(필수 hard-no만 후보 박탈, 그 외 부정은 감점). **막대 시각에는 weight를 쓰지 않는다** — 막대는 건수 분포(§3.3).

**레드라인**
- viewport 좌우 패딩: 16px. 상/하단 고정 바 내부 패딩: 좌우 16, 상하 12.
- 상단 고정 바 56px(progress + privacy 점), 콘텐츠는 그 아래 스크롤. 하단 고정 바 72px, 콘텐츠 하단에 동일 높이 패딩(버튼이 마지막 카드 가리지 않게).
- SlotCard: 패딩 16, radius 12, 보더 hairline, 카드 간 12. 날짜·시간 라인과 ChipGroup 사이 12.
- IntensityChipGroup: 칩 사이 8, 칩 높이 48, 가로 wrap(단계 수 가변 흡수 — 절대 고정 그리드 금지).
- PrivacyNotice(상단 persistent): brand-soft 바탕, radius 8, 패딩 12×16, 좌측 자물쇠 아이콘 20px. 선택 참석자에게만 노출, 화면 상단 상주.

**상태**
- **기본**: 모든 슬롯 미선택(중립). 미선택 = 무응답(거짓 응답 강요 안 함). SubmitButton 라벨 "응답 제출 (0/8)".
- **로딩**: SlotCard 스켈레톤 3장(날짜줄 + 칩 자리 회색 블록, `--c-surface-sunken`, shimmer는 reduced-motion 시 정적).
- **에러**(제출 실패, mock 드묾): 하단에 인라인 Toast "잠시 후 다시 시도해 주세요"(황토 `--s-error`, 빨강 아님). **입력값 전부 보존**.
- **빈 상태**: 슬롯 0개는 RESP-000 게이트에서 이미 차단 → 이 화면 진입 안 함.
- **부분 응답**: 일부만 선택 후 제출 → ConfirmSheet "응답하지 않은 슬롯이 있어요. 그대로 제출할까요?"(중립, 부정 뉘앙스 금지). [그대로 제출] / [마저 응답하기].

**인터랙션**
- 강도 칩 탭 = 즉시 선택(motion-fast 색 전환). 같은 칩 재탭 = 해제(무응답 복귀).
- 부정 강도(avoid/hard-no) 탭 시: **확인 다이얼로그·경고·진동·빨강 없음.** 다른 칩과 동일한 중립 피드백.
- 코멘트 아이콘 탭 → SCR-MOB-RESP-001b 코멘트 시트(하단 시트).

- **역할별 분기**: `role=optional` → ReassuranceBanner + PrivacyNotice를 brand-soft 블록으로 *강조*. `role=required` → 안심 배너는 약하게/생략, 강도 표현 안내 위주. `role` 미지정 → 보수적으로 안심 노출(솔직함 우선, feature-spec F-MOB-RESP-003-001).
- **상태**: 기본 / 로딩(제목·기간 스켈레톤) / 에러(만료·마감 링크 → 황토 안내 + 주최자 문의, 응답 차단) / 빈(슬롯 0개 → "아직 후보 시간이 등록되지 않았어요" + 차단).

### 2.3 SCR-MOB-RESP-002 완료

- 완료 체크(브랜드 청록 success) + "응답이 전달되었어요" + (선택) "당신의 응답은 비공개로 안전하게 전달됐어요" 재확인 + (마감 전) [응답 수정] 링크.
- 상태: 기본(완료) / 로딩(전송) / 에러(재시도, 입력 보존) / 마감 후 → "응답이 마감되었습니다".

### 2.4 솔직함 보호의 시각적 체감 (Flow A 7지점 → 디자인 구현)

| 체감 지점 | 디자인 구현 |
|----------|-----------|
| (1) 무가입 | 로그인 UI 없음. 게이트는 이름 입력/선택만. |
| (2) 역할 인지 | RoleBadge를 게이트 상단에 명확히(색+라벨+아이콘). |
| (3) 안심 | ReassuranceBanner를 brand-soft 블록으로 강조(경고색 아닌 따뜻한 청록 톤). |
| (4) 비공개 고지 | PrivacyNotice 자물쇠 아이콘 + info 텍스트. |
| (5) 부정 강도 무경고 | avoid/hard-no 칩에 빨강·경고·확인창 없음(§1.2 무채/토프 색, 중립 형태). |
| (6) 비공개 지속 노출 | PrivacyNotice를 **상단 상주 + 하단 바에도 은은히** 이중 배치. 스크롤해도 항상 보임(NFR-002 체감의 핵심). |
| (7) 완료 재확인 | RESP-002에서 비공개 전달 재확인 카피. |

> ★ 비공개 "체감"의 디자인 장치 = **지속성**. 1회 고지(게이트)로 끝내지 않고, 입력 화면 상단(상주 배너) + 하단 바(은은한 자물쇠 라벨) 두 곳에 상주시켜 스크롤 내내 "안 보인다"를 인지하게 한다. 이것이 NFR-002를 "보이게" 만드는 핵심.

### 3.3 ★ 제외 슬롯 vs 감점 슬롯의 시각 위계 (확정 보완사항 1 반영)

추천 로직(FR-002 [확정]): **필수 참석자 hard-no만 후보 제외**, 나머지(필수 soft·선택 hard-no·선택 soft)는 *감점하되 후보 유지*. 이 두 종류를 시각적으로 명확히 구분한다.

| 종류 | 정의 | 시각 처리 |
|------|------|----------|
| **후보(점수순)** | 제외되지 않은 모든 슬롯 | `--c-surface` 카드, SlotScoreBadge에 순위+점수(mono), `--shadow-card`. 점수가 낮아도(감점 누적) 후보로 표시. |
| **감점됐지만 후보** | 선택 hard-no·필수 avoid 등으로 점수↓ | 위와 동일 카드. 단 점수가 낮아 **자연스럽게 하단 정렬**(점수 위계로만 구분, 별도 경고색 없음). RequiredFulfillmentTag는 "필수 5/5 가능"으로 정상. |
| **제외(필수 hard-no)** | 필수 1명이라도 hard-no | `--c-surface-sunken` 바탕 + opacity 0.6, 점수 자리에 `⊘ 제외` 배지(황토 `--s-warning` 보더, 채움 없음), 확정 버튼 대신 "필수 N명 불가" 라벨. **빨강 금지**(황토). 리스트 최하단 별도 구획. |

> 위계 원칙: **제외는 "흐림 + 가라앉은 바탕 + ⊘ 배지"의 3중 신호**로, 감점(점수 낮음)과 분명히 다르게 보이게 한다. 감점 슬롯은 여전히 "선택 가능한 후보"이므로 정상 카드로 두되 점수 순서로만 아래에 둔다. 색 경고 대신 *명도/채도 강등*으로 위계를 만든다(차분 톤 유지).

### 3.4 ★ 집계 막대 = 건수 분포 (보완사항 3 반영)

`IntensityDistributionBar`는 **"각 강도에 몇 명이 응답했는지"의 건수(count) 분포**다. 추천 점수(weight 합)와 다른 계산임을 시각으로도 분리한다.

- 막대 = 100% 폭 stacked. 각 세그먼트 폭 = (해당 강도 응답 *건수* / 전체 응답 건수). **weight를 폭에 쓰지 않는다**(hard-no의 제외 신호를 막대에 반영 금지 — hard-no도 "건수 1"로만 쌓인다).
- 세그먼트 색 = `polarity`(§1.2 색), 정렬 = `order`(긍정→부정 왼→오).
- 필수/선택을 **두 줄**로 분리(필수행·선택행). 선택행은 집계만(개인 식별 불가).
- 세그먼트에 건수 라벨(예: "선호 4") + 형태 부호(접근성). 막대 위 캡션 "응답 N명 기준".
- 단계 수 가변: 3단계면 세그먼트 3개, 4단계면 4개. 막대 폭은 항상 100%(§0.1 규칙2).

### 3.5 대시보드 상태

- **기본**: 응답 일부/전체, 추천 정렬 표시.
- **로딩**: 요약 바 + SlotCard 스켈레톤(집계 계산 중).
- **에러**(mock): "현황을 불러오지 못했어요" + [다시 시도](황토, 빨강 아님).
- **★ 빈 상태(응답 0건)**: 추천 영역에 placeholder "응답이 모이면 추천이 표시돼요" + "아직 응답이 없어요. 링크를 공유해 보세요." + [링크 다시 공유] + 미응답 명단. (강도 단계 수 무관 동작)
- **부분 빈**: 필수만 응답·선택 무응답 → 필수 기준 추천 우선 표시, 선택 분포행은 "선택 참석자 응답 없음".
- **최소 익명성(미결)**: 선택 참석자 1명뿐인 슬롯 → 집계가 곧 개인 식별 → "선택 1명 응답"만 표시, 강도 분포 숨김(open_question, feature-spec F-WEB-DASH-003-003 예외).

### 3.6 비공개 경계의 시각 구현 (주최자 측)

- 대시보드 상단 PrivacyBoundaryNotice 상주: "선택 참석자 응답은 집계로만 표시됩니다"(info 톤).
- 선택 참석자 분포는 **항상 집계 막대로만**. 슬롯 상세에서도 개인 행 노출 금지(이름↔강도 매핑 UI 자체를 두지 않는다).
- 코멘트도 집계/익명 맥락으로만(개인 귀속 표시 금지).
