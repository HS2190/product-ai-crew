## 1. 배경 및 목적

### 1.1 문제 정의 (key_insights 인용)

다인원(6명+) 회의 일정 조율에서 "겹치는 시간 찾기"는 기존 도구가 이미 잘 푸는 **commodity**다 〔Theme 1, `[관찰]` 6개 도구 전부〕. 그러나 **범용 일정 도구**에는 세 가지 구조적 빈틈이 남아 있고, 이 빈틈에서 진짜 문제가 발생한다.

| # | 문제 | 근거 (인용) |
|---|------|-----------|
| **P-1 강도** | "되긴 되는데 점심 직후라 별로", "그 요일은 외근이라 피하고 싶다" 같은 **부정적 선호 강도**를 담을 칸이 없다(대부분 yes/no 2단계, Doodle만 if-need-be 3단계). 이 뉘앙스는 메신저로 새어나가 결정에 반영되지 못한다 | Theme 2, I1 `[관찰]` / I4 `[해석]` |
| **P-2 역할** | "누가 꼭 와야 하고(필수) 누가 선택인가"가 폴링형 도구에 없어 모든 응답을 동등 취급한다 → "선택 3명이 안 돼도 필수 5명이 되는 슬롯"을 우선순위화 못 한다. Outlook만 역할 구분이 있으나 **조직 도메인 내부 한정** | Theme 3, I2 `[관찰]` |
| **P-3 솔직함** | 선택 참석자는 "내가 avoid를 누르면 다수에게 폐를 끼친다"는 압박 속에 응답한다. **범용 일정 도구**는 응답을 공개·동등 취급해 솔직함의 비용이 높다(사회적 바람직성 편향의 일정 조율 버전) | Theme 4, I3 `[관찰: 부재 확인 — 범용 도구 한정]` + `[추정]` |

세 빈틈은 **서로 연결**돼 있다 — 정보가 풍부할수록(강도·역할) 참석자는 솔직하기 어려워진다. 그래서 단순히 입력칸을 늘리는 게 아니라 *솔직함의 비용을 낮추는* 설계가 필요하다 〔Executive Summary, `[해석]`〕.

### 1.2 왜 지금, 왜 이 제품인가 (0→1 진입 근거)

시장은 두 갈래다 — (A) 폴링형(when2meet/Doodle/되는시간): 외부 참석자에 강하나 **역할 구분 없음**, (B) 캘린더형(Outlook): 역할은 있으나 **조직 내부 한정** 〔Competitor 종합, `[관찰]`〕. **세 빈틈(강도·역할·솔직함)을 한 제품에서 동시에 푸는 도구는 (분석한 범용 도구 범위에서) 확인되지 않았다** — 이것이 0→1 진입 근거다 〔`[해석]`〕.

> ⚠️ **이 진입 근거는 잠정 결론이다.** 한국 직접 경쟁자(되는시간·모두의 시간)의 강도/역할/솔직함 처리는 미조사다 〔Reviewer 주의 ②, 연구 한계〕. §8에 검증 과제로 남긴다. "솔직함 장치 부재"도 *범용 일정 도구 한정*으로 인용한다 〔Reviewer 주의 ①〕.

## 3. 타겟 사용자

3개 페르소나를 `persona.md`에 정의했다. 설계 우선순위는 **선택 참석자(우민지) > 주최자(김도현) > 필수 참석자(박서준)** 〔Theme 4가 핵심 차별 축〕.

| 페르소나 | 역할 | 핵심 니즈 | 이 제품에서의 의미 |
|---------|------|----------|------------------|
| **김도현** | 주최자/조율자 | 빠른 확정·미응답 추적·강도/역할 가시화 | 도입 결정자, 리텐션 축 |
| **박서준** | 필수 참석자 | 강도 표현·낮은 응답 마찰 | 강도 입력 수혜자 |
| **우민지** | 선택 참석자 | 비공개·솔직함 보호·안심 | ★ 차별 기회의 핵심 타겟 |

**사용 시나리오 (요약):** 김도현이 6~12명에게 후보 슬롯으로 조율 링크를 연다 → 박서준(필수)·우민지(선택)는 모바일에서 슬롯별 강도를 입력 → 우민지의 강도는 다른 참석자에게 비공개, 집계만 김도현에게 노출 → 김도현은 "필수=hard, 선택=가중치"로 정렬된 추천 슬롯에서 확정.

> 본 페르소나는 1차 데이터 없이 도메인 추론으로 정의한 *작업 가설*이다(특히 P3의 솔직함 부담). 사용성 테스트로 검증한다 〔User Segments `[추정]`, Reviewer 주의 ①〕.

## 4. 기능 범위

### In Scope
- 후보 슬롯 생성 및 조율 링크 공유(계정 불필요, 외부 개방)
- **선호 강도 입력**(다단계, 부정적 강도 포함) — FR-001
- **필수/선택 역할 구분 + 역할 반영 추천 로직** — FR-002
- **선택 참석자 응답 비공개 처리 + 안심 메시지** — FR-003
- 모바일 초경량 응답 UX(30초 목표) + 미응답 리마인더 — FR-004
- 주최자용 강도·역할 집계 대시보드(추천 슬롯 정렬) — FR-005
- 슬롯별 맥락 코멘트 첨부 — FR-006

> 범위는 **디자인 → 프론트엔드 구현까지**다. 백엔드·DB·API·실제 캘린더 연동·인증은 범위 밖이며, 데이터는 **mock/정적**으로 처리한다(추천 로직도 프론트 내 정적 계산으로 시연).

### Out of Scope (이번 버전)
- [Out of Scope] 외부 캘린더 실연동(Google/Outlook/네이버) — Theme 1 패리티 항목이나 백엔드 필요, 본 범위 밖
- [Out of Scope] 회의 링크 자동 생성(Zoom/Meet) — 되는시간 패리티 기능, 백엔드 의존
- [Out of Scope] 실서버 인증·계정 시스템 — 정적/mock으로 대체
- [Out of Scope] 푸시 알림 실발송 인프라 — 리마인더는 UI 상태로만 시연
- [Out of Scope] 결제·유료 플랜
- [Won't Have] AI 자동 일정 제안(자연어) — 후속 버전

## 5. 요구사항

### 5.1 기능 요구사항 (FR) — 세 빈틈 매핑

| ID | 기능 | 푸는 빈틈 | 어떻게 푸는가 | 인용 |
|----|------|----------|--------------|------|
| **FR-001** | 선호 강도 입력 모델 | **강도** | yes/no를 넘어 **4단계: 선호(prefer) / 가능(ok) / 가급적 회피(avoid) / 불가(hard-no)**. Doodle 3단계(if-need-be)가 시장 검증 출발점, 그 위에 *부정적 강도(avoid)*를 더하는 게 빈틈 | I1, Theme 2 |
| **FR-002** | 필수/선택 역할 + 역할 반영 추천 | **역할** | 주최자가 참석자를 필수/선택으로 지정. 추천 로직: **필수=hard 제약(한 명이라도 hard-no면 슬롯 감점/제외), 선택=가중치 반영**. Outlook 로직 + 폴링형 개방성(계정 불필요)을 결합 | I2, Theme 3 |
| **FR-003** | 선택 참석자 솔직함 보호 | **솔직함** | 선택 참석자의 개인 강도/불참은 **다른 참석자에게 비공개**(주최자는 집계만 봄). 응답 화면에 **"당신이 안 돼도 회의는 진행됩니다"** 안심 메시지 | I3, Theme 4 |
| **FR-004** | 모바일 초경량 응답 + 리마인더 | (토대) | 슬롯 카드 탭으로 강도 선택(폼 최소화), 30초 목표. 미응답자 자동 리마인더 상태 표시 | I5, Theme 5 〔Impact 추정 의존 — §6 주의〕 |
| **FR-005** | 주최자 집계 대시보드 | (통합) | 강도·역할이 반영된 슬롯 추천 정렬, 미응답 현황 한눈에. P1↔P3 긴장의 절충점(주최자는 *집계된* 강도를 봄) | Theme 3·4 통합 |
| **FR-006** | 슬롯 맥락 코멘트 | 강도 보조 | 슬롯 응답에 짧은 사정 첨부(메신저로 새는 정보 모으기) | I4 |

### 5.2 비기능 요구사항 (NFR)
- NFR-001: 응답 플로우는 모바일 우선, 첫 화면에서 강도 입력까지 마찰 최소(30초 목표) 〔Theme 5, 추정 KPI〕
- NFR-002: 비공개 처리의 *체감*이 명확해야 한다 — 선택 참석자가 "내 응답이 안 보인다"를 인지할 수 있는 시각적 장치 〔FR-003 핵심〕
- NFR-003: 6~12명 그리드에서도 강도·역할이 한눈에 읽히는 가독성(Outlook 6명+ 가독성 저하의 반면교사) 〔Theme 3〕
- NFR-004: 데이터는 정적/mock. 추천 로직은 프론트 내 결정적(deterministic) 계산으로 재현 가능해야 함(데모 일관성)

## 6. 우선순위 (Impact vs Effort)

> 기준: Impact(High=핵심 KPI 직접 / Med=경험 개선 / Low=부가), Effort(Low≤1주 / Med 2~4주 / High≥1개월). 본 프로젝트 범위는 프론트 구현(mock)이므로 Effort는 *프론트 구현 난이도*로 환산.

| 기능 | Impact | Effort | 우선순위 | 결정 근거 (Why) |
|------|--------|--------|---------|----------------|
| **FR-001 강도 입력** | High | Med | **Must Have** | 세 빈틈 중 가장 또렷하고 입력값이 모든 추천의 원천. Doodle 3단계가 시장 검증 출발점이라 리스크 낮음 〔I1〕 |
| **FR-002 역할 + 추천 로직** | High | High | **Must Have** | I2·I3가 차별의 정체성. 역할 없이는 "전원 가능 슬롯 찾기"로 회귀 → commodity. Effort 높으나 핵심이라 포함 〔I2〕 |
| **FR-003 솔직함 보호** | High | Med | **Must Have** | 제품의 *중심 설계 과제*이자 입력 문제 정의의 핵심. P3가 핵심 타겟. 단, 효과는 **추정**이라 검증 KPI 필수 〔I3, Theme 4〕 |
| **FR-005 주최자 대시보드** | High | Med | **Must Have** | FR-001~003의 출력부. 주최자가 결정하는 화면이 없으면 입력이 무의미. P1↔P3 긴장의 절충점 |
| **FR-004 모바일 응답 + 리마인더** | High `[추정]` | Med | **Should Have** | 차별 기능의 토대지만 Impact=High 근거가 **추정**이다 〔Reviewer 주의 ③〕. 응답 UX(모바일 경량)는 Must급에 준해 구현하되, **리마인더는 mock 상태 표시로 축소** — Impact 불확실성을 반영해 Should로 강등 |
| **FR-006 맥락 코멘트** | Med | Low | **Nice to Have** | 강도를 보조하는 부가 입력. Low effort라 여유 시 추가 〔I4〕 |
| 외부 캘린더 실연동 | — | High | **Won't Have(범위 밖)** | 백엔드 의존, 본 시스템 범위 밖(§4) |

**Must Have 4건**(FR-001·002·003·005)이 "강도·역할·솔직함" 세 빈틈 + 그 출력부를 모두 커버한다. 〔게이트 요건: Must ≥1 충족〕

> **추정 의존 표기** 〔Reviewer 주의 ③〕: FR-004의 Impact=High는 Researcher가 `[추정]`으로 명시한 근거다(일정 조율의 모바일·리마인더 가치는 1차 데이터로 검증 안 됨). 따라서 **모바일 응답 경험**은 차별 기능을 떠받치는 토대로 구현하되, **리마인더의 우선순위는 보수적으로(Should, mock)** 잡았다. 사용성 테스트에서 응답 마찰이 실제 병목으로 확인되면 Must로 승격한다.

## 8. 브랜드 방향성 / 톤앤매너 (디자이너·UX라이터 전달)

### 8.1 브랜드 포지셔닝
> **"솔직해도 괜찮은 일정 조율"** — 더 많은 칸을 강요하지 않고, 솔직한 신호를 안전하게 모으는 도구.

차별은 "겹치는 시간"이 아니라 **강도·역할·솔직함**에 있다. 브랜드 인상도 *효율*보다 *안심과 배려*에 무게를 둔다(특히 선택 참석자 경험).

### 8.2 톤앤매너
- **Voice:** 압박하지 않는 / 배려하는 / 명료한. 독촉·강요·죄책감 유발 금지(P3 솔직함 보호와 직결)
- **핵심 카피 원칙:** "당신이 안 돼도 회의는 진행됩니다"처럼 *안심*을 먼저 준다. 부정 응답(avoid/hard-no)을 누를 때 부정적 뉘앙스나 경고를 주지 않는다
- **강도 표현 어휘:** 선호/가능/가급적 회피/불가 — 가치판단 없는 중립 어휘. "싫음" 같은 감정어 지양
- **시각 인상:** 차분하고 신뢰감 있는 톤. 강도는 단계가 직관적으로 읽히는 색/형태 스케일(빨강=금지 같은 강한 경고색 남용 지양 — 회피는 거부가 아님)
- **모바일 우선:** 한 손·이동 중 30초 응답에 맞는 큰 탭 타깃·최소 입력

### 8.3 디자인 시 유의 (NFR 연계)
- 비공개의 *체감*을 시각적으로 전달(선택 참석자: "내 응답은 다른 사람에게 보이지 않아요" 인지) 〔NFR-002〕
- 6~12명 강도·역할 집계의 가독성(주최자 대시보드) 〔NFR-003〕
- 접근성(WCAG): 강도는 색만이 아니라 형태/라벨로도 구분

## 10. 미결 사항 ([확인 필요] — 기획자 단계 협의)

- **[확인 필요]** 강도 단계 해상도: **4단계(prefer/ok/avoid/hard-no) 채택을 제안**하나, 입력 부담 vs 변별력 트레이드오프는 사용성 테스트로 검증. 3단계(Doodle식)로 축소 가능성 열어둠 〔Q for Research〕
- **[확인 필요]** 타겟 환경(사내 회의 / 외부 미팅 / 동호회·스터디)에 따라 세 빈틈 우선순위가 달라지는가 — 1차 데모는 **사내+외부 혼합 회의**를 기본 시나리오로 제안. 기획자와 확정 〔User Segments 검증 과제〕
- **[확인 필요]** 비공개 처리의 구체 UX: 선택 참석자 응답을 주최자에게 "완전 비공개"로 할지 "집계만 노출"할지 — 본 PRD는 *집계만 노출* 제안. 디자이너와 절충점 협의
- **[확인 필요]** 필수/선택을 *주최자가 지정* vs *참석자가 자기 신고* — 본 PRD는 주최자 지정 제안

## 11. 검증 과제 (Reviewer 주의사항 → 후속 검증으로 이관)

1. 〔주의 ①〕 "솔직함 장치 부재"는 **범용 일정 도구 한정** 주장이다. 본 PRD 전체에서 이 한정으로만 인용했다. 실제 한국 직접 경쟁자 검증 필요.
2. 〔주의 ②〕 "세 빈틈 동시 해결 도구 없음"은 **잠정 결론**. 되는시간·모두의 시간의 강도/역할/솔직함 처리 미조사 — 직접 앱 사용 기반 추가 조사 필요.
3. 〔주의 ③〕 Theme 5(모바일·리마인더) Impact=High는 **추정**. FR-004를 Should로 보수적 배치했고, 사용성 테스트로 Must 승격 여부 결정.
4. P3 솔직함 부담의 실재 여부 및 비공개 처리의 효과 — 제품 핵심 가설, 사용성 테스트 1순위 검증.
