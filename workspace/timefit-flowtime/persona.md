## 페르소나 우선순위

이 제품은 **세 역할의 긴장**을 푼다. 페르소나도 세 명을 정의하되, 설계 우선순위는 다음과 같다.

1. **P3 선택 참석자(우민지)** — 제품의 차별 기회(솔직함 보호)의 핵심 타겟. *이 사람이 솔직하게 응답하는가*가 제품 성패의 축.
2. **P1 주최자/조율자(김도현)** — 도입 결정자이자 빈도 높은 사용자. *이 사람이 빠르게 확정하는가*가 리텐션의 축.
3. **P2 필수 참석자(박서준)** — 강도 입력의 1차 수혜자. 응답 마찰이 낮아야 한다.

## P1. 주최자 / 조율자 — 김도현 (Organizer) 〔도입 결정자〕

| 항목 | 내용 |
|------|------|
| 나이/직무 | 34세, 중견 IT 회사 프로덕트 팀 리드 (또는 동호회·스터디 운영진) |
| 맥락 | 한 주에 2~4개의 6~12명 회의를 소집. 일정 확정 책임이 본인에게 있음 |
| 디지털 숙련도 | 높음. 캘린더·메신저·노션 능숙. 새 도구 도입에 거부감 없으나 "팀원이 안 쓰면" 빠르게 이탈 |
| 사용 환경 | 데스크톱 + 모바일 혼용. 일정 취합·확정은 이동 중 모바일에서도 자주 발생 |

**Pain Points** (→ 연결 인사이트)
- 가능 시간을 메신저로 일일이 취합하고 손으로 정리한다 — 느리고 누락이 잦다 〔I5, Theme 5〕
- "되긴 되는데 그날은 외근이라…" 같은 강도 정보가 대화에 흩어져 결정에 반영 안 됨 〔I1·I4, Theme 2〕
- 누가 꼭 와야 하는지(필수) 구분이 도구에 없어, 전원이 가능한 슬롯만 찾다 일정이 한없이 밀린다 〔I2, Theme 3〕
- 응답 안 한 사람을 일일이 찾아 독촉해야 한다 〔I5, Theme 5〕

**Goals**
- 6명+ 일정을 "전원이 아니라 *필수 인원* 기준"으로 빠르게 확정
- 강도·역할 정보를 한 화면에서 보고 의사결정
- 미응답자를 자동으로 추적·리마인드

**성공 신호:** 조율 시작 → 확정까지 걸린 시간이 메신저 취합 대비 크게 단축. 재방문해 다음 회의도 이 도구로 연다.

## P2. 필수 참석자 — 박서준 (Required) 〔강도 입력 수혜자〕

| 항목 | 내용 |
|------|------|
| 나이/직무 | 29세, 같은 팀 실무 담당. 회의 성립에 꼭 필요한 인원 |
| 맥락 | 회의당 2~5명. 빠지면 회의가 무의미해지는 위치 |
| 디지털 숙련도 | 보통~높음. 알림에 빠르게 반응하지만 "폼 채우기"는 귀찮아함 |
| 사용 환경 | 주로 모바일. 알림 받고 그 자리에서 30초 안에 끝내고 싶음 |

**Pain Points**
- "가능/불가능" 이분법으로는 "되긴 되는데 점심 직후라 집중 안 됨" 같은 진짜 선호를 못 담는다 〔I1, Theme 2〕
- 솔직히 "그 시간은 피하고 싶다"고 했다가 조율을 어렵게 만들까 봐 그냥 "가능"을 누른다 → 결국 본인이 힘든 시간에 회의 잡힘 〔I1·I3〕

**Goals**
- 가능/불가능을 넘어 **선호 강도**를 빠르게 표현 (선호 / 가능 / 가급적 피하고 싶음 / 절대 불가)
- 사정(맥락)을 슬롯에 짧게 첨부

**성공 신호:** 30초 안에 응답 완료. 본인이 "피하고 싶다"고 표시한 시간이 실제로 회피된다.

## P3. 선택 참석자 — 우민지 (Optional) 〔★ 핵심 타겟: 솔직함 보호〕

| 항목 | 내용 |
|------|------|
| 나이/직무 | 31세, 인접 팀/유관 부서. 와도 되고 안 와도 되는 인원 |
| 맥락 | 회의당 다수일 수 있음. 본인 없이도 회의는 성립함 |
| 디지털 숙련도 | 보통. 도구보다 "분위기"에 민감 — 폐 끼치는 걸 극도로 꺼림 |
| 사용 환경 | 모바일. 여러 회의 초대를 받아 응답 피로가 큼 |

**Pain Points** (제품의 중심 과제)
- "내가 avoid를 누르면 필수 인원 5명에게 폐를 끼친다"는 압박 → 솔직히 못 답하고 "아무때나 가능"으로 거짓 응답 〔I3, Theme 4〕
- 응답이 다른 참석자에게 그대로 공개돼 솔직함의 비용이 높다 〔I3, Theme 4〕
- "나는 선택인데 왜 전원 일정처럼 취급받지?" — 빠져도 된다는 안심이 없다 〔I2·I3〕

**Goals**
- **압박 없이 솔직하게** 응답 (내 강도/불참이 다수에게 노출되지 않음)
- "당신이 안 돼도 회의는 진행됩니다"라는 명시적 안심
- 가벼운 응답 — 안 와도 되는 회의에 시간 쓰고 싶지 않음

**성공 신호:** 선택 참석자의 응답이 "솔직"하다(거짓 가능 응답이 줄어든다). 검증: 선택 참석자가 avoid/hard-no를 실제로 사용하는 비율, 사후 "솔직히 답했나" 설문.

> ⚠️ 이 페르소나의 핵심 가정("솔직함 부담이 존재하고, 비공개 처리로 완화된다")은 **추정**이다. 사용성 테스트로 반드시 검증한다.

## 세그먼트 간 긴장 (제품의 중심 설계 과제)

> 주최자(P1)는 *더 많은 정보*(강도·역할·맥락)를 원하고, 선택 참석자(P3)는 *덜 노출되길* 원한다. 이 긴장을 "입력칸을 늘리는 것"이 아니라 *솔직함의 비용을 낮추는 비공개 설계*로 푼다 〔Research 해석〕.

| | P1 주최자 | P3 선택 참석자 |
|---|---|---|
| 원하는 것 | 강도·역할·맥락 풍부한 정보 | 최소 노출, 압박 없음 |
| 제품의 절충 | 주최자는 *집계된* 강도·역할을 본다 | 개인 단위 솔직한 신호는 비공개로 보호 |

## 검증 과제 (기획자·디자이너·사용성 테스트로 이관)

- P3의 솔직함 부담이 실재하는가, 비공개 처리가 실제로 솔직함을 끌어올리는가
- 강도 단계 수의 적정 해상도(3 vs 4단계)
- 타겟 환경(사내 회의 / 외부 미팅 / 동호회)별로 세 빈틈의 우선순위가 달라지는가
