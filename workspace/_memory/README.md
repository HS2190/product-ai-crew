# 기억층 (Memory Layer)

프로젝트를 **넘어** 누적되는 맥락을 담는 곳이다. `workspace/[서비스명]/session.md`가 한 프로젝트 *안*의 진행을 추적한다면, 기억층은 프로젝트 *사이*에 쌓이는 판단과 선호를 담아 시스템이 쓸수록 그 회사·그 디자이너에게 맞게 똑똑해지도록 만든다.

## 2층 구조

| 층 | 경로 | 담는 것 |
|----|------|--------|
| **개인** | `designer-profile.md` | 회사 불문 유지되는 나의 작업 취향·원칙 |
| **회사** | `companies/[회사명]/decisions.md` | 그 회사에서 내린 판단과 근거 (결정 로그) |
| **회사** | `companies/[회사명]/conventions.md` | 그 회사의 톤·디자인 규칙·기술 제약 |

회사별로 분리해 A사의 결정이 B사로 새지 않게 한다. 개인 층은 회사가 바뀌어도 유지된다.
새 회사는 `companies/_template/`를 복사해 `companies/[회사명]/`를 만든다.

## 기록 방식 — 반자동 (제안 → 승인)

- **자동 저장하지 않는다** (쓰레기 누적 방지).
- **무조건 수동도 아니다** — 기억할 가치가 있는 항목은 오케스트레이터가 *제안*한다.
- 사용자가 **승인한 것만** 해당 파일에 누적된다.

## 무엇을 담는가 / 담지 않는가

- **담는 것**: 재현 가능한 판단의 근거(왜 그렇게 결정했나), 회사의 톤·규칙·제약, 반복 확인된 사용자 선호.
- **담지 않는 것**: 산출물 자체(PRD·디자인·코드 — 프로젝트 폴더에 있음), 리서치 원본 데이터, 일회성 정보, 세션 진행 상태(`session.md`가 담당).
- 원칙: 기억층은 **판단과 선호**만 담는다. 데이터 창고가 아니다.

## 읽기 — 자동 주입

오케스트레이터는 작업 시작 시 개인 프로파일과 해당 회사 기억을 자동으로 로딩해 모든 에이전트에 `memory_context`로 주입한다. 사용자가 매번 "지난번 결정 참고해"라고 말하지 않아도 적용된다. 자세한 흐름은 루트 `CLAUDE.md`의 「프로젝트 간 기억층」 섹션을 따른다.
