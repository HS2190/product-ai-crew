## 3. 케이스 처리 원칙 (Gemini, 채택 + 보완)

- 라벨 분리: 회사 작업(Dr's Solution · Wepair · Gocha · Sensicon) = **COMMISSIONED**(홈 시안의 "Made to order"와 연결) / GitMate · Iris = **SELF-INITIATED**
- 모든 케이스 MISSING → DECISION → PROOF 3단, 회고·감상 배제
- **보완 — 근거 태그 어휘 통일**: Gemini는 `실측` 태그를 씀. 우리 기준(tokens.md)은 `관찰 · 출처 · 본인`. 사이트·덱이 이미 "실측"을 쓰므로 **4종(실측 · 관찰 · 출처 · 본인)으로 확장** 권장
- Dr's Solution(현 재직): 내부 결함 수치는 노출 범위 확인 전까지 숨기고, UI 산출물 수치(화면 · 문구 수)만

## 4. 기각·수정한 Gemini 제안

| Gemini 제안 | 판단 | 이유 |
|---|---|---|
| 홈 "화면을 그리던 디자이너에서…"를 문학적 수사로 삭제 | **보류** | 사용자가 유지 결정한 정체성 문장의 한글 짝. 히어로 보조문으로 남길지 사용자 판단 |

| 우선순위 Later = UI 개편 | 수정 | 문구 → UI를 따로 하면 두 번 일함. 페이지 단위로 문구 + 템플릿을 같이 |
