## 1. 자동 반영 기능 명세

### 1-1. 기능 개요

| 항목 | 내용 |
|---|---|
| 기능명 | AOS 입고 자동 반영 |
| 트리거 | 위페어 파트너스 앱 Foreground 진입 시 (최초 실행 + 백그라운드 → 포그라운드 복귀) |
| 목적 | AOS 알파에서 완료된 입고 등록을 위페어에 중복 작업 없이 자동 반영 |
| 우선순위 | 필수 |

### 1-2. 트리거 조건

| 트리거 시점 | 실행 여부 |
|---|---|
| 앱 최초 실행 | ✅ 실행 |
| 백그라운드 → 포그라운드 전환 | ✅ 실행 |
| 앱 내 다른 화면 → 작업목록 이동 | ❌ 미실행 (진입 시마다 실행하지 않음) |
| 앱 종료 후 재실행 | ✅ 실행 |

> **주의:** 과도한 반복 실행을 방지하기 위해 포그라운드 전환 기준으로만 트리거.
> 마지막 스캔 시각을 로컬 저장해 일정 시간(예: 30초) 내 재실행은 skip.

### 1-3. 데이터 처리 로직

```
1. AIAOS전송 폴더 경로 확인
   └── 경로: DCIM/AIAOS전송/
   └── 권한 없음 → 종료 (사용자 알림 없음)

2. 폴더 목록 스캔
   └── "차량번호_차종" 형식 폴더 필터링
   └── 최근 수정일 기준 정렬 (최신순)

3. 폴더명 파싱
   └── 언더스코어(_) 기준 분리
   └── 앞부분: 차량번호 (예: 12가1234)
   └── 뒷부분: 차종명 (예: 쏘렌토 MQ4)

4. 차종명 정규화
   └── 제조사 접두어 제거 (기아, 현대, BMW 등)
   └── 모델 코드 제거 (MQ4, G80 등 선택적)
   └── 표준 차종 DB 매핑 (가능한 경우)
   └── 매핑 실패 시: 원본 문자열 그대로 사용

5. 중복 확인
   └── 위페어 DB에서 동일 차량번호 조회
   └── 오늘 날짜 기준 이미 등록된 차량번호면 skip

6. 입고 등록 API 호출
   └── 엔드포인트: POST /v1/vehicles/register
   └── 파라미터: 차량번호, 차종명, 입고시점(폴더 생성시각)

7. 사진 업로드
   └── 대표사진: AIAOS전송/{폴더명}/ 내 첫 번째 파일 (생성시각 기준)
   └── 나머지 사진: 전체 업로드 (비동기, 순서 보장 불필요)

8. 결과 처리
   └── 전체 성공: 작업목록 갱신 + 토스트
   └── 일부 실패: 성공 건만 갱신 + 부분 실패 토스트
   └── 전체 실패: 기존 목록 유지 + 실패 토스트
```

### 1-4. 성공 / 실패 / 중복 처리 기준

| 케이스 | 판단 기준 | 처리 |
|---|---|---|
| 성공 | API 응답 200 + 사진 업로드 완료 | 작업목록 갱신, 성공 토스트 |
| 실패 (API) | API 응답 4xx/5xx | 해당 건 skip, 실패 건 카운트 |
| 실패 (네트워크) | 타임아웃 or 연결 없음 | 전체 중단, 실패 토스트 |
| 중복 (동일 차번) | 오늘 기준 동일 차량번호 기등록 | 해당 건 skip (에러 아님) |
| 사진 없음 | 폴더 내 파일 0개 | 차량 정보만 등록, 사진 없이 완료 |
| 차종 정규화 실패 | 표준 DB 미매칭 | 원본 문자열 그대로 등록 |

### 1-5. 피드백 처리

| 상황 | 피드백 |
|---|---|
| 1건 이상 성공 | 토스트: "N건의 입고 데이터를 불러왔어요" (3초) |
| 0건 (신규 없음) | 피드백 없음 (조용히 종료) |
| 전체 실패 | 토스트: "AOS 연동에 실패했어요. 수동으로 불러와 주세요" (4초) |

## 2. 수동 연동 기능 명세

### 2-1. 기능 개요

| 항목 | 내용 |
|---|---|
| 기능명 | AOS 수동 불러오기 |
| 트리거 | 작업목록 화면 내 Btn_AOS_Sync 버튼 탭 |
| 목적 | 자동 반영 실패 또는 사용자 임의 동기화 요청 시 수동으로 AOS 데이터 가져오기 |
| 우선순위 | 필수 |

### 2-2. 버튼 동작 정의

| 단계 | 동작 |
|---|---|
| 탭 | 버튼 상태 → 로딩(스피너 회전), 탭 비활성화 |
| 스캔 시작 | AIAOS전송 폴더 접근 시도 |
| 처리 중 | 자동 반영과 동일한 1-3 데이터 처리 로직 실행 |
| 완료(성공) | 버튼 → 완료 아이콘(2초) → 기본 상태 / 토스트 표시 |
| 완료(실패) | 버튼 → 기본 상태 복귀 / 실패 토스트 표시 |

### 2-3. 연동 중 / 완료 / 실패 상태 처리

| 상태 | 버튼 UI | 토스트 메시지 | 목록 변화 |
|---|---|---|---|
| 연동 중 | 스피너 (disabled) | 없음 | 변화 없음 |
| 완료 (성공) | ✓ 아이콘 → 기본 | "N건 입고를 불러왔어요" | 신규 카드 상단 추가 |
| 완료 (새 데이터 없음) | 기본 | "새로 불러올 입고 데이터가 없어요" | 변화 없음 |
| 실패 (API) | 기본 | "불러오기에 실패했어요. 다시 시도해 주세요" | 변화 없음 |
| 실패 (네트워크) | 기본 | "네트워크 연결을 확인해 주세요" | 변화 없음 |
| 실패 (권한 없음) | 기본 | "AOS 폴더에 접근할 수 없어요. 권한을 확인해 주세요" | 변화 없음 |
| 부분 성공 | 기본 | "N건 중 M건 불러오기에 실패했어요" | 성공 건만 추가 |

### 2-4. 예외 케이스

| 예외 상황 | 처리 방식 | 우선순위 |
|---|---|---|
| AOS 폴더 자체 없음 | "새로 불러올 입고 데이터가 없어요" 토스트 | 필수 |
| 폴더 읽기 권한 없음 | 권한 요청 다이얼로그 또는 설정 유도 안내 | 필수 |
| 네트워크 오류 | 토스트 표시 후 재시도 가능 | 필수 |
| 진행 중 재탭 | 버튼 disabled 상태 유지, 재실행 없음 | 필수 |
| 진행 중 앱 백그라운드 전환 | 백그라운드에서 계속 처리, 완료 후 포그라운드 복귀 시 결과 토스트 | 권장 |
| 폴더 내 사진 0개 | 차량 정보만 등록, 사진 없음 상태로 카드 생성 | 필수 |
| 차량번호 파싱 실패 (형식 불일치) | 해당 폴더 skip, 로그 기록 | 권장 |
| 서버 점검 중 (503) | "잠시 후 다시 시도해 주세요" 토스트 | 필수 |

## 3. 공통 기술 요구사항

| 항목 | 요구사항 |
|---|---|
| 스캔 대상 경로 | `DCIM/AIAOS전송/` (Android 기준) |
| 폴더명 형식 | `{차량번호}_{차종명}` (언더스코어 1개 기준 분리) |
| 중복 기준 | 동일 차량번호 + 오늘 날짜 기준 |
| 재실행 방지 | 마지막 스캔 시각 로컬 저장, 30초 이내 재실행 skip |
| 사진 업로드 방식 | 대표사진(1장) 먼저, 나머지 비동기 병렬 처리 |
| API 타임아웃 | 요청당 10초 |
| 실패 재시도 | 자동 반영: 미재시도 / 수동 연동: 버튼 재탭으로 재시도 가능 |
| 권한 요구 | Android 저장소 읽기 권한 (READ_EXTERNAL_STORAGE 또는 READ_MEDIA_IMAGES) |
