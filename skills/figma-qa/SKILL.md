# figma-qa — 시안 자동 점검

Figma에 그린 결과를 사용자에게 보여 주기 전에, 사람이 매번 지적하던 문제(잘림 · 겹침 · 임의 색 · 직접 그린 요소)를 스크립트로 먼저 찾아 고친다.

## 언제 실행하나
- Figma에 화면 · 시안 · 플로우 · 상태 모음 · 전달 문서를 **그리거나 고친 뒤, 보고하기 전** — 자동
- 사용자가 점검을 요청할 때
- 실행하지 않음: 읽기만 한 작업, 코드 · 문서 작업, 사용자가 "점검 빼고"라고 한 경우

## 순서

### 1. 범위 정하기
- 이번에 그리거나 고친 **섹션 · 프레임 id** (같은 페이지 안). 페이지 전체가 아니라 섹션 단위
- 여러 섹션이면 `TARGET_IDS`에 함께 넣음. 섹션 하나가 노드 1만 개를 넘으면 하위 섹션으로 나눠 병렬 실행

### 2. 실행 (읽기 전용)
- `scripts/check.js`를 Read → 첫 줄 `'__TARGET__'`를 대상 id로 바꿔 `use_figma`의 code로 그대로 넘김 (`skillNames: figma-use`)
- 캔버스를 바꾸지 않음. 화면 33개 · 노드 7천 개 기준 1회 호출로 끝남

### 3. 판정 — 항목마다 실제 문제 / 의도 / 오탐
잘림 · 겹침 · 넘침은 **해당 노드의 부모를 `node.screenshot()`으로 찍어 눈으로 확인한 뒤** 판정 (한 번의 use_figma로 여러 장).

| 항목 | 실제 문제 | 의도로 볼 수 있는 경우 |
|---|---|---|
| 잘림 | 글자 · 버튼 · 카드 테두리가 잘려 보임, 화면 아래 목록 줄이 반쯤 잘림 | 가로 스크롤 목록 끝 걸침 |
| 텍스트 넘침 | 글자가 상자 밖으로 나옴 | — (`fontNote`가 있으면 신뢰 낮음 → 스크린샷으로만 판단) |
| 텍스트 겹침 · 텍스트 · 아이콘 겹침 | 같은 층에서 글자끼리 · 글자와 아이콘이 겹침 | — |
| 배치 겹침 · 섹션 밖으로 나감 | 설명 카드 · 라벨 · 화면이 서로 겹치거나 섹션 밖 | — |
| 연결 안 된 색 | 화면 안 색이 DS 변수 · 스타일에 연결 안 됨 | OS 화면 흉내(알림 · 설정 앱), 사진 위 반투명 덮개 |
| 컴포넌트 아님 | 이름은 버튼 · 칩 · 배지인데 직접 그린 것 | — |
| 한쪽 색 띠 | 금지 패턴 (왼쪽 · 오른쪽 굵은 테두리, 카드 왼쪽 세로 막대) | 없음 |
| 옛 컴포넌트 의심 · 원본 컴포넌트 없음 | 리뉴얼 화면에 옛 페이지 · 삭제된 컴포넌트 | — |
| 임시 문구 | Lorem · TODO 등 | — |

- `componentSources`: 인스턴스 원본 페이지 분포. 리뉴얼 화면에 '코드 원본' 등 다른 페이지 출처가 섞이면 확인
- `screensWithoutInstances`: 컴포넌트를 하나도 안 쓴 화면 → 직접 그린 화면 의심

### 4. 고치기
- 실제 문제만 고침 (figma-use · figma-generate-design 규칙대로, DS 컴포넌트 · 변수 사용)
- 색 → 가장 가까운 DS 변수로 연결. 직접 그린 요소 → DS 컴포넌트로 교체. 새 컴포넌트가 필요하면 만들지 말고 보고
- 레이아웃을 바꿔야 하는 문제(화면 높이 · 아이템 수 조정 등 디자인 판단)는 고치지 말고 '확인 필요'로 보고

### 5. 재점검
- 같은 범위로 다시 실행해 실제 문제 0건 확인. 고친 부분만 스크린샷 1장

### 6. 보고 (한국어, 짧게 · 결과 JSON 그대로 붙이지 않기)
```
점검: [섹션 이름] · 화면 n개
- 고침 n건: [종류] 무엇을 어떻게 (한 줄씩)
- 의도로 둔 것 n건: 이유
- 확인 필요 n건: 정해야 할 것
```

## 예외 표시
- 의도한 잘림 · 겹침이 매번 걸리면, 사용자에게 묻고 그 레이어 이름에 `[qa-ok]`를 붙임 → 이후 점검에서 빠짐
- 일부러 화면 위에 올린 '수정 표시' · '확인 필요' · 마커는 자동으로 빠짐

## 한계
- 원격 실행 환경에서는 글꼴이 없는 것으로 읽혀(`fontNote`) 텍스트 넘침 판정이 부정확할 수 있음 → 글자 많은 화면은 스크린샷으로 보완
- 위계 · 여백 · 톤 같은 디자인 품질은 판단 못 함 (critique-* 스킬 몫)
- 덮이는 층(팝오버 · 모달 · 패널 · 토스트)은 이름 규칙과 '화면 바로 아래 그림자 있는 레이어'로 구분 — 이름이 다르면 겹침 오탐이 날 수 있음 → 스크린샷으로 판정
