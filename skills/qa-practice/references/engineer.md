# Engineer용 — mock이라도 실제처럼 동작해야 하는 지점

크루 Engineer는 백엔드 없이 mock 데이터로 구현한다. 그래도 아래는 실제 서비스처럼 동작하게 만든다.

## 1. 중복 요청

- 데이터를 만들거나 바꾸는 버튼은 처리 중 비활성 → 연타해도 요청 1번
- 확인: 버튼을 빠르게 두 번 눌러 생성 건수가 1인지

## 2. 권한은 요청 단계에서

- 버튼 숨김으로 끝내지 않기 — 데이터 접근 함수 · 라우트 가드에서도 막기
- 확인: 권한 없는 화면 주소를 직접 입력 → 막힘 / 남의 글 id로 수정 · 삭제 시도 → 거부

## 3. 없는 대상 · 실패

- 잘못된 id 라우트, 요청 실패(mock에서 실패 분기) → 빈 화면 · 무한 로딩 대신 디자인의 error 상태
- 삭제 후 뒤로 가기로 재진입 → 없는 대상 안내

## 4. 입력 유지

- 작성 중 입력값이 화면 회전 · 탭 이동 · 뒤로 갔다 오기로 사라지지 않게 (스펙이 초기화로 정한 경우 제외)
- 세션 만료 후 저장 시 작성 내용 보존

## 5. 반영 일치

- 생성 · 수정 · 삭제 후 목록 · 상세 · 개수 · 검색 결과에 모두 반영
- 목록만 그대로면 캐시 · 화면 갱신 문제

## 6. 참고 — HTTP · 상태 코드 (실제 API 연동 시 · mock 응답 설계 시)

| 동작 | 메서드 | 성공 | 주요 실패 |
|---|---|---|---|
| 생성 | POST | 201 (또는 200) | 400 형식 오류 · 409 중복 |
| 조회 | GET | 200 | 404 없음 |
| 수정 | PATCH(부분) / PUT(전체) | 200 · 204 | 403 권한 없음 |
| 삭제 | DELETE | 204 · 200 | 404 · 410 |

- 401 로그인 필요 · 만료 / 403 권한 없음 · 보안 장비 차단 / 429 요청 과다
- 500 서버 오류 / 502 중간 서버가 잘못된 응답 받음 / 503 점검 · 과부하 / 504 시간 초과
- JSON 함정: `12000` ≠ `"12000"`, `null` · `""` · 키 없음은 서로 다름 → 화면이 각각 어떻게 보이는지
- 고쳤는데 화면이 그대로면: 강력 새로고침 → 캐시 · 쿠키 삭제 → CDN 캐시 → 배포 버전 확인
