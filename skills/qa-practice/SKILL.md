# qa-practice — QA 실무 체크리스트

크루 각 역할이 "써 보면 깨지는 곳"을 미리 막기 위한 참고 모음. 에이전트 문서에는 꼭 지킬 규칙만 두고, 상세 목록은 여기서 역할별로 읽는다.

- 출처: 현업 QA 실무에서 자주 쓰는 점검 항목을 역할별로 정리
- 성격: 현업 QA 실무 체크리스트. 방법론 교재가 아님
- 원칙: **해당하는 기능에만** 적용. 로그인 · 결제 · 권한 · 외부 연동이 없는 단순 화면에 억지로 채우지 않음

## 역할별 참고 파일

| 역할 | 파일 | 언제 읽나 |
|---|---|---|
| 기획자 | [references/planner.md](references/planner.md) | 정책 기준값 · 권한 · 데이터 생성 · 외부 연동(간편로그인 · 결제 · 딥링크)이 있는 기능 |
| 디자이너 | [references/designer.md](references/designer.md) | 화면을 그릴 때 항상 (긴 텍스트 · 시스템 설정 · 겹쳐 뜨는 요소 · OS 차이) |
| Engineer | [references/engineer.md](references/engineer.md) | 데이터를 만들거나 바꾸는 기능, 권한 · 라우트가 있는 기능 |
| QA | [references/qa.md](references/qa.md) | QA 단계 전체 (테스트 케이스 · 탐색적 테스트 · 버그 리포트 · 심각도) |

Reviewer는 각 역할 파일의 항목을 해당 역할 검수 때 참고한다.

## 모든 역할 공통 8원칙

1. **기준은 문서** — 기획서 · 정책 · 상태 정의가 기준. 문서끼리 다르면 진행 전에 질문. 변경은 말이 아니라 기록으로
2. **정상 · 예외 · 경계값 세 벌** — 기능마다 세 가지를 붙이면 테스트 목록이 됨
3. **화면만 보지 않기** — 화면 → API 응답 → 데이터 순으로 대조. 최종 기준은 저장된 데이터
4. **권한은 화면이 아니라 요청에서** — 버튼을 숨겨도 주소 · API로 직접 들어오면 막혀야 함
5. **비정상 상황이 버그의 집** — 연타 · 네트워크 끊김 · 중단 후 복귀 · 긴 텍스트 · 빈 값 · 뒤로 가기 · 외부 앱 왕복
6. **리포트는 재현 가능하게** — 제목 한 줄 · 환경 · 재현 절차 · 기대 / 실제 · 증거 · 심각도
7. **심각도 ≠ 우선순위** — 심각도는 문제의 크기, 우선순위는 고칠 순서
8. **사실로 말하기** — 감정 없이 근거로. 적은 버그지 사람이 아님

## 새 지식 반영

- 새 내용은 해당 역할 파일에만 추가 (주제가 아니라 "그 지식으로 판단하는 역할" 기준)
- 정말 모든 기능에 필요한 것만 에이전트 문서 규칙으로 올림
