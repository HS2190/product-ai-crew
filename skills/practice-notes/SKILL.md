# practice-notes — 크루 실무 지식

크루 각 역할이 "써 보면 깨지는 곳"을 미리 막고, 왜 그런지 알고 판단하도록 돕는 참고 모음. 에이전트 문서에는 꼭 지킬 규칙만 두고, 상세는 여기서 읽는다.

- 성격: 현업 실무 기준. 방법론 교재가 아님
- 원칙 1: **해당하는 기능에만** 적용. 로그인 · 결제 · 권한 · 외부 연동이 없는 단순 화면에 억지로 채우지 않음
- 원칙 2: 숫자는 **출발점이지 규칙이 아님**. 회사 conventions · 디자인 시스템 · 페르소나에 정해진 기준이 있으면 그것이 우선
- 출처: 출처별 반영 범위는 [sources.md](sources.md)

## 구조

```
checklists/   역할별 체크리스트. 작업마다 자기 역할 파일을 읽는다 (짧게)
topics/       주제별 개념 문서. 그 주제를 다루는 작업일 때만 읽는다 (원리 · 이유 · 숫자 · 예외)
sources.md    출처 장부 (어디서 무엇을 반영했는지)
```

## 모든 역할 공통 원칙

1. **기준은 문서** — 기획서 · 정책 · 상태 정의가 기준. 문서끼리 다르면 진행 전에 질문. 변경은 말이 아니라 기록으로
2. **정상 · 예외 · 경계값 세 벌** — 기능마다 세 가지를 붙이면 테스트 목록이 됨
3. **기본 화면에서 멈추지 않기** — 누른 뒤 · 기다리는 동안 · 끝난 뒤 · 실패 · 빈 상태까지
4. **화면만 보지 않기** — 화면 → API 응답 → 데이터 순으로 대조. 최종 기준은 저장된 데이터
5. **권한은 화면이 아니라 요청에서** — 버튼을 숨겨도 주소 · API로 직접 들어오면 막혀야 함
6. **비정상 상황이 버그의 집** — 연타 · 네트워크 끊김 · 중단 후 복귀 · 긴 텍스트 · 빈 값 · 뒤로 가기 · 외부 앱 왕복
7. **이름만 말고 동작 · 기준값까지** — 개발자가 추측해야 할 부분을 줄이는 것도 설계
8. **사실로 말하기** — 감정 없이 근거로. 적은 버그지 사람이 아님

## 새 지식 반영 (쌓는 규칙)

1. **사람용 학습노트를 먼저 갱신**하고, 거기서 크루에 필요한 것만 거른다. 노트를 통째로 옮기지 않는다
2. **역할은 "그 지식으로 판단하는 역할"** 기준으로 정한다. 주제가 아니라 결정하는 사람
3. **원리 · 이유 · 숫자는 `topics/`에 주제별로**, 확인 항목은 `checklists/`에 한 줄로. 체크리스트 줄에는 근거 개념 문서와 장을 단다
4. **붙이지 말고 합친다.** 같은 내용이 이미 있으면 기존 줄을 다듬는다. 출처끼리 엇갈리면 근거가 분명한 쪽을 남기고 이유를 적는다
5. **분량 상한**: 체크리스트 파일 150줄, 개념 문서 200줄. 넘으면 묶어서 줄인다
6. **"규칙 아님" 단서까지 옮긴다.** 출처가 "출발점일 뿐"이라고 한 숫자는 그 단서를 지우지 않는다
7. 정말 모든 기능에 필요한 것만 에이전트 문서 규칙으로 올린다
8. 반영한 출처 · 영상 ID · 기준일을 [sources.md](sources.md)에 적는다. 다음 업데이트 확인은 이 목록과 비교한다
