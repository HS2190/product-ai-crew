# Engineer 체크리스트 — mock이라도 실제처럼 동작해야 하는 지점

크루 Engineer는 백엔드 없이 mock 데이터로 구현한다. 그래도 아래는 실제 서비스처럼 동작하게 만든다. 원리 · 이유는 줄 끝의 개념 문서(`../topics/`)에 있다.

## 1. 중복 요청

- 데이터를 만들거나 바꾸는 버튼은 처리 중 비활성 → 연타해도 요청 1번
- 확인: 버튼을 빠르게 두 번 눌러 생성 건수가 1인지

## 2. 권한은 요청 단계에서

- 버튼 숨김으로 끝내지 않기. 데이터 접근 함수 · 라우트 가드에서도 막기
- 확인: 권한 없는 화면 주소를 직접 입력 → 막힘 / 남의 글 id로 수정 · 삭제 시도 → 거부

## 3. 없는 대상 · 실패

- 잘못된 id 라우트, 요청 실패(mock에서 실패 분기) → 빈 화면 · 무한 로딩 대신 디자인의 error 상태
- 삭제 후 뒤로 가기로 재진입 → 없는 대상 안내
- mock 실패 분기는 상태 코드별로(401 · 403 · 404 · 5xx) 화면이 다르게 (`api-http.md` 2장)

## 4. 입력 유지

- 작성 중 입력값이 화면 회전 · 탭 이동 · 뒤로 갔다 오기로 사라지지 않게 (스펙이 초기화로 정한 경우 제외)
- 세션 만료 후 저장 시 작성 내용 보존

## 5. 반영 일치

- 생성 · 수정 · 삭제 후 목록 · 상세 · 개수 · 검색 결과에 모두 반영
- 목록만 그대로면 캐시 · 화면 갱신 문제

## 6. 상태 구현

- 누름(프레스드) 반응과 처리 결과를 따로 구현. 눌렸다고 성공 안내를 띄우지 않기 (`states.md` 1장)
- 진행률을 실제로 알 수 없는 작업에 임의의 퍼센트를 넣지 않기 (`states.md` 3장)
- 숫자 표기 기준값(9,999+) · 빈 상태 표시 · 최소 · 최대는 스펙 값 그대로. 스펙에 없으면 `implementation_notes`에 정한 값을 남김
- 말줄임 · 최대 줄 수를 스펙대로

## 7. 크기 · 글자

- 디자인 수치(1배수)를 DP · PT로, 글자는 사용자 설정을 따르는 단위로 옮김 (`size-units.md` 4장)
- 큰 글자 설정에서 버튼 · 카드가 같이 늘어나 잘리지 않음 (`size-units.md` 6장)
- 아이콘은 벡터 또는 배수 파일 중 정한 형식으로 (`size-units.md` 2장)
- 회사 코드 토큰 파일이 있으면 그 토큰만 사용

## 8. 데이터 형식

- 숫자와 문자열(`12000` vs `"12000"`), `null` · 빈 문자열 · 키 없음을 구분해 다루고, 각각 화면이 어떻게 보이는지 스펙과 맞춤 (`api-http.md` 3장)
- 지원 브라우저 · OS 범위를 `implementation_notes`에 적음 (`platforms.md`)
