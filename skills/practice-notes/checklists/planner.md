# 기획자 체크리스트 — 기획 단계에서 막을 예외

해당하는 기능에만 정의한다. 해당 없으면 쓰지 않는다. 원리 · 이유는 줄 끝의 개념 문서(`../topics/`)에 있다.

## 1. 기준값은 숫자 + 경계

- "일정 금액 이상" 금지 → "20,000원 이상"
- 경계에서 결과 확정: 19,999원(불가) · 20,000원(가능)
- 길이 규칙도 같음: "8~16자" → 7 · 8 · 16 · 17자 결과
- 조건이 겹치면 결정 테이블로 조합 (예: 회원 여부 × 쿠폰 만료 여부 → 4가지 결과)
- 상태가 바뀌는 기능은 상태 전이 규칙 (예: 배송 중에는 취소 불가)

## 2. 권한 매트릭스

사용자 유형이 둘 이상이면 표로 정리한다. 칸 하나 = 테스트 하나.

| 기능 \ 유형 | 비로그인 | 일반 회원 | VIP |
|---|---|---|---|
| 상품 조회 | 가능 | 가능 | 가능 |
| 주문 | 불가 → 로그인 화면 | 가능 | 가능 |
| VIP 쿠폰 | 불가 (숨김) | 불가 (숨김) | 가능 |

- 불가일 때 막는 방식까지: 숨김 / 비활성 / 누르면 로그인 화면 이동
- 조건부 칸은 경계: 등급이 바뀌는 순간 기존 쿠폰 · 혜택은 어떻게 되나
- 남의 데이터(글 · 주문 · 정보)는 주소의 번호만 바꿔 들어와도 막혀야 함

## 3. 중복 실행

- 결제 · 등록 · 신청 · 저장처럼 데이터를 만드는 버튼: 연타 · 느린 네트워크에서도 1건만
- 처리 방식 명시: 처리 중 버튼 비활성 + 로딩 표시, 완료 후 이동 화면

## 4. 앱 밖에 나갔다 돌아오기

| 구간 | 정할 것 |
|---|---|
| 간편로그인 (카카오 · 네이버 · 애플) | 앱 설치 / 미설치 두 경로, 동의 화면 취소 · 뒤로 가기 시 돌아올 화면, 선택 동의 거부로 이메일이 비어도 가입되는지, 애플 이메일 가리기 주소 처리, 애플은 이름 · 이메일을 첫 가입 때만 줌 → 그때 저장, 일반 가입 이메일과 같은 계정이면 새 계정 vs 연결 |
| 결제 (인앱 결제 앱 / 웹뷰 결제창) | 결제 앱 미설치 시 스토어 안내, 결제 중 앱 종료 시 결과 수신, 웹뷰 닫기 · 뒤로 가기, 서버 결과와 화면 결과 일치 |
| 딥링크 (푸시 · 문자 · 메신저 · 메일) | 앱 설치 시 정확한 화면(번호까지), 미설치 시 스토어 · 웹 → 설치 후 원래 화면(지연 딥링크), 로그인 풀림 → 로그인 후 원래 화면, 없는 번호 → 안내 화면, 진입 후 뒤로 가기 |
| 권한 팝업 (카메라 · 알림 · 위치) | 거부 시 안내, '한 번만 허용' 후 다음 요청, Android 13 이상 / 미만 알림 권한 차이 |

- 화면마다 네이티브인지 웹뷰인지 명시 (웹뷰는 앱 업데이트 없이 수정 반영, 뒤로 가기 · 로그인 유지 · 네이티브와 데이터 전달 확인 필요) (`platforms.md` 2장)

## 5. 확인 후 값 변경

- 인증 · 검증을 마친 값(휴대폰 번호 · 이메일)을 다시 고치면 인증 상태 초기화 여부
- 예: 휴대폰 인증 완료 후 번호 수정 → 인증 완료가 남으면 남의 번호로 가입 가능

## 6. 연결 데이터

- 지우면 딸린 데이터는? (글 삭제 → 댓글 · 첨부 · 검색 결과 · 개수)
- 삭제 확인 창 유무

## 7. 문서끼리 맞추기

- PRD · 정책 · 기능 명세 · 화면 기획에서 같은 규칙(쿠폰 개수 · 기준 금액)이 같은지
- 변경 이력 남기기 — 바뀐 화면부터 다음 단계가 확인함

## 8. 출시 · 운영 상황

기존 서비스에 붙는 기능이거나 앱 배포가 있을 때만.

- 서버 점검 중 진입: 점검 화면에 보여 줄 것(점검 시간 · 다음 행동)
- 강제 업데이트: 막을 버전 기준(예: 3.5.0 미만), 안내 후 스토어 이동, 나중에 하기 허용 여부
- 앱 출시 일정에는 스토어 심사 기간 포함
- 지표를 보는 기능이면 단계마다 남길 이벤트를 정함 (퍼널: 상품 → 장바구니 → 결제 단계별 이벤트). A/B 테스트가 있으면 그룹별 화면을 각각 정의

## 9. 화면이 대응해야 할 정책 기준값

케이스는 정책을 낳는다. 화면이 달라지는 지점마다 숫자를 정한다. (`states.md` 5장)

- 최댓값 · 최솟값: 수량(재고 · 구매 제한), 입력 개수, 글자 수
- 반복 횟수: 비밀번호 오류 몇 번째부터 비밀번호 찾기 안내 · 잠금
- 표시가 바뀌는 값: 리뷰 수 9,999+ 같은 축약 기준
- 빈 상태 종료 조건: '신규' 표시를 리뷰 몇 개 · 며칠 뒤에 별점으로 바꿀지
- 상태 목록과 바뀌는 조건을 기능 명세에 적는다(처음 · 불러오는 중 · 빈 결과 · 오류)

## 10. 흐름

(`flows.md`)

- User Flow는 목적지(끝낼 일)부터 정하고, 시작점이 여러 개면 각각 그린다(검색 · 카테고리 · 추천 · 푸시)
- 갈림(로그인 요구 · 권한)과 뒤로 돌아왔을 때의 흐름을 적었다
- 기능 · 섹션마다 넣은 이유 한 줄. 다른 서비스에 있다는 건 이유가 아님
- 입력이 많은 흐름은 꼭 필요한 항목부터 줄였다
