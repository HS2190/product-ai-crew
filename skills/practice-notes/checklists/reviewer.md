# Reviewer 체크리스트 — 단계별로 이 스킬에서 볼 것

Reviewer는 각 역할 체크리스트를 그 역할 검수 때 쓴다. 아래는 단계별로 특히 놓치기 쉬운 것만 모은 것이다. **해당하는 기능에만** 요구하고, 해당 없는 기능에 억지로 채우게 하지 않는다. 회사 conventions · 디자인 시스템과 다르면 회사 기준이 우선이다.

| 단계 | 볼 것 | 근거 |
|---|---|---|
| 기획자 | 기준값의 숫자 · 경계, 권한 매트릭스, 중복 실행, 앱 밖 복귀, 인증 후 값 변경 | `planner.md` 1~5장 |
| 기획자 | 화면이 대응할 정책 기준값(최대 · 반복 횟수 · 표시 기준 · 빈 상태 종료 조건), 상태 목록 | `planner.md` 9장, `../topics/states.md` |
| 기획자 | 목적지 · 시작점별 흐름, 갈림 · 뒤로 가기, 기능마다 이유 | `planner.md` 10장, `../topics/flows.md` |
| UX 라이터 | 레이블 vs 플레이스홀더, 오류 원인 + 고치는 법, 반복 오류 안내, 비활성 이유, 빈 상태 · 없는 대상의 다음 행동 | `ux-writer.md` |
| 디자이너 | 긴 문구 · 큰 숫자 · 빈 값 · 큰 글씨 · 최소 폭 상태를 대표 화면에 보여 줬는가 | `designer.md` 1장 |
| 디자이너 | 버튼 · 입력 · 로딩 · 빈 상태가 빠지지 않았는가, 누름과 성공이 구분됐는가 | `designer.md` 2장 |
| 디자이너 | 컴포넌트 스펙에 동작 · 상태 · 기준값이 있는가, 모양이 같은데 동작이 다른 요소가 없는가 | `designer.md` 3장, `../topics/components.md` |
| 디자이너 | 1배수 기준 · 4 · 8 단위 · 글자 단계, 같은 역할 요소가 화면마다 다르지 않은가, 예외에 이유 | `designer.md` 4장, `../topics/size-units.md`, `../topics/typography.md` |
| Engineer | 연타 시 요청 1번, 주소 직접 입력 시 권한 차단, 잘못된 id · 요청 실패 시 error 상태, 입력 유지 | `engineer.md` 1~4장 |
| Engineer | 누름 반응과 처리 결과 분리, 지어낸 진행률 없음, 기준값을 스펙대로, 큰 글자에서 안 잘림 | `engineer.md` 6 · 7장 |
| QA | 비정상 상황 · 상태 · OS · 브라우저를 해당하는 만큼 시도했는가, 버그와 「기획 확인」 분리 | `qa.md` |

- 판정 메모에는 어느 항목이 왜 빠졌는지 근거 파일과 장을 함께 적는다
