# API · HTTP · 캐시 (상태 코드 · JSON · 화면 vs 서버)

- 언제 읽나: mock 응답을 설계하거나 실제 API에 붙일 때(Engineer), 오류 상태 화면을 정할 때(기획자 · 디자이너), 버그 원인을 좁힐 때(QA)
- 원칙: 크루 Engineer는 백엔드 없이 mock으로 구현한다. 그래도 **응답 모양과 실패 분기는 실제처럼** 설계해야 실제 연동 때 화면이 버틴다

## 핵심

1. 상태 코드 **4xx는 요청 쪽, 5xx는 서버 쪽** 문제다. 화면은 코드별로 다른 안내가 필요하다
2. JSON에서 `12000`과 `"12000"`, `null` · `""` · 키 없음은 **서로 다른 값**이다. 화면이 각각 어떻게 보이는지 정한다
3. 고쳤는데 화면이 그대로면 **캐시 → 배포 버전** 순으로 의심한다

## 1. 동작별 메서드와 응답

| 동작 | 메서드 | 성공 | 주요 실패 |
|---|---|---|---|
| 생성 | POST | 201 (또는 200) | 400 형식 오류 · 409 중복 |
| 조회 | GET | 200 | 404 없음 |
| 수정 | PATCH(부분) / PUT(전체) | 200 · 204 | 403 권한 없음 |
| 삭제 | DELETE | 204 · 200 | 404 · 410 |

- 생성 · 수정 · 삭제 뒤에는 목록 · 상세 · 개수 · 검색 결과에 모두 반영돼야 한다. 목록만 그대로면 캐시 · 화면 갱신 문제

## 2. 상태 코드와 화면

| 코드 | 뜻 | 화면에서 |
|---|---|---|
| 400 | 요청 내용이 잘못됨(필수값 누락 · 형식 오류) | 어느 칸이 왜 틀렸는지 |
| 401 | 로그인 안 됨 · 만료 | 로그인 화면으로, 작성 중 내용은 보존 |
| 403 | 로그인은 됐지만 권한 없음(보안 장비 차단도 403) | 권한 없음 안내, 버튼 숨김만으로 끝내지 않기 |
| 404 | 대상 없음(삭제된 글 · 잘못된 주소) | 없는 대상 안내 + 다음 행동 |
| 409 | 중복 · 충돌 | 이미 있음 안내 |
| 429 | 짧은 시간에 요청 과다 | 잠시 후 다시 시도 |
| 500 | 서버 내부 오류 | 일시적 오류 안내 + 다시 시도 |
| 502 | 중간 서버가 뒤쪽 서버에게서 잘못된 응답을 받음 | 500과 같은 안내 |
| 503 | 점검 · 과부하 | 점검 화면 또는 잠시 후 시도 |
| 504 | 중간 서버가 응답을 기다리다 시간 초과 | 다시 시도, 중복 처리 여부 확인 |

- 버그 리포트에는 상태 코드와 함께 요청 주소 · 응답 본문 · 발생 시간. 5xx는 서버 로그를 찾아야 해서 시간이 특히 중요

## 3. JSON 읽기

- 기본은 키와 값. 키는 큰따옴표, 콜론 뒤에 값
- 값의 종류: 문자열 · 숫자 · 참 / 거짓 · null · 객체(`{}`, 여러 정보를 하나로) · 배열(`[]`, 같은 모양 여러 개)
- 안쪽 값은 경로로 찾는다: `items[0].price`
- 함정: 숫자 `12000`과 문자열 `"12000"`은 다르다(정렬 · 합계가 틀어짐). `null` · 빈 문자열 · 키 없음도 각각 화면이 어떻게 보이는지 정한다
- 화면 값과 응답 JSON을 비교하면 프론트 문제인지 서버 문제인지 나눌 수 있다

## 4. 캐시 · 쿠키

- 캐시: 한 번 받은 파일을 기기에 저장. 서버는 바뀌었는데 예전 파일을 보여 줄 수 있다
- 쿠키: 사이트가 브라우저에 남기는 작은 정보(로그인 상태 · 설정). 예전 상태로 보이게 만들 수 있다
- 확인 순서
  1. 웹: 강력 새로 고침(윈도우 Ctrl+Shift+R, 맥 Cmd+Shift+R)
  2. 개발자 도구를 연 채 새로 고침 버튼 오른쪽 클릭 → 캐시 비우기 및 강력 새로 고침
  3. 쿠키까지: 애플리케이션 탭 → 사이트 데이터 지우기(로그인도 풀림)
  4. 안드로이드 앱: 설정 → 애플리케이션 → 저장 공간 → 캐시 삭제(데이터 삭제는 로그인까지 지움)
  5. 아이폰 앱: 캐시만 지우는 기본 메뉴 없음 → 앱 안 메뉴 또는 재설치
  6. 그래도 그대로면 캐시가 아니다 → CDN 캐시 → 배포가 실제로 됐는지 버전 확인

## 5. 화면 문제인지 서버 문제인지

| 증상 | 먼저 의심 |
|---|---|
| 같은 요청인데 결과가 들쭉날쭉 | 로드 밸런서 뒤 서버마다 다른 버전 · 설정 |
| 도메인 바꾼 직후 접속 안 됨 | DNS 반영 대기 |
| 브라우저 보안 경고 화면 | SSL 인증서 만료 |
| 사람이 몰릴 때만 느림 · 오류 | 서버 부하, 모니터링의 에러율 · 응답 시간 |
| 지표 숫자가 이상 | 화면보다 이벤트 로그 먼저 |

## 역할별로 쓰는 법

- **Engineer:** mock 응답도 위 메서드 · 상태 코드 표대로 실패 분기를 만든다. 숫자 · 문자열 · null 구분을 지킨다
- **기획자 · 디자이너:** 401 · 403 · 404 · 5xx · 점검마다 보여 줄 화면을 정한다(`states.md` 6장)
- **QA:** 화면 값과 응답을 대조하고, 리포트에 코드 · 주소 · 응답 · 시간을 남긴다
