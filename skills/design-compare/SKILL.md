# design-compare — 시안 비교 · 채택 · 정리

비교판을 그려 고르게 하고, 고른 안을 관련 화면 전체에 반영한 뒤 나머지를 치운다.
요청이 있을 때만 실행 (항상 켜진 자동화 아님).

공통 코드: `scripts/figma-kit.js` 다음에 `scripts/compare-kit.js`를 붙여 `use_figma` code 맨 위에 넣음 (`skillNames: figma-use`).

| 함수 | 하는 일 |
|---|---|
| `compareBoard(기준 노드, { title, basis, options, at })` | 기준 섹션 아래에 '[title] — 시안 비교' 섹션 + 안마다 열(이름 · 추천 · 설명 · 화면 복제 · 좋은 점 · 아쉬운 점). 반환 `columns[i].screens` = 고칠 복제본 |
| `fitBoard(섹션)` | 복제본을 고친 뒤 설명 폭 · 섹션 크기 다시 맞춤 |
| `spotBelow(노드, gap)` | 그 노드가 든 최상위 섹션 아래 빈 자리 |
| `toArchive(노드들, { page, name })` | 페이지 맨 아래 보관 섹션으로 옮김 |

## 1. 비교 준비 (그리기 전)
- 비교 대상 화면 · 상호작용과 기준 화면을 정함. 화면은 **기존 화면 복제 + 그 프로젝트 DS 컴포넌트**로 (직접 새로 그리지 않음)
- 개발된 기능이면 지금 모양(배치 · 위치 · 배경)을 먼저 확인하고 그 모양을 '지금' 기준안으로
- 안 수: '지금'(있으면) + 2~3안. 상호작용이면 **방식이 다른 안**으로 (드롭다운 · 인라인 줄 · 팝업 · 접히는 영역 등). 옆 패널을 기본값으로 쓰지 않음
- 지금 기능은 빼지 않음. 서버에 없는 기능이 필요한 안이면 그 안 아쉬운 점에 '개발 필요 · 무엇'으로
- 추천 1개를 근거와 함께 정함
- 무엇을 비교할지 요청에서 분명하지 않으면 그리기 전에 한 번 묻기

## 2. 비교판 그리기
- 위치: 원본 섹션 **바로 아래** (`spotBelow`). 흐름 · 상태 모음 · 개발 전달 섹션 안에는 넣지 않음
- 이름: 섹션 `[대상] — 시안 비교`, 안 `A안 · 두 줄 요약`처럼 기호 + 핵심 한 마디
- `basis`: 무엇을 비교하는지 · 고르는 기준 한두 줄
- 안마다 `note` 한 줄 + 좋은 점 · 아쉬운 점 2~3줄 개조식. 개발 영향(코드 그대로 / 화면 로직 변경 / 서버 변경)을 아쉬운 점이나 note에
- 모든 안이 **같은 상황**을 보여 줌: 이름 · 시각 · 건수 · 탭 숫자 통일, 복제 원본의 남은 요소 정리. 상태가 갈리는 안이면 빈 · 많음 · 긴 문구 상태 1~2장 추가
- 승인 전이므로 원본 컴포넌트 · DS는 고치지 않음. 비교안 안의 인스턴스에서만 바꿈
- 금지: AI 티 패턴(알약 라벨 · 큰 숫자 카드 · 벤토), 한쪽 색 띠, 작업 메모('채택 후 정식 등록' 등)
- 다 그린 뒤 `fitBoard` → **figma-qa**를 비교 섹션에 실행 → 고친 뒤 섹션 스크린샷으로 확인

## 3. 보고 · 고르기
```
시안 비교: [섹션 이름] ([node id])
- 지금: 한 줄
- A안 · …: 한 줄 (추천)
- B안 · …: 한 줄
추천: A안 — 이유 한 줄
```
- 이어서 AskUserQuestion으로 고르게 함: 추천안을 첫 번째에 '(Recommended)', 그 외 안들, '더 다듬기'. 섞기 · 수정은 '기타'로 받음
- 답이 '더 다듬기' · 수정이면 같은 섹션 안에서 고치고 2~3단계 반복

## 4. 채택
1. **반영 범위 찾기**: 채택안과 같은 컴포넌트 · 같은 패턴 · 같은 문구가 나오는 화면을 파일에서 찾아 목록으로 (흐름 · 상태 모음 · 핵심 화면 · 확인 필요 카드까지)
2. **반영**: 여러 화면에 퍼지는 변경은 원본 컴포넌트(변형 · 속성 추가)를 고쳐 인스턴스로 퍼지게. 공유 DS 라이브러리를 고쳐야 하면 범위를 먼저 보고
3. **흐름에 옮김**: 시안 영역의 채택 화면을 흐름 · 상태 모음 자리로 옮기거나 그 화면에 반영
4. **이름 정리**: 'A안 · …' 같은 비교용 이름을 그 파일의 화면 이름 규칙(S-xx 등)으로
5. **아이콘**이 새로 생겼으면 그 파일 아이콘그라피(DS 아이콘 자리)에 컴포넌트로 등록하고 화면은 그 인스턴스로 교체
6. **개발 전달 뒤**라면: 바뀐 자리에 수정 표시('수정 MM.DD · 내용')를 남기고, 전달 문서(목차 · 개발 확인 항목 · 코드와 다르게 정한 것)를 갱신
7. **나머지 안 삭제 · 비교 섹션 삭제** (기본). 관련 확인 필요 카드도 삭제. 사용자가 남기라고 하면 5단계(보관)
8. 바꾼 범위에 **figma-qa** 실행 → 고침
9. 그 프로젝트 메모리에 채택 결과 한 줄 (무엇을 · 어느 안 · 날짜)

보고:
```
채택: A안 · … → 화면 n개 반영
- 반영: [화면 이름 · id] …
- 정리: 나머지 안 · 비교 섹션 삭제 / 보관
- 남은 것: (개발 확인 · 확인 필요 등, 없으면 생략)
```

## 5. 방향 전환 · 보관
- 비교 결과로 **이미 채택했던 방향을 바꿀 때**는 이전 안을 지우지 않고 `toArchive`로 페이지 맨 아래 보관 섹션에 옮김
- 보관 섹션 이름: `[보관 · 무엇]` (예: `[보관 · 홈 A안]`). 보관 섹션은 흐름 · 개발 전달 · 목차에서 빠짐
- 사용자가 "보관해줘"라고 한 안도 같은 방식

## 체크리스트
- [ ] 비교판이 원본 섹션 바로 아래, 흐름 밖에 있음
- [ ] '지금' + 2~3안, 추천 1개, 안마다 좋은 점 · 아쉬운 점 · 개발 영향
- [ ] 모든 안이 같은 데이터 · 같은 상황
- [ ] 승인 전 원본 컴포넌트 · DS 안 고침
- [ ] figma-qa 0건 + 스크린샷 확인 후 보고, AskUserQuestion으로 고르게 함
- [ ] 채택 후: 관련 화면 전체 반영 · 이름 정리 · 아이콘 등록 · 수정 표시(전달 뒤) · 나머지 삭제 또는 보관 · figma-qa
