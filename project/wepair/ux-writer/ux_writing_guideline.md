## 1. 개요

### 1-1. 이 문서의 목적

이 문서는 위페어 파트너스 앱의 모든 UI 문구를 일관되게 작성하기 위한 기준입니다.
문구 하나가 사용자 신뢰에 직접 영향을 줍니다. 전수조사에서 발견된 116건의 문구 중 35건(30.2%)이 수정이 필요했으며, 가장 많은 오류는 붙여쓰기·맞춤법(51.4%)과 어투 불일치(20.0%)였습니다. 이 가이드라인은 같은 오류가 반복되지 않도록 실무 기준을 정의합니다.

### 1-2. 사용 대상 및 활용 방법

| 역할 | 활용 방법 |
|---|---|
| **PM · 기획자** | 화면 기획서 작성 시 문구 초안을 이 문서 기준으로 작성. 리뷰 시 체크리스트로 활용 |
| **디자이너** | 피그마 화면에 문구를 삽입할 때 컴포넌트별 가이드(3장) 참고. 플레이스홀더·빈상태·에러 메시지 특히 주의 |
| **개발자** | 하드코딩 문구 작성 시 용어 사전(4장) 우선 확인. 서버 에러 메시지 노출 방식도 이 기준 적용 |
| **UX 라이터** | 전수조사 및 리뷰 시 이 문서를 판단 기준으로 사용 |

### 1-3. 브랜드 보이스 & 톤 4원칙

위페어 파트너스는 공업사 업무 담당자가 매일 사용하는 B2B 업무 툴입니다. 아래 4가지 원칙이 모든 문구의 기준입니다.

#### 명확하게 (Clear)

복잡한 상황도 쉽고 간결하게 설명합니다. 사용자가 다음에 무엇을 해야 하는지 바로 알 수 있어야 합니다.

```
❌ 카메라를 사용할 수 있는 권한이 필요합니다.
✅ 사진 촬영을 위해 카메라 접근 권한이 필요해요.
```

#### 친근하게 (Warm but composed)

따뜻하되 가볍지 않게. 과도한 감탄이나 느낌표는 사용하지 않습니다.

```
❌ 위페어 파트너스에 오신걸 환영합니다!
✅ 위페어 파트너스에 오신 걸 환영해요.
```

#### 간결하게 (Concise)

한 문장에 하나의 메시지. 불필요한 수식어와 접속사를 제거합니다.

```
❌ 회원가입을 위한 필수 약관에 모두 동의해주세요.
✅ 필수 약관에 모두 동의해 주세요.
```

#### 능동적으로 (Active)

시스템 관점이 아닌 사용자 행동 중심으로 작성합니다. 수동태를 쓰지 않습니다.

```
❌ 비밀번호 재설정이 완료되었습니다.
✅ 비밀번호를 재설정했어요.
```

## 2. 기본 문체 규칙

### 2-1. 해요체 사용 원칙

전체 서비스에서 `-해요` 체로 통일합니다.

| 금지 어미 | 권장 어미 | 예외 |
|---|---|---|
| `-합니다` / `-입니다` | `-해요` / `-예요` / `-이에요` | 법적 문서 (이용약관, 개인정보처리방침 본문) |
| `-됩니다` / `-되었습니다` | `-됐어요` / `-했어요` | — |
| `-없습니다` / `-있습니다` | `-없어요` / `-있어요` | — |
| `-하십시오` / `-해주십시오` | `-해 주세요` | — |

**예시**

```
❌ 등록된 작업이 없습니다.
✅ 등록된 작업이 없어요.

❌ 비밀번호 재설정이 완료되었습니다.
✅ 비밀번호를 재설정했어요.

❌ 결제 내역이 없습니다.
✅ 아직 결제 내역이 없어요.
```

> **예외 적용 방법:** 법적 문서 본문은 `-합니다` 체를 허용하지만, 해당 화면의 버튼·토스트·에러 메시지는 여전히 `-해요` 체를 사용합니다.

---

### 2-2. 맞춤법·띄어쓰기 핵심 규칙

전수조사에서 가장 많이 발견된 오류 패턴입니다. 아래 규칙만 지켜도 오류의 절반 이상을 막을 수 있습니다.

#### 규칙 1: 명사+명사 조합은 붙이지 않는다

두 개 이상의 명사가 결합된 UI 레이블은 띄어 씁니다.

| ❌ 금지 | ✅ 권장 |
|---|---|
| 작업검색 | 작업 검색 |
| 작업완료 | 작업 완료 |
| 결제내역 | 결제 내역 |
| 정산내역 | 정산 내역 |
| 기본정보 | 기본 정보 |
| 보험여부 | 보험 여부 |
| 수리내역 | 수리 내역 |
| 회원탈퇴 | 회원 탈퇴 |
| 계정확인 | 계정 확인 |

> **예외:** 고유명사·브랜드명·약어처럼 하나의 단어로 굳어진 경우는 붙여 씁니다. (예: `위페어파트너스` → 브랜드명이지만 `위페어 파트너스`가 표준)

#### 규칙 2: "중(中)"은 앞말과 띄어 쓴다

진행·상태를 나타내는 "중"은 명사이므로 앞말과 띄어 씁니다.

```
❌ 작업중
✅ 작업 중

❌ 처리중
✅ 처리 중
```

#### 규칙 3: "해 주세요"는 반드시 띄어 쓴다

보조 동사 "주다"는 앞 용언과 띄어 씁니다.

```
❌ 확인해주세요 / 입력해주세요 / 동의해주세요
✅ 확인해 주세요 / 입력해 주세요 / 동의해 주세요
```

#### 규칙 4: 조사 앞 띄어쓰기 주의

```
❌ 아이디 입니다 → 아이디예요 (조사 '이다' 앞 불필요한 공백)
❌ 일치 하지 않아요 → 일치하지 않아요 (용언 내부 공백)
```

---

### 2-3. 번역투 표현 제거

영어나 일본어를 직역한 듯한 표현은 자연스러운 한국어로 바꿉니다.

| ❌ 번역투 | ✅ 자연스러운 표현 |
|---|---|
| `~의 경우` | `~하면`, `~할 때`, `~하셨나요?` |
| `~을 통해` | `~로`, `~에서` |
| `~에 대한` | `~` (생략 가능한 경우 많음) |
| `~을 진행하다` | `~하다` |
| `본 서비스`, `본 페이지` | `이 서비스`, `이 페이지` |
| `귀하` | 주어 생략 또는 `고객사` |
| `정상적으로` | 삭제 (불필요한 부사) |
| `성공적으로` | 삭제 또는 완료 사실만 서술 |

**실제 수정 사례**

```
❌ 아이디를 분실하신 경우 위페어 파트너스 고객센터 (1660-4945)로 문의해 주세요.
✅ 아이디를 잊으셨나요? 고객센터(1660-4945)로 문의해 주세요.
```

---

### 2-4. 높임말 과용 금지

시스템의 동작을 설명하거나 정보를 전달할 때 불필요한 높임 표현을 사용하지 않습니다. 높임말은 사용자에게 직접 요청하거나 안내할 때만 씁니다.

```
❌ [연락처]로 보내드린 인증번호 6자리를 입력해 주세요.
   ("보내드린" → 시스템이 발송한 것이므로 높임 불필요)
✅ [연락처]로 보낸 인증번호 6자리를 입력해 주세요.

❌ 새로운 비밀번호를 입력해주세요.
   ("새로운" → 불필요한 형용사)
✅ 새 비밀번호를 입력해 주세요.
```

## 3. 컴포넌트별 문구 가이드

### 3-1. 버튼 (Button)

#### 기본 원칙

- 동작을 명확히 나타내는 동사를 사용합니다.
- 권장 길이: 2~5자 (최대 8자)
- 취소 버튼은 항상 `취소` 고정

#### 유형별 규칙

**이동 버튼** — 어디로 이동하는지 방향을 포함합니다.

| ❌ 금지 | ✅ 권장 | 이유 |
|---|---|---|
| 다음 | 다음으로 | 이동 방향 불명확 |
| 이전 | 이전으로 | — |
| 홈 | 홈으로 | — |

**허용/권한 버튼** — 무엇을 허용하는지 명시합니다.

| ❌ 금지 | ✅ 권장 | 이유 |
|---|---|---|
| 계속 | 권한 허용하기 | 무엇을 허용하는지 불명확 |
| 확인 | 카메라 허용하기 / 알림 허용하기 | 동작 불명확 |

**확인/실행 버튼** — 행동이 무엇인지 동사로 명확히 합니다.

| ❌ 금지 | ✅ 권장 | 이유 |
|---|---|---|
| OK | 저장하기 / 삭제하기 / 전송하기 | 동작 불명확 |
| 중복확인 | 중복 확인 | 띄어쓰기 오류 |
| 확인 (단독) | 맥락에 맞는 동사 | 모호함 |

---

### 3-2. 플레이스홀더 (Placeholder)

#### 기본 원칙

- 입력 형식 또는 예시를 반드시 표기합니다.
- 레이블 단어 단독 사용은 금지합니다. (레이블과 동일한 내용 반복 금지)
- 형식이 있는 필드는 형식을 보여주고, 자유 입력 필드는 예시를 보여줍니다.

#### 유형별 작성법

| 필드 유형 | ❌ 금지 | ✅ 권장 |
|---|---|---|
| 아이디 | 아이디 | `예) wepair` |
| 비밀번호 | 비밀번호 | `영문+숫자+특수문자` |
| 연락처 | 담당자 연락처 | `010-0000-0000` |
| 이메일 | 이메일을 입력하세요 | `example@company.com` |
| 사업자번호 | 사업자 등록번호 | `000-00-00000` |
| 검색창 | 검색 | `차량번호 또는 고객명 검색` |

> **원칙:** 레이블이 이미 필드 이름을 알려주고 있으므로, 플레이스홀더는 "어떻게 입력하면 되는지"를 알려주는 역할에만 집중합니다.

---

### 3-3. 레이블 (Label)

#### 기본 원칙

- 명사+명사 조합은 반드시 띄어 씁니다. (→ 2-2 규칙 1 참고)
- 동일 화면, 동일 플로우 내에서 같은 개념은 같은 용어를 씁니다.
- 섹션 헤더와 해당 섹션 내 입력 레이블의 용어는 반드시 일치해야 합니다.

**용어 일관성 오류 사례**

```
❌ 섹션 헤더: "수리 내역" / 입력 레이블: "수리내역"
✅ 두 곳 모두: "수리 내역"

❌ 회원가입 화면: "서비스 이용약관" / 설정 화면: "서비스 이용 약관"
✅ 전체 표준: "서비스 이용약관" (용어 사전 우선)
```

### 3-4. 에러 메시지 (Error Message)

#### 기본 원칙

에러 메시지는 반드시 두 가지를 포함해야 합니다.

1. **무엇이 잘못됐는지** — 원인을 구체적으로
2. **어떻게 해결하는지** — 다음 행동을 안내

사용자를 탓하거나 비난하는 표현은 절대 금지합니다.

#### 작성 공식

```
[무엇이 문제인지] + [어떻게 하면 되는지]
```

#### 예시

| ❌ 금지 | ✅ 권장 | 이유 |
|---|---|---|
| 로그인 정보가 일치하지 않습니다. 정보를 확인해주세요. | 아이디 또는 비밀번호를 확인해 주세요. | 수동태 제거, 구체적 항목 명시, 띄어쓰기 교정 |
| 비밀번호가 일치 하지 않습니다. 다시 입력해주세요. | 비밀번호가 일치하지 않아요. 다시 입력해 주세요. | 맞춤법, 해요체 통일 |
| 잘못된 입력입니다 | 이메일 형식을 확인해 주세요 | 원인 특정, 해결 방법 안내 |
| 필수 항목입니다 | 이름을 입력해야 다음으로 넘어갈 수 있어요 | 어떤 항목인지, 왜 필요한지 명시 |

#### 토스트 에러 제목

에러 상황의 토스트 제목은 상태를 명확히 표시합니다. 중립적인 표현은 금지합니다.

```
❌ 로그인 정보 확인     (에러인데 중립적 표현)
✅ 로그인 실패          (상태 명확히 명시)

❌ 처리 중              (결과가 불분명)
✅ 저장 실패            (무엇이 실패했는지 명확히)
```

---

### 3-5. 빈상태 (Empty State)

#### 기본 원칙

빈상태 메시지는 반드시 두 가지를 포함해야 합니다.

1. **왜 비어있는지** — 현재 상태 설명
2. **무엇을 하면 되는지** — 다음 행동 안내

단순히 "없습니다"로 끝나는 메시지는 사용 금지합니다.

#### 작성 공식

```
[왜 비어있는지] + [무엇을 하면 채워지는지]
```

#### 예시

| ❌ 금지 | ✅ 권장 | 이유 |
|---|---|---|
| 등록된 작업이 없습니다. | 등록된 작업이 없어요. 입고등록에서 차량을 추가해 보세요. | 해요체 통일 + 다음 행동 안내 |
| 결제 내역이 없습니다. | 아직 결제 내역이 없어요. | 해요체 통일 ("아직"으로 임시 상태 표현) |
| 출고일 미지정 | 출고일을 선택해 주세요. | 상태 나열이 아닌 행동 요청으로 전환 |
| 데이터가 없습니다 | 아직 등록된 항목이 없어요. 새 항목을 추가해 보세요. | 다음 행동 안내 포함 |

> **"아직"의 활용:** 사용자가 아직 아무것도 하지 않은 상태는 `아직 ~이 없어요`로 시작해 데이터가 없는 것이 이상한 상태가 아님을 암시합니다.

### 3-6. 알림 / 토스트 (Notification / Toast)

#### 기본 원칙

- 간결하게: 1~2문장 이내
- 과도한 감탄 표현 금지: `!!!`, `🎉`, `완벽해요!` 등
- 성공/실패 상태를 제목에서 명확히 구분
- 능동태 사용 (수동태 금지)

#### 상태별 작성법

**성공 토스트**

```
❌ 비밀번호 재설정이 완료되었습니다.
✅ 비밀번호를 재설정했어요.

❌ 귀하의 요청이 정상적으로 접수되었습니다.
✅ 요청을 접수했어요.

❌ 완료되었습니다!!!  🎉
✅ 저장했어요.
```

**정보/안내 토스트**

```
❌ 사용 가능한 아이디 입니다.
✅ 사용할 수 있는 아이디예요.
```

**실패/에러 토스트** → 3-4 에러 메시지 규칙 동일 적용

### 4-2. 금지 표현 목록

## 5. 적용 예시

전수조사에서 수정된 대표 사례를 유형별로 Before / After 형태로 정리합니다.

---

### 5-1. 에러 메시지 — 원인 + 해결 방법 포함

**Before**
> 로그인 정보가 일치하지 않습니다. 정보를 확인해주세요.

**After**
> 아이디 또는 비밀번호를 확인해 주세요.

**수정 포인트**
- 수동태("일치하지 않습니다") → 능동형("확인해 주세요")
- 어떤 정보를 확인해야 하는지 구체화("아이디 또는 비밀번호")
- "해주세요" → "해 주세요" 띄어쓰기 교정

---

**Before**
> 로그인 정보 확인 *(토스트 제목)*

**After**
> 로그인 실패

**수정 포인트**
- 에러 상황에서 중립적 표현 사용 → 상태를 명확히 표기

---

### 5-2. 빈상태 — 다음 행동 안내 포함

**Before**
> 출고일 미지정

**After**
> 출고일을 선택해 주세요.

**수정 포인트**
- 상태 나열(명사형) → 행동 요청(동사형)으로 전환
- 사용자가 무엇을 해야 하는지 명확히 안내

---

**Before**
> 입고등록에서 차량을 추가하면 이곳에서 진행 상황을 관리할 수 있습니다.

**After**
> 입고등록에서 차량을 추가하면 진행 상황을 이곳에서 확인할 수 있어요.

**수정 포인트**
- `-있습니다` → `-있어요` 해요체 통일

---

### 5-3. 버튼 — 동작 명확화

**Before**
> 다음

**After**
> 다음으로

**수정 포인트**
- 이동 버튼은 방향(으로)을 포함해 이동임을 명확히 표현

---

**Before**
> 계속

**After**
> 권한 허용하기

**수정 포인트**
- 카메라 권한 요청 화면에서 "계속"은 무엇을 하는지 불분명
- 버튼이 어떤 행동을 수행하는지 구체적으로 명시

---

### 5-4. 플레이스홀더 — 형식 예시 필수

**Before**
> 아이디

**After**
> 예) wepair

**수정 포인트**
- 레이블과 동일한 단어 반복 금지
- 입력 형식·예시를 제공해 사용자 입력 오류를 사전에 방지

---

**Before**
> 담당자 연락처

**After**
> 010-0000-0000

**수정 포인트**
- 입력 형식(하이픈 구분 여부)을 명확히 제시

---

### 5-5. 번역투 제거

**Before**
> 아이디를 분실하신 경우 위페어 파트너스 고객센터 (1660-4945)로 문의해 주세요.

**After**
> 아이디를 잊으셨나요? 고객센터(1660-4945)로 문의해 주세요.

**수정 포인트**
- "~의 경우" → 의문문으로 전환해 자연스럽고 친근하게
- "분실하신" → "잊으셨나요?" 구어체로 변경
- "위페어 파트너스 고객센터" → "고객센터" (문맥상 자명하면 서비스명 생략)

---

### 5-6. 알림/토스트 — 수동태 제거 + 해요체 통일

**Before**
> 비밀번호 재설정이 완료되었습니다.

**After**
> 비밀번호를 재설정했어요.

**수정 포인트**
- 수동태("~이 완료되었습니다") → 능동태("~했어요")
- `-습니다` → `-해요` 체 통일

---

**Before**
> 사용 가능한 아이디 입니다.

**After**
> 사용할 수 있는 아이디예요.

**수정 포인트**
- "아이디 입니다" → "아이디예요" 조사 붙여쓰기 교정
- `-입니다` → `-예요` 해요체 통일
