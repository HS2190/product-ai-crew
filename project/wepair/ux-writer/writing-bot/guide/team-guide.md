# 팀 가이드 — 위페어 파트너스 UX Writing 봇 사용법

> 이 문서는 UX Writing 봇을 처음 쓰는 팀원을 위한 안내서입니다.

---

## 이 봇이 뭔가요?

**위페어 파트너스 앱의 UI 문구를 검수·생성·개선하는 UX 라이터 역할의 AI 봇입니다.**

피그마 화면을 보고 문구를 추출하거나, 작성한 문구가 가이드라인에 맞는지 확인하거나, 새 화면의 문구 초안을 잡을 때 사용합니다.

---

## 언제 쓰면 좋아요?

### 상황 1 — 기획서에 문구를 넣어야 할 때

새 화면을 기획하면서 버튼·에러 메시지·빈상태 문구를 작성해야 할 때 봇에게 초안을 요청하세요. 가이드라인에 맞는 초안을 바로 받을 수 있습니다.

### 상황 2 — 피그마 문구가 가이드라인에 맞는지 확인하고 싶을 때

화면 단위로 문구를 붙여넣거나 피그마 링크를 공유하면, 전수조사 형식으로 결과를 받을 수 있습니다.

### 상황 3 — 개발 중 에러 메시지나 토스트 문구가 필요할 때

서버 에러, 권한 요청, 빈상태 등 개발 중 필요한 문구를 실시간으로 요청할 수 있습니다.

---

## 사용 방법

### 문구 검수

작성한 문구가 가이드라인에 맞는지 확인할 때 사용합니다.

**요청 형식:**
```
아래 문구를 검수해 줘.
화면: [화면명]
문구: [원문 문구]
```

**출력 결과:**
- 유형 분류 (A~F)
- 수정안
- 수정 이유

---

### 문구 생성

새 화면이나 컴포넌트의 문구 초안을 받을 때 사용합니다.

**요청 형식:**
```
아래 상황에 맞는 문구를 작성해 줘.
화면: [화면명]
컴포넌트: [버튼 / 에러 / 빈상태 / 토스트 등]
상황: [어떤 상황인지 설명]
```

**예시:**
```
화면: 작업 상세
컴포넌트: 빈상태
상황: 사진이 아직 업로드되지 않은 상태
```

---

### 전수조사

피그마 화면 전체의 문구를 한 번에 검토할 때 사용합니다.

**요청 형식:**
```
아래 피그마 화면의 문구를 전수조사해 줘.
[피그마 링크 또는 화면별 문구 목록]
```

**출력 결과:**
- Confluence 마크다운 표 형식
- 화면별 통계 요약
- 유형별 수정 우선순위

---

## 케이스 추가 요청 방법

발견한 새 오류 패턴이나 수정 사례를 케이스로 등록하고 싶을 때:

1. `cases/index.md`에 새 행 추가
2. `cases/wepair-audit-cases.md`에 상세 내용 추가
3. 세션 파일(`sessions/YYYY-MM-DD.md`)에 발견 경위 기록
4. 동일 패턴이 3회 이상 반복되면 `docs/`로 승격 요청

---

## 주의사항

> **최종 판단은 반드시 사람이 합니다.**

- 봇의 제안은 초안입니다. 맥락·브랜드·법적 요건을 함께 고려해야 합니다.
- 법적 문서(이용약관, 개인정보처리방침 본문)는 별도 법무 검토가 필요합니다.
- 새 컴포넌트나 신규 서비스 기능이 추가되면 가이드라인을 먼저 업데이트해야 합니다.
- 봇이 생성한 문구를 그대로 배포하기 전에 반드시 UX 라이터가 최종 검토합니다.
