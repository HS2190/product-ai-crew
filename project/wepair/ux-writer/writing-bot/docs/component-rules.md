# Component Rules — 컴포넌트별 문구 가이드

> 위페어 파트너스의 UI 컴포넌트별 문구 작성 원칙과 금지/권장 표현을 정의합니다.

---

## 버튼 (Button)

### 작성 원칙
- 동작을 명확히 나타내는 **동사**를 사용한다
- 권장 길이: 2~5자 (최대 8자)
- 취소 버튼은 항상 `취소` 고정

### 구조 패턴

| 유형 | 패턴 | 예시 |
|---|---|---|
| 이동 버튼 | `[목적지] + 으로` | 다음으로, 홈으로, 이전으로 |
| 실행 버튼 | `[동작] + 하기` | 저장하기, 삭제하기, 전송하기 |
| 허용 버튼 | `[대상] + 허용하기` | 권한 허용하기, 카메라 허용하기 |
| 취소 버튼 | `취소` 고정 | 취소 |

### 금지 → 대체

| ❌ 금지 | ✅ 대체 | 이유 |
|---|---|---|
| 다음 | 다음으로 | 이동 방향 불명확 |
| 계속 | 권한 허용하기 | 무엇을 하는지 불명확 |
| 확인 (단독) | 맥락에 맞는 동사 | 동작 불명확 |
| OK | 저장하기 / 삭제하기 | 동작 불명확 |
| 중복확인 | 중복 확인 | 붙여쓰기 오류 |
| 회원탈퇴 | 회원 탈퇴 | 붙여쓰기 오류 |

### 예시

```
❌ 다음 / 계속 / OK / 확인
✅ 다음으로 / 권한 허용하기 / 저장하기 / 삭제하기
```

## 메뉴 (Menu / Tab / Navigation)

### 작성 원칙
- 명사형으로 간결하게 작성한다
- 2~4자 권장
- 화면 내 동일 개념은 동일 표기를 사용한다 (탭과 하단 내비게이션 일치)

### 구조 패턴

단어 단독 사용. 동사 불필요.

### 금지 → 대체

| ❌ 금지 | ✅ 대체 | 이유 |
|---|---|---|
| 작업중 | 작업 중 | 띄어쓰기 오류 (진행형 "중" 분리) |
| 작업완료 | 작업 완료 | 붙여쓰기 오류 |
| 결제내역 | 결제 내역 | 붙여쓰기 오류 |
| 정산내역 | 정산 내역 | 붙여쓰기 오류 |

### 예시

```
❌ 작업중 / 작업완료 / 결제내역
✅ 작업 중 / 작업 완료 / 결제 내역
```

## 에러 메시지 (Error)

### 작성 원칙
1. **무엇이 잘못됐는지** — 원인을 구체적으로
2. **어떻게 해결하는지** — 다음 행동을 안내
3. 사용자를 탓하거나 비난하는 표현 절대 금지

### 구조 패턴

```
[무엇이 문제인지] + [어떻게 하면 되는지]
```

### 금지 → 대체

| ❌ 금지 | ✅ 대체 | 이유 |
|---|---|---|
| 잘못된 입력입니다 | 이메일 형식을 확인해 주세요 | 원인 미제공, 사용자 탓 |
| 오류가 발생하였습니다 | 구체적인 에러 상황 설명 | 모호함, 수동태 |
| 필수 항목입니다 | 이름을 입력해야 다음으로 넘어갈 수 있어요 | 어떤 항목인지, 왜 필요한지 미제공 |
| 로그인 정보가 일치하지 않습니다. 정보를 확인해주세요. | 아이디 또는 비밀번호를 확인해 주세요 | 수동태, 구체성 부족, 띄어쓰기 |
| 비밀번호가 일치 하지 않습니다. 다시 입력해주세요. | 비밀번호가 일치하지 않아요. 다시 입력해 주세요 | 띄어쓰기, 해요체 불일치 |

### 예시

```
❌ 잘못된 입력입니다.
❌ 오류가 발생하였습니다.
✅ 이메일 형식을 확인해 주세요.
✅ 아이디 또는 비밀번호를 확인해 주세요.
✅ 비밀번호가 일치하지 않아요. 다시 입력해 주세요.
```

## 토스트 (Toast)

### 작성 원칙
- 1~2문장 이내로 간결하게
- 성공/실패/정보 상태를 **제목**에서 명확히 구분
- 능동태 사용, 수동태 금지
- 과도한 감탄 표현 금지

### 구조 패턴

| 상태 | 제목 패턴 | 본문 패턴 |
|---|---|---|
| 성공 | `[대상]을 [동작]했어요` | 생략 또는 간단한 부연 |
| 실패 | `[대상] 실패` | 원인 + 해결 방법 |
| 정보 | 상태 직접 서술 | 부연 설명 |

### 금지 → 대체

| ❌ 금지 | ✅ 대체 | 이유 |
|---|---|---|
| 로그인 정보 확인 (에러 토스트 제목) | 로그인 실패 | 에러 상황인데 중립적 표현 |
| 비밀번호 재설정이 완료되었습니다 | 비밀번호를 재설정했어요 | 수동태, 해요체 미통일 |
| 귀하의 요청이 정상적으로 접수되었습니다 | 요청을 접수했어요 | 격식체, 불필요한 부사, 수동태 |
| 사용 가능한 아이디 입니다 | 사용할 수 있는 아이디예요 | 맞춤법, 해요체 |

### 예시

```
❌ 완료되었습니다!!! 🎉
❌ 비밀번호 재설정이 완료되었습니다.
✅ 저장했어요.
✅ 비밀번호를 재설정했어요.
```

## 빈상태 (Empty State)

### 작성 원칙
1. **왜 비어있는지** — 현재 상태 설명
2. **무엇을 하면 되는지** — 다음 행동 안내
두 가지를 반드시 포함한다. "없습니다"로만 끝내지 않는다.

### 구조 패턴

```
[왜 비어있는지] + [무엇을 하면 채워지는지]
```

"아직"을 활용해 임시 상태임을 암시한다.

### 금지 → 대체

| ❌ 금지 | ✅ 대체 | 이유 |
|---|---|---|
| 데이터가 없습니다 | 아직 등록된 항목이 없어요. 새 항목을 추가해 보세요 | 해요체, 다음 행동 안내 |
| 등록된 작업이 없습니다 | 등록된 작업이 없어요. 입고등록에서 차량을 추가해 보세요 | 해요체, 다음 행동 안내 |
| 출고일 미지정 | 출고일을 선택해 주세요 | 명사 나열 → 행동 요청으로 전환 |
| 결제 내역이 없습니다 | 아직 결제 내역이 없어요 | 해요체 통일 |

### 예시

```
❌ 데이터가 없습니다.
❌ 출고일 미지정
✅ 아직 등록된 항목이 없어요. 새 항목을 추가해 보세요.
✅ 출고일을 선택해 주세요.
```

## 안내 (Guide / Instruction)

### 작성 원칙
- 불필요한 수식어·접속사 제거
- 한 문장에 하나의 메시지
- 필요한 경우 이유(맥락)도 포함

### 구조 패턴

```
[맥락 또는 이유] + [행동 요청]
```

### 금지 → 대체

| ❌ 금지 | ✅ 대체 | 이유 |
|---|---|---|
| 회원가입을 위한 필수 약관에 모두 동의해주세요 | 필수 약관에 모두 동의해 주세요 | 불필요한 수식어, 띄어쓰기 |
| 새로운 비밀번호를 입력해주세요 | 새 비밀번호를 입력해 주세요 | 불필요한 형용사, 띄어쓰기 |
| 카메라를 사용할 수 있는 권한이 필요합니다 | 사진 촬영을 위해 카메라 접근 권한이 필요해요 | 해요체, 이유 명시 |
| [연락처]로 보내드린 인증번호 6자리를 입력해주세요 | [연락처]로 보낸 인증번호 6자리를 입력해 주세요 | 불필요한 높임, 띄어쓰기 |

### 예시

```
❌ 새로운 비밀번호를 입력해주세요.
❌ 회원가입을 위한 필수 약관에 모두 동의해주세요.
✅ 새 비밀번호를 입력해 주세요.
✅ 필수 약관에 모두 동의해 주세요.
```

## 레이블 (Label)

### 작성 원칙
- 명사+명사 조합은 반드시 띄어 쓴다
- 동일 화면·동일 플로우 내 같은 개념은 같은 용어를 쓴다
- 섹션 헤더와 입력 레이블의 용어를 반드시 일치시킨다

### 구조 패턴

단어 또는 단어+단어 조합. 동사 불필요.

### 금지 → 대체

| ❌ 금지 | ✅ 대체 | 이유 |
|---|---|---|
| 기본정보 | 기본 정보 | 붙여쓰기 오류 |
| 보험여부 | 보험 여부 | 붙여쓰기 오류 |
| 수리내역 | 수리 내역 | 붙여쓰기 오류 (헤더와 불일치) |
| 계정확인 | 계정 확인 | 붙여쓰기 오류 |
| 서비스 이용 약관 (설정) | 서비스 이용약관 | 회원가입 화면과 표기 불일치 |

### 예시

```
❌ 기본정보 / 보험여부 / 수리내역
✅ 기본 정보 / 보험 여부 / 수리 내역
```

## 알림·다이얼로그 (Alert / Dialog)

### 작성 원칙
- 제목: 상황을 명확하게 (성공/실패/확인 요청 구분)
- 본문: 왜 이 알림이 떴는지 + 선택의 결과
- 액션 버튼: 버튼 컴포넌트 가이드 동일 적용

### 구조 패턴

```
제목: [상태/행동] 확인
본문: [상황 설명] + [결과 또는 안내]
버튼: [동사형 확인] / 취소
```

### 예시

```
❌ 제목: 주의 / 버튼: 확인
✅ 제목: 작업을 삭제할까요? / 버튼: 삭제하기 / 취소
```

## 헤더 (App Bar / Page Header)

### 작성 원칙
- 현재 화면이 어디인지 명확히 표현
- 2~6자 이내 권장
- 동사형 금지 (명사형 사용)

### 구조 패턴

`[화면 이름]` 단독 사용.

### 예시

```
❌ 로그인 하기
✅ 로그인

❌ 설정하기
✅ 설정
```
