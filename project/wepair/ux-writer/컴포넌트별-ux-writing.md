## 1. 버튼 (Button)

### 작성 가이드

**원칙**
- 동사 기본형 또는 명사형으로 작성. 2~5자 권장, 최대 8자
- 명사+명사 조합은 반드시 띄어 씀
- 취소 버튼은 항상 `취소` 고정. `아니오`, `닫기`와 혼용 금지
- 느낌표, 물음표 사용 금지
- Primary / Secondary 버튼이 함께 있을 때 Primary가 더 구체적인 동작을 표현해야 함

**구조**
```
[동작] or [명사 + 동작]

Primary   →  구체적인 동작  (예: 입고 등록, 작업 완료, 동의서 발송)
Secondary →  취소 / 닫기 / 다시 찍기
```

**체크리스트**
- [ ] 명사+명사 사이 띄어쓰기 확인 (작업완료 → 작업 완료)
- [ ] "중(中)" 앞 띄어쓰기 확인 (작업중 → 작업 중)
- [ ] 취소 버튼은 `취소` 단어 고정
- [ ] 동작이 명확하게 드러나는가 (`확인` 대신 `저장하기`, `삭제하기`)

**금지 표현**

| 금지 | 이유 | 대체 |
|------|------|------|
| 확인 (단독) | 동작이 모호함 | 저장하기 / 삭제하기 / 발송하기 등 구체적 동사 사용. 단, 에러 다이얼로그 닫기 용도는 `확인` 허용 |
| OK / YES / NO | 영어·딱딱한 표현 | 확인 / 취소 |
| ~해주세요 (버튼) | 버튼은 명령형 불가 | 명사형 또는 동사 기본형 |
| 완료! / 발송! | 느낌표 금지 | 완료 / 발송 |

**예시**

| 상황 | X | O |
|------|---|---|
| 입고 처리 | 입고등록 | 입고 등록 |
| 사진 선택 | 사진선택 | 사진 선택 |
| 직접 입력 전환 | 직접입력 | 직접 입력 |
| 작업 완료 처리 | 작업완료 | 작업 완료 |
| 작업 완료 취소 | 작업완료 취소 | 작업 완료 취소 |
| 목록 이동 | 작업중 목록 이동 | 작업 중 목록으로 이동 |
| 결제 취소 | 결제취소 | 결제 취소 |

## 2. 메뉴 (Menu)

### 작성 가이드

**원칙**
- 명사형 단어로 작성. 동사 기본형 사용 금지 (`탈퇴하기` → `회원 탈퇴`)
- 명사+명사 조합은 띄어 씀
- 탭 바, 사이드 메뉴, 설정 리스트 모두 동일 원칙 적용
- 메뉴 간 용어는 일관성 유지 (결제 내역 / 정산 내역처럼 같은 패턴 사용)

**구조**
```
[명사] or [명사 + 명사]

예: 작업 목록 / 결제 현황 / 공업사 정보 / 회원 탈퇴
```

**체크리스트**
- [ ] 명사+명사 사이 띄어쓰기
- [ ] 동사형(-하기, -하다) 미사용 확인
- [ ] 동일 depth 메뉴 간 표현 패턴 일치 여부

**금지 표현**

| 금지 | 이유 | 대체 |
|------|------|------|
| 회원탈퇴 | 명사 붙여쓰기 | 회원 탈퇴 |
| 탈퇴하기 | 메뉴에 동사형 사용 | 회원 탈퇴 |
| 마이페이지 | 영어 혼용 | 내 정보 / 계정 정보 |

**예시**

| 상황 | X | O |
|------|---|---|
| 탈퇴 메뉴 | 회원탈퇴 | 회원 탈퇴 |
| 정보 메뉴 | 기본정보 | 기본 정보 |
| 내역 메뉴 | 결제내역 | 결제 내역 |

## 3. 에러 (Error Message)

### 작성 가이드

**원칙**
- **원인 + 해결 방법** 두 가지를 반드시 포함
- 사용자를 탓하는 표현 금지
- `-않아요`, `-없어요` 해요체 사용
- 해결 방법이 있을 때는 구체적인 다음 행동을 안내
- 시스템 오류와 사용자 입력 오류를 구분해서 작성

**구조**
```
입력 오류  →  [무엇이] [어떻게] 않아요. [어떻게 하면] 돼요.
시스템 오류 →  [무엇을] 하지 못했어요. [어떻게 해결하면] 돼요.
권한 오류  →  [무엇을] 위해 [어떤 권한]이 필요해요. ([설정 방법])
```

**체크리스트**
- [ ] `-않습니다`, `-불가능합니다` → `-않아요`, `-없어요` 변환
- [ ] 해결 방법이 명시되어 있는가
- [ ] 사용자를 탓하는 표현 없는가 (`잘못된 입력`, `올바르지 않은`)
- [ ] `확인해주세요` → `확인해 주세요` 띄어쓰기

**금지 표현**

| 금지 | 이유 | 대체 |
|------|------|------|
| 잘못된 입력입니다 | 사용자 탓 | [구체적 필드] 형식을 확인해 주세요 |
| 오류가 발생하였습니다 | 모호하고 -합니다 체 | 구체적 상황 + 해결 방법 |
| 필수 항목입니다 | 모호함, 딱딱함 | [항목명]을 입력해야 다음으로 넘어갈 수 있어요 |
| 다시 시도해주세요 | 띄어쓰기 오류 | 다시 시도해 주세요 |
| 불가능합니다 | -합니다 체 | 할 수 없어요 |

**예시**

| 상황 | X | O |
|------|---|---|
| 로그인 실패 | 로그인 정보가 일치하지 않습니다. 정보를 확인해주세요. | 로그인 정보가 일치하지 않아요. 다시 확인해 주세요. |
| 인증 시간 초과 | 인증정보 입력시간이 지났습니다. 인증번호를 재발송 후 다시 입력해주세요. | 인증 정보 입력 시간이 지났어요. 인증번호를 다시 발송하고 입력해 주세요. |
| 파일 없음 | 업로드 한 파일이 존재하지 않습니다. | 업로드된 파일이 없어요. |
| 기간 경과 | 취소 가능일이 경과하여 직접 취소가 불가능 합니다. | 취소 가능일이 지나 직접 취소할 수 없어요. 고객센터(1660-4945)로 문의해 주세요. |

## 4. 토스트 (Toast / Snackbar)

### 작성 가이드

**원칙**
- **능동형 단문** 1문장. 15자 이내 권장
- `[대상]을 [동사]했어요.` 패턴으로 통일
- 과도한 감탄·느낌표 금지
- 성공 토스트는 완료 사실만 간결하게. 추가 안내가 필요하면 별도 다이얼로그 사용
- 실패 토스트는 에러 컴포넌트로 대체 검토

**구조**
```
성공  →  [대상]을 [동사]했어요.
재시도 필요  →  [동작]하지 못했어요. 다시 시도해 주세요.
```

**체크리스트**
- [ ] `~가 되었습니다` → `~을 ~했어요` 능동형 변환
- [ ] 15자 이내인가
- [ ] 느낌표 없는가
- [ ] `정상적으로`, `성공적으로` 삭제했는가
- [ ] 명사+명사 띄어쓰기 (`작업사진` → `작업 사진`, `결제링크` → `결제 링크`)

**금지 표현**

| 금지 | 이유 | 대체 |
|------|------|------|
| ~가 되었습니다 | -합니다 체 + 수동태 | ~을 ~했어요 |
| ~이 완료되었습니다 | 수동태 | ~을 완료했어요 |
| 정상적으로 처리되었습니다 | 번역투 부사 + 수동태 | 처리했어요 |
| 성공적으로 전송되었습니다 | 번역투 부사 + 수동태 | 전송했어요 |
| 완료되었습니다!!! | 과도한 감탄 | 완료했어요 |

**예시**

| 상황 | X | O |
|------|---|---|
| 다운로드 완료 | 작업사진이 다운로드 되었습니다. | 작업 사진을 다운로드했어요. |
| 공유 완료 | 작업사진이 카카오톡으로 공유되었습니다. | 작업 사진을 카카오톡으로 공유했어요. |
| 발송 완료 | 동의서가 발송 되었습니다. | 동의서를 발송했어요. |
| 재발송 완료 | 동의서가 재발송 되엇씁니다. (오타) | 동의서를 다시 발송했어요. |
| 결제 링크 전송 | 카카오톡으로 결제링크가 전송 되었습니다. | 카카오톡으로 결제 링크를 전송했어요. |
| 결제 취소 | 결제가 정상적으로 취소 되었습니다. | 결제를 취소했어요. |
| 작업 완료 취소 | 작업완료가 취소 되었습니다. | 작업 완료를 취소했어요. |

## 5. 빈상태 (Empty State)

### 작성 가이드

**원칙**
- **왜 비어있는지 + 무엇을 하면 되는지** 두 가지를 포함
- 단순히 없다는 사실만 서술하지 않음
- 해요체 사용. `없습니다` → `없어요`
- 다음 행동을 유도하는 문구를 덧붙임 (단, 다음 행동이 없는 구조면 상태만 서술해도 됨)

**구조**
```
기본형  →  아직 [내용]이 없어요.
유도형  →  아직 [내용]이 없어요. [행동]해 보세요.
상태형  →  [조건]된 [내용]이 없어요.
```

**체크리스트**
- [ ] `없습니다` → `없어요` 변환
- [ ] 단순 상태 서술에서 다음 행동 안내 추가 가능한지 검토
- [ ] `업로드 된` → `업로드된` 붙여쓰기

**금지 표현**

| 금지 | 이유 | 대체 |
|------|------|------|
| 데이터가 없습니다 | -합니다 체, 너무 기술적 | 아직 [항목명]이 없어요 |
| 결과가 없습니다 | 동일 | 검색 결과가 없어요. 다른 키워드로 검색해 보세요 |
| 업로드 된 | 띄어쓰기 오류 | 업로드된 |

**예시**

| 상황 | X | O |
|------|---|---|
| 결제 내역 없음 | 결제 내역이 없습니다. | 아직 결제 내역이 없어요. |
| 정산 내역 없음 | 정산 내역이 없습니다. | 아직 정산 내역이 없어요. |
| 사진 없음 | 업로드 된 작업 사진이 없습니다. | 업로드된 작업 사진이 없어요. |
| 동의서 없음 | 작성된 동의서가 없습니다. | 작성된 동의서가 없어요. |

## 6. 안내 (Guidance)

### 작성 가이드

**원칙**
- 사용자가 다음에 무엇을 해야 하는지 바로 알 수 있어야 함
- `-해 주세요` 띄어쓰기 필수 (보조 동사 `주다`는 앞말과 띄어 씀)
- 시스템 주어(`시스템이`, `서비스가`) 생략. 사용자 행동 중심으로 작성
- 불필요한 수식어 제거 (`~을 위한`, `~하신 경우`)
- 높임말 과용 금지 (`입력하신` → `입력한`)

**구조**
```
입력 요청  →  [내용]을 입력해 주세요.
동의 요청  →  [약관]에 동의해 주세요.
권한 요청  →  [기능]을 위해 [권한]이 필요해요. ([설정 경로])
필수 항목  →  * 표시는 필수 입력 항목이에요.
```

**체크리스트**
- [ ] `해주세요` → `해 주세요` 띄어쓰기
- [ ] `~의 경우`, `~하신 경우` → `~하면`, `~할 때` 변환
- [ ] `입력하신` → `입력한` 높임말 과용 제거
- [ ] `~합니다` → `~해요` 변환
- [ ] 불필요한 수식어 제거 후 더 짧아지는가

**금지 표현**

| 금지 | 이유 | 대체 |
|------|------|------|
| ~의 경우 | 번역투 | ~하면, ~할 때 |

| ~을 위한 필수 약관 | 불필요한 수식어 | 필수 약관 |
| 위치해주세요 | 어색한 표현 + 띄어쓰기 | 맞춰 주세요 / 놓아 주세요 |

## 7. 레이블 (Label / Status)

## 8. 알림 / 다이얼로그 (Alert / Dialog)

### 작성 가이드

**원칙**
- **제목**: 동작 또는 상황을 명사형으로 (예: 작업 삭제 / 결제 취소)
- **본문**: 해요체로 작성. 결과와 영향을 명확하게 설명
- **확인 버튼**: 파괴적 액션은 동작명으로 (`삭제`, `취소`), 단순 확인은 `확인`
- 파괴적 액션 확인 문구는 `~할까요?` 패턴 사용 (`하시겠습니까?` 금지)
- 한 다이얼로그에 한 가지 메시지만. 두 가지 이상이면 분리 검토

**구조**
```
제목  →  [동작명] (명사형)
본문  →  [영향 설명]이에요. [복구 불가 등 경고]해요. [동작]할까요?
버튼  →  [취소]  [동작명]  (Primary = 동작명, Secondary = 취소)
```

**체크리스트**
- [ ] 제목이 명사형인가
- [ ] 본문이 해요체인가 (`-습니다`, `-하시겠습니까` 금지)
- [ ] 파괴적 액션은 `~할까요?` 패턴
- [ ] Primary 버튼이 구체적인 동작명인가
- [ ] 본문 1문장 = 1메시지

**금지 표현**

| 금지 | 이유 | 대체 |
|------|------|------|
| ~하시겠습니까? | 딱딱하고 격식체 | ~할까요? |
| ~됩니다 | -합니다 체 | ~돼요 |
| 삭제 하시겠습니까 | 띄어쓰기 + 격식체 | 삭제할까요? |
| 취소하기 (버튼) | 메뉴에 동사형 | 취소 |

**예시**

| 요소 | X | O |
|------|---|---|
| 삭제 확인 본문 | 삭제된 데이터는 복구할 수 없습니다. 삭제 하시겠습니까? | 삭제된 데이터는 복구할 수 없어요. 삭제할까요? |
| 파괴적 영향 설명 | 작업 사진 폴더도 삭제됩니다. | 작업 사진 폴더도 함께 삭제돼요. |

## 9. 헤더 (Header)

### 작성 가이드

**원칙**
- 브랜드 첫인상에 직결되는 문구. 신중하게 작성
- 해요체 사용. 느낌표 금지
- 과도한 환영·감탄 표현 자제
- 띄어쓰기 오류 없도록 특히 주의 (`오신걸` → `오신 걸`)

**구조**
```
환영 문구  →  [서비스명]에 오신 걸 환영해요.
화면 제목  →  [명사형]  (예: 작업 목록 / 결제 현황)
```

**체크리스트**
- [ ] 느낌표 없는가
- [ ] 해요체 사용 (`환영합니다` → `환영해요`)
- [ ] 띄어쓰기 (`오신걸` → `오신 걸`)
- [ ] 과도한 감탄 표현 없는가

**예시**

| 상황 | X | O |
|------|---|---|
| 서비스 환영 | 위페어 파트너스에 오신걸 환영합니다! | 위페어 파트너스에 오신 걸 환영해요. |
| 화면 제목 | 작업목록 | 작업 목록 |
